# 森云科技 - SYZC 供应链金融存货监管系统 核心业务场景和流程

---

> **文档定位**：本文件为 SYZC 系统当前已确认核心业务场景的流程规范。通过 Mermaid 流程图、关键业务规则矩阵及异常分支，阐明货物入库、仓单开立、抵/质押单开立、货物出库、存货转让、仓内移位、差异调整、盘点、提货移交、设备管理、融资管理和风险信息管理等业务流程。

## 1. 核心场景 1：货物入库

*业务目标：运营方权限人员为货主完成货物入库制单，经可配置审批人审批通过后，货物正式进入库存台账。入库完成是后续开立仓单、办理抵/质押业务的硬前置条件。*

### 1.1 端到端主流程与异常分支 (Flowchart)

```mermaid

    Step1 --> Step2[提交入库单，系统自动记录制单时间]
```

### 1.2 关键业务规则矩阵

| 规则编号 | 规则名称 | 适用阶段 | 规则描述与触发条件 | 系统自动化响应 / 拦截动作 | 前置 / 后置影响 | 审计与防篡改要求 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **R-RKD-01** | **入库时间限制规则** | 制单录入 | 入库时间（业务时间）只允许选择当前或过去时间，不可选未来时间；制单时间由系统在提交时自动记录。 | 选择未来时间时系统阻断提交，提示时间不合规。 | 前置：无；<br/>后置：单据提交成功。 | 制单时间由系统自动生成，不可人工修改；操作人与时间戳全程记录。 |
| **R-RKD-02** | **审批通过即入库** | 审批节点 | 系统无独立"确认入库"操作，可配置审批人审批通过后，货物即视为入库成功，库存台账同步更新。 | 审批通过后系统自动变更库存记录，无需额外确认动作。 | 前置：入库单提交；<br/>后置：货物出现在库存台账中，可用于发起仓单开立。 | 审批动作记录操作人、审批时间与审批意见，不可篡改。 |
| **R-RKD-03** | **驳回后重新制单** | 驳回处理 | 入库单被驳回后，原单据状态流转为"已驳回"，发起人不可在原单上修改，须重新制一张新单。 | 系统支持将原单信息反写至新单，减少重复录入工作量。 | 前置：单据被驳回；<br/>后置：新单进入审批流程。 | 记录驳回原因、驳回人与时间；新旧单据关联可追溯。 |
| **R-RKD-04** | **摄像头自动抓拍存证** | 入库成功后 | 入库审批通过后，系统检测对应仓库/库房/分区是否配置摄像头，有则自动触发抓拍。 | 摄像头抓拍自动触发，无需人工操作，照片与入库单关联归档。 | 前置：入库审批通过；<br/>后置：现场照片与单据绑定存证。 | 抓拍照片附加时间戳与库位信息，归档后不可修改。 |

## 2. 核心场景 2：仓单开立

*业务目标：货物完成入库后，运营方权限人员可在独立入口为货主发起仓单开立申请。仓单为官方认证单据，不可拆分与合并，须经货主本人手机端人脸识别授权及可配置审批人审批通过后方可开立成功。仓单开立成功是后续办理抵/质押业务的硬前置条件。*

### 2.1 端到端主流程与异常分支 (Flowchart)

```mermaid
flowchart TD
    Start([进入仓单开立独立入口]) --> Step1[选择货主]
    Step1 --> Step2[选择该货主名下已入库的库存货物]
    Step2 --> Step3[填写仓单开立信息]
    Step3 --> Step4[提交仓单开立申请，系统自动记录制单时间]

    Step4 --> Step5[手机端：货主本人完成人脸识别]
    Step5 --> Check1{人脸识别结果?}

    Check1 -- 识别失败 --> Err1[单据中断，不进入审批流程]

    Check2 -- 驳回 --> Err2[单据失效，不可重新发起]
    Err2 --> EndErr2([流程终止])

    Check2 -- 通过 --> Step7[仓单开立成功，关联底层货物，更新货物状态]
    Step7 --> End([仓单开立完成])
```

### 2.2 关键业务规则矩阵

| 规则编号 | 规则名称 | 适用阶段 | 规则描述与触发条件 | 系统自动化响应 / 拦截动作 | 前置 / 后置影响 | 审计与防篡改要求 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **R-DWR-01** | **入库前置强制校验** | 仓单开立发起 | 仓单开立所选货物必须已完成入库（入库单审批通过），不允许对未入库或入库审批中的货物发起仓单开立。 | 选择货物时，系统仅展示库存台账中已入库的可用货物供选择。 | 前置：货物已入库；<br/>后置：提交仓单开立申请。 | 记录所选货物批次与对应入库单编号，确保溯源链完整。 |
| **R-DWR-02** | **货主人脸识别强制授权** | 提交后人脸环节 | 仓单开立申请提交后，必须由货主本人在手机端完成人脸识别，人脸通过后单据方可进入审批流程。 | 人脸识别失败则单据中断，不进入审批；由运营方协助发起，货主本人完成识别动作。 | 前置：申请已提交；<br/>后置：单据进入审批流。 | 记录人脸识别时间、识别结果与操作设备信息。 |
| **R-DWR-03** | **仓单不可拆分与合并** | 仓单全生命周期 | 仓单为官方认证单据，一经开立不可拆分为多张，亦不可与其他仓单合并。 | 系统不提供拆分与合并功能入口。 | 前置：无；<br/>后置：无。 | 仓单编号唯一，与底层货物对应，任何变更均生成审计快照。 |
| **R-DWR-04** | **驳回后不可重新发起** | 审批驳回 | 仓单开立申请被驳回后，该单据状态变为"已驳回失效"，不可在原单基础上重新发起。 | 系统屏蔽驳回单据的重新提交按钮；如需重新开立，须从独立入口全新发起新申请。 | 前置：审批驳回；<br/>后置：单据归档，货物恢复可用状态。 | 记录驳回原因、驳回人与时间；驳回单据永久归档可查。 |

## 3. 核心场景 3：抵/质押单开立

*业务目标：支持 C 端外部货主自行发起、B 端运营方直接代发起，以及 B 端从融资申请关联发起抵/质押单。直接发起时提交即冻结所选押品；融资关联发起时继承融资申请已锁定押品并保持只读。抵押单与质押单仅名称不同，共用审批流程；审批通过后形成正式抵/质押占用。*

### 3.1 直接发起主流程与异常分支

```mermaid
flowchart TD
    A([C端外部货主自行发起 / B端运营方代发起]) --> B[选择货主主体类型]
    B --> C[填写贷款及授信信息、抵/质押方式、安全线/控货线、权利人、合同编号]
    C --> D[选择抵/质押物类型：普通货物或仓单]
    D --> E1{押品类型?}
    E1 -- 普通货物 --> E2[选择已入库库存，可跨仓、可选部分数量]
    E1 -- 仓单 --> E3[选择已成功开立的仓单，可多选、每张整单]
    E2 --> F0[展示货品明细、单价、总价及参考价格]
    E3 --> F0
    F0 --> D1[提交抵/质押单]
    D1 --> D2[提交时冻结所选押品]
    D2 --> E{审批结果?}
    E -- 撤回（仅审批中） --> F[释放冻结押品，单据结束]
    E -- 驳回 --> G[释放冻结押品，单据结束]
    E -- 通过 --> H[抵/质押单开立成功]
    H --> I[普通存货状态变为抵/质押中；仓单状态变为冻结/抵质押中]
    I --> J[仓单关联货物状态保持为仓单中]
    J --> K([抵/质押单开立流程结束])
```

### 3.2 关键业务规则矩阵

| 规则编号 | 规则名称 | 适用阶段 | 规则描述与系统响应 | 前置 / 后置影响 | 审计要求 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **R-PL-01** | 双入口同规则 | 发起 | C 端外部货主自行发起，B 端运营方代货主发起；两端可选押品范围和业务规则相同。 | 按主体和入口控制数据权限。 | 记录发起入口、货主主体和代办人。 |
| **R-PL-02** | 押品类型互斥 | 押品选择 | 一张单只能选择普通货物或仓单，不能混合。 | 选择一种类型后锁定另一类型入口。 | 保存押品类型快照。 |
| **R-PL-03** | 普通货物选择 | 押品选择 | 普通货物必须已入库，可跨仓选择，并支持部分数量。 | 仅展示可用库存；数量不得超过可用量。 | 保存库存批次、数量、单价、总价。 |
| **R-PL-04** | 仓单选择 | 押品选择 | 仓单必须已成功开立，可多选、可跨仓，但每张仓单必须整单选择。 | 已冻结或已抵/质押仓单不可选。 | 保存仓单及关联货物快照。 |
| **R-PL-05** | 直接发起提交即冻结 | 提交 | C 端或 B 端直接发起时，提交审批即冻结所选押品；审批中不可重复使用。 | 驳回、撤回或开立失败时释放本次冻结。 | 记录冻结和释放的操作、时间及原因。 |
| **R-PL-06** | 审批状态控制 | 审批 | 审批角色和节点由系统自定义；仅审批中允许撤回，审批通过后不可撤回。 | 直接发起的单据驳回或撤回时释放押品；融资关联单据维持融资申请锁定并恢复待抵/质押办理。 | 保存审批意见、节点、人员和时间。 |
| **R-PL-07** | 融资关联发起 | 发起 | 资金方录入授信结果后，由 B 端运营人员从融资申请发起抵/质押单。 | 一笔融资申请只能关联一张有效抵/质押单。 | 保存融资申请、授信结果、发起人与抵/质押单关联。 |
| **R-PL-08** | 融资押品只读继承 | 发起 | 抵/质押物类型、明细、数量、货主、仓库、库位、批次和货品信息从融资申请锁定快照继承，禁止增加、删除、更换或修改数量。 | 仅允许填写抵/质押方式、安全线/控货线、权利人、合同编号等业务字段。 | 保存继承快照、锁定记录和数据版本。 |
| **R-PL-09** | 融资锁定转换 | 审批 | 融资关联发起不重复冻结押品；审批期间维持融资申请锁定，审批通过后转换为正式抵/质押占用。 | 创建失败、驳回或撤回时恢复待抵/质押办理并保留融资申请锁定，除非融资申请关闭。 | 记录锁定关系转换前后版本及失败原因。 |
| **R-PL-10** | 融资押品一致性校验 | 提交 | 提交时重新校验融资申请、授信结果、押品快照、锁定数量和数据版本。 | 任一项不一致时阻断创建，不允许通过编辑押品绕过。 | 记录冲突字段、当前值、快照值和处理结果。 |

### 3.3 单据字段与状态

抵/质押单至少包含：货主主体类型、贷款金额、贷款期数、授信金额、授信期数、抵/质押方式（固定/静态、浮动/流动）、本单货值安全线/控货线、抵/质押权人信息、合同编号（非必填）、抵/质押物类型、货品明细、单价、总价、参考价格、单据状态和发起人。开立阶段不录入货物评估价值。

| 状态 | 含义 | 可执行操作 | 后续状态 |
| :--- | :--- | :--- | :--- |
| 待开立 | 已选择货主主体、押品类型及押品，尚未提交 | 编辑、提交、放弃 | 开立中、已放弃 |
| 开立中 | 执行锁定和建单事务 | 查看、查询结果 | 已开立、开立失败 |
| 已开立 | 已生成业务单并完成押品状态变更 | 查看、发起独立的评估价值录入 | 本流程结束 |
| 开立失败 | 建单未完成或等待补偿 | 查看原因、查询补偿结果 | 待开立或关闭 |
| 已放弃 | 客户放弃办理 | 仅查看 | 终态 |

### 3.4 角色、权限与审计

| 角色 | 责任边界 | 核心权限 |
| :--- | :--- | :--- |
| 平台运营/抵质押业务人员 | 协助核对和处理异常 | 查看授权申请、代办、处理异常任务 |
| 风控/审计人员 | 监督风险和追溯 | 查看锁定、冲突、异常及审计快照，无权绕过校验 |

关键动作记录操作人、机构、时间戳、IP、设备、幂等键、前后状态、押品版本及补偿结果；人工解锁或补偿必须双人复核并留存原因。

### 3.5 独立流程：货物评估价值录入

抵/质押单成功开立后，B 端运营方可针对整张抵/质押单单独发起货物评估价值录入流程。该流程使用系统自定义审批流程，允许同一张抵/质押单重复发起，所有历史记录保留。

| 规则 | 处理方式 |
| :--- | :--- |
| 录入范围 | 以整张抵/质押单为单位录入，不按明细逐项录入。 |
| 生效规则 | 审批通过后成为最新生效的货物评估价值。 |
| 审批中 | 继续使用上一笔已生效评估价值计算抵押率。 |
| 无历史值 | 尚无已生效评估价值时，暂不计算抵押率。 |
| 抵押率 | `抵押率 =（贷款余额 ÷ 货物评估价值）× 100%`。 |
| 历史记录 | 保存每次录入值、发起人、审批记录、生效时间和历史版本。 |

### 3.6 融资申请关联发起流程

```mermaid
flowchart TD
    A([资金方已录入授信结果]) --> B[B端运营人员从融资申请发起抵/质押单]
    B --> C[系统只读继承融资申请锁定的押品明细和数量]
    C --> D[B端填写抵/质押方式、安全线/控货线、权利人、合同编号]
    D --> E{融资申请、授信结果、押品锁定和版本是否一致?}
    E -- 否 --> F[阻断提交并提示冲突，不允许修改押品绕过]
    F --> B
    E -- 是 --> G[提交抵/质押单并维持融资申请锁定]
    G --> H{审批结果?}
    H -- 通过 --> I[融资申请锁定转换为正式抵/质押占用]
    I --> J([抵/质押单已开立，融资转化完成])
    H -- 驳回或撤回 --> K[抵/质押单结束，恢复待抵/质押办理]
    K --> L[融资申请锁定继续有效，可重新发起新单]
    H -- 创建失败 --> M[记录失败并释放本次创建事务]
    M --> L
```

## 4. 核心场景 4：B 端货物出库流程

*业务目标：由 B 端运营方根据货物类型发起出库申请，经审批通过后扣减对应业务库存，并生成独立的提货单。普通货物、仓单货物和抵/质押单货物分别遵循不同的校验和状态处理规则。*

### 4.1 普通货物出库

```mermaid
flowchart TD
    A([B端运营方选择货主]) --> B[选择可用普通库存]
    B --> C[发起普通货物出库单]
    C --> D{审批结果?}
    D -- 审批中撤回 --> E[单据结束，库存保持可用]
    D -- 驳回 --> F[原单结束并记录原因，库存保持可用]
    F --> F1[发起人从独立入口新建出库单，可引用原单信息]
    F1 --> C
    D -- 通过 --> G[扣减普通库存]
    G --> H{提货单生成结果?}
    H -- 成功 --> H1[生成独立提货单]
    H -- 失败 --> H2[进入异常挂起，冻结出库结果并自动重试]
    H2 --> H3{补偿结果?}
    H3 -- 成功 --> H1
    H3 -- 失败 --> H4[人工复核并完成补偿或冲正]
    H4 --> H1
    H1 --> I([进入提货单板块])
```

### 4.2 仓单出库

```mermaid
flowchart TD
    A([B端运营方选择货主]) --> B[选择已开立仓单及仓单下部分货物]
```

## 8. 核心场景 8：盘点

*业务目标：由 B 端运营方发起内部盘点，记录仓库货物的账面数量、实际盘点数量及差异数量，用于日常管理和库存核查。盘点结果只作为记录，不直接改变业务数据。*

```mermaid
flowchart TD
```

## 9. 核心场景 9：提货单与货物移交

*业务目标：出库单审批通过后，系统自动生成提货单。有权限人员通过短信提货码或线上人工校验确认提货人身份，上传现场移交凭证后一次性完成整单货物移交。提货单不支持分批提货；取消提货时，通过重新入库流程恢复库存。*

### 9.1 端到端主流程与异常分支

```mermaid
flowchart TD
    A([出库单审批通过]) --> B[系统自动生成提货单]
    B --> C[提货单展示状态：待提货]
    C --> D{业务操作?}

    D -- 获取提货码 --> E[有权限人员手动点击获取]
    E --> F[系统向提货人手机号发送短信提货码]
    F --> G[提货码有效期为7天]
    G --> H{确认提货方式?}

    D -- 直接确认提货 --> H
    H -- 短信提货码 --> I{提货码是否有效且匹配?}
    I -- 否 --> J[提示校验失败，保持待提货]
    J --> K[允许重新输入或由有权限人员重置提货码]
    K --> F
    I -- 是 --> L[身份校验通过]
    H -- 线上人工校验 --> M[有权限人员核验提货人信息]
    M --> N[必填跳过提货码原因]
    N --> L

    L --> O[上传现场照片或电子签字，至少一项]
    O --> P{移交凭证是否满足要求?}
    P -- 否 --> Q[阻断确认提货并提示补充凭证]
    Q --> O
    P -- 是 --> R[整单确认提货并完成货物移交]
    R --> S([提货单状态：已提货])

    D -- 取消提货 --> T[有权限人员填写取消原因]
    T --> U[跳转入库页面并反写提货单货物信息]
    U --> V{是否提交重新入库单?}
    V -- 否 --> C
    V -- 是 --> W[关联重新入库单，展示状态仍为待提货]
    W --> X[操作状态变为重新入库处理中，确认提货按钮置灰]
    X --> Y{入库审批结果?}
    Y -- 通过 --> Z[恢复库存，提货单状态变为已取消]
    Z --> Z1([已取消，流程结束])
    Y -- 驳回或撤回 --> Z2[解除提货锁定并记录原因]
    Z2 --> C
```

### 9.2 提货单状态与操作控制

| 展示状态 | 内部操作状态 | 含义 | 可执行操作 | 后续状态 |
| :--- | :--- | :--- | :--- | :--- |
| 待提货 | 可提货 | 提货单已生成，尚未完成提货或提交重新入库单 | 获取/重置提货码、确认提货、取消提货 | 已提货、重新入库处理中 |
| 待提货 | 重新入库处理中 | 已提交关联入库单，入库流程尚未结束 | 查看提货单、查看关联入库单 | 已取消、可提货 |
| 已取消 | 已重新入库 | 关联入库单审批通过，库存已经恢复，提货单取消生效 | 仅查看 | 终态 |
| 已提货 | 已完成 | 已完成身份校验、凭证上传和整单移交 | 仅查看 | 终态 |

> 页面展示状态与内部操作状态必须分别保存。确认提货按钮由内部操作状态控制，不得仅根据页面展示的“待提货”判断是否可操作。

| R-PICK-04 | 提货码有效期与重置 | 提货码有效期为7天；过期后不能使用，只能重置。重置后原提货码立即失效，新码重新计算7天。 | 同一提货单同一时刻仅允许一个有效提货码。 | 记录提货码版本、有效期、重置人和重置时间，不保存明文提货码。 |
| R-PICK-05 | 双确认方式 | 确认提货支持短信提货码和线上人工校验两种方式。人工校验必须由有权限人员执行并填写跳过提货码原因。 | 任一方式校验通过后进入移交凭证上传。 | 记录确认方式、操作人、校验结果及人工校验原因。 |
| R-PICK-06 | 校验失败处理 | 提货码错误、过期或失效时不锁定提货单，也不自动通知运营人员。 | 保持待提货，可重新输入或由有权限人员重置提货码。 | 记录失败时间、失败原因和来源终端。 |
| R-PICK-07 | 整单提货 | 一张提货单不允许分批提货，必须一次性确认全部货物移交。 | 确认成功后整单变为已提货，禁止再次确认或取消。 | 保存提货货物、数量及确认前后状态快照。 |
| R-PICK-08 | 移交凭证必填 | 确认提货前由用户自行上传现场照片或电子签字，两者至少上传一项。 | 未上传有效凭证时阻断确认提货。 | 保存附件类型、上传人、上传时间、文件摘要和关联提货单。 |
| R-PICK-09 | 取消提货 | 仅待提货且内部操作状态为可提货时允许取消，取消原因必填。 | 跳转入库页面，并反写提货单货物信息。 | 记录取消操作人、取消原因、时间和原货物快照。 |
| R-PICK-10 | 重新入库锁定 | 用户提交重新入库单后，提货单展示状态仍为待提货，内部操作状态变为重新入库处理中。 | 立即将确认提货按钮置灰，禁止提货与重新入库并发执行。 | 保存关联入库单号、锁定时间、操作人和数据版本。 |
| R-PICK-11 | 重新入库结果 | 重新入库必须执行完整入库审批。审批通过后恢复库存，提货单状态变为已取消；驳回或撤回时解除锁定，恢复待提货和可提货状态。 | 通过后进入已取消终态；驳回或撤回后恢复可提货。 | 记录审批结果、库存恢复流水、解锁原因和前后版本。 |

## 11. 核心场景 11：融资管理

*业务目标：C 端用户选择融资产品和拟抵/质押物提交融资申请，系统立即锁定押品；B 端完成受理、可选尽调和独家资金方分配，资金方接单、提交融资方案并录入授信结果后，由 B 端运营人员发起唯一抵/质押单。系统不替代资金方内部授信决策，仅记录业务过程与结果。*

### 11.1 端到端主流程与异常分支

```mermaid
flowchart TD

    D -- 仓单 --> F[选择一张或多张已开立仓单，每张整单]
    E --> G[提交融资申请]
    F --> G
    G --> H[立即锁定所选押品]
    H --> I[状态：待B端受理]

    I --> J{待受理阶段操作?}
    J -- C端撤回 --> K[申请已撤回并立即释放全部押品]
    J -- B端驳回 --> L[申请已驳回并立即释放全部押品]
    J -- B端受理或首次分配 --> M[进入正式处理流程，C端不可撤回]

    M --> N{融资产品是否要求尽调?}

    W -- 接单 --> W1[资金方处理中]

    AF -- 失败 --> AG[记录失败原因，释放本次创建事务]
    AG --> AB
    AF -- 成功 --> AH[生成唯一抵/质押单]
```

### 11.2 融资申请、方案与授信字段

| :--- | :--- | :--- | :--- |
| 融资申请 | 融资产品、融资金额、融资期限、联系人、手机号、抵/质押物类型及明细 | C 端用户 | 必填、格式、产品有效、押品可用、普通库存与仓单不可混选 |

| 角色 | 责任边界 | 核心权限 |

## 12. 核心场景 12：风险信息管理

*业务目标：通过独立的“风险管理配置”板块定义订单预警、设备预警和设备事务通知规则，再由独立的“风险信息”板块承接规则命中后的信息展示、人工处理、通知升级、贷中风控结果和风险公示。配置数据与风险信息记录相互关联但职责隔离，规则变更不得覆盖历史风险事实。*

### 12.1 板块隔离与总体流程

### 12.2 风险管理配置板块

#### 12.2.1 订单预警配置

```mermaid
flowchart TD
    A([有权限人员新建订单预警配置]) --> B[选择抵/质押订单或监管订单]
    B --> C[输入规则名称]
    C --> D[勾选一个或多个预警类型]
    D --> E[按类型填写阈值、周期、解除方式或风控模型]
    E --> F{是否为设备相关类型?}
    F -- 是 --> G[从订单关联仓库/库区/库位中选择一台或多台对应设备]
    F -- 否 --> H[无需选择设备]
    G --> I[配置首次通知对象和邮件/短信/站内方式]
    H --> I
    I --> J[可选配置未处理天数和一级升级通知对象]
    J --> K{订单ID与预警类型是否已存在有效配置?}
```

| 订单预警类型 | 配置内容 | 触发条件/输出 |
| :--- | :--- | :--- |
| 解抵/质押/监管超时 | 超时日期 | 到达日期仍未完成对应业务时生成押品预警 |
| 价格下跌 | 押品总价值下跌百分比 | 实际跌幅达到配置百分比时生成押品预警 |
| 图像识别异常 | 行人入侵、车辆入侵、物品形态变化；选择多台监控设备 | 第三方算法事件命中时生成押品预警 |
| 盘点异常 | 是否启用 | 盘点数量与系统记录数量不一致时生成押品预警 |
| 巡检异常 | 巡检人员、巡检周期 | 未按配置周期完成巡检时生成押品预警 |
| 物联异常 | 温度、湿度、氧气、二氧化碳上下限区间，烟感异常条件；选择多台物联设备 | SYZC 使用第三方原始采集值匹配本规则阈值，命中后生成押品预警 |
| 智能挂锁异常 | 拆壳、锁舌被卡、锁杆被剪、非法开箱、拆卡报警、密码错误、关锁异常、电量低于20%；选择多台挂锁设备 | 命中所选行为时生成押品预警 |
| 抵/质押率异常 | 一组补仓线或平仓线阈值；解除方式选择补仓、平仓或部分结清 | 抵/质押率命中配置阈值时生成押品预警，并提供对应处置入口 |
| 人脸门禁异常 | 门未关、密码错误；选择多台人脸门禁设备 | 命中所选行为时生成押品预警 |
| GPS异常 | 进围栏、出围栏、普通限速、怠速滞留、路线偏离、非法拆除；选择多台GPS设备 | 第三方推送所选事件时生成押品预警 |
| 贷中风控模型 | 选择第三方智风控模型 | 执行结果仅回写贷中订单行的风险标识，不生成新的押品预警记录 |

一条订单配置可勾选多个预警类型，但保存时必须拆分为独立规则明细，并以“订单ID + 预警类型”保证有效配置唯一。同一台物联设备在不同订单规则中允许配置不同阈值。

#### 12.2.2 设备预警配置

设备预警配置不关联抵/质押订单，由用户选择一台或多台具体设备及一个或多个预警类型。支持设备离线、锚点闯入、物联超阈值、智能挂锁异常、人脸门禁异常和GPS异常。物联阈值在每条 SYZC 风险规则内配置；设备离线时长仍采用第三方全局配置，SYZC 只接收离线事件。

未绑定仓库、库区或库位的设备也允许配置，列表可见性由账号设备和数据权限决定。设备被第三方移出后，引用该设备的有效配置自动失效并停止生成新预警。

#### 12.2.3 设备事务通知配置

```mermaid
flowchart TD
    A([有权限人员新建设备事务通知配置]) --> B[输入规则名称]
    B --> C[选择一台或多台设备]
    C --> D[勾选一个或多个通知类型]
    D --> E[开锁通知/关锁通知/设备上线通知/设备移出通知]
    E --> F[配置首次通知对象和邮件/短信/站内方式]
    F --> G[可选配置未处理天数和一级升级通知对象]
    G --> H[保存并启用]

```

开锁、关锁通知适用于门禁设备；上线、移出通知适用于所有设备类型。设备移出事件生成的通知记录继续保留并正常处于未处理或已处理状态，同时引用该设备的事务通知配置自动失效。

#### 12.2.4 通知与升级规则

| 配置项 | 规则 |
| :--- | :--- |
| 首次通知对象 | 由规则配置选择，可配置一个或多个对象 |
| 通知方式 | 邮件、短信、站内消息，可多选 |
| 升级条件 | 预警或事务通知生成后达到配置天数仍未处理 |
| 升级对象 | 由规则另选一组通知对象 |
| 升级次数 | 仅支持一级升级 |
| 列表表现 | 升级只发送通知，不生成新记录、不改变状态、不展示“已升级”标签 |
| 停止条件 | 记录已处理或配置/预警已失效后停止后续通知 |

### 12.3 风险信息展示与人工处理板块

#### 12.3.1 押品预警与设备预警生成

```mermaid
flowchart TD
    A([业务数据或第三方事件到达]) --> B[匹配已启用且有效的规则明细]
    B --> C{是否命中规则?}
    C -- 否 --> D[只保存原始数据或事件，不生成预警]
    C -- 是 --> E{同一规则是否存在当前未处理预警?}
    E -- 是 --> F[更新最新命中值、命中时间和累计次数]
    E -- 否 --> G[生成新的未处理预警]
    F --> H[按规则执行首次或升级通知]
    G --> H
    H --> I[在押品预警或设备预警列表展示]
```

同一规则持续命中时只更新当前未处理预警；已处理后再次命中才生成新记录。预警条件恢复正常后不自动解除，仍须人工处理。规则修改、停用或关联设备移出时，当前未处理预警变为失效，历史记录继续保留。

#### 12.3.2 状态与处理要求

| 信息类型 | 状态/筛选项 | 人工处理要求 | 失效规则 |
| :--- | :--- | :--- | :--- |
| 押品预警信息 | 未处理、已处理、失效 | 处理说明和附件必填 | 规则修改/停用、关联对象失效时，当前未处理预警变为失效 |
| 设备预警信息 | 未处理、已处理、失效 | 处理说明和附件必填 | 规则修改/停用、设备移出时，当前未处理预警变为失效 |
| 设备事务通知 | 全部、未处理、已处理 | 处理说明和附件必填 | 通知记录不失效；设备移出时仅将关联配置标记失效 |

抵/质押率异常选择补仓、平仓或部分结清后，系统跳转对应业务流程；业务流程完成后，仍由有权限人员填写处理说明、上传附件并人工标记已处理。

风险信息不设置预警等级。列表直接展示预警类型、配置阈值、实际命中值、命中时间、累计次数、处理状态及配置的处置方式。

### 12.4 贷中风控管理

```mermaid
flowchart TD
    A([第三方智风控平台同步模型]) --> B[订单规则选择一个风控模型]
    B --> C[有权限人员在贷中风控列表单选或批量勾选订单]
    C --> D[逐笔调用各订单规则关联的模型]
    D --> E{第三方执行结果?}
    E -- 调用失败 --> F[展示失败原因并允许重新执行]
    F --> D
    E -- 成功 --> G[接收指标数值、结果资料和是否触发预警标识]
    G --> H[保存本次执行历史]
    H --> I{是否触发预警?}
    I -- 是 --> J[订单行展示最新风险标识和结果]
    J --> K[按规则发送邮件/短信/站内通知]
    I -- 否 --> L[清除订单行当前风险标识]
    L --> M[历史执行结果继续保留]
```

贷中风控页面展示全部纳入贷中管理的抵/质押或监管订单，并按订单数据权限控制。一条规则只关联一个模型；同一订单需要执行多个模型时创建多条规则。第三方负责判断是否触发预警并上传结果资料，SYZC 只接收、保存和展示。贷中风险只更新订单行标识，不在押品预警列表重新生成记录。

### 12.5 风险公示

```mermaid
flowchart TD
    A([有权限人员进入已处理预警]) --> B{是否与抵/质押单关联?}
    B -- 否 --> C[不允许公示]
    B -- 是 --> D{预警来源?}
    D -- 订单预警 --> E[生成独立公示快照]
    D -- 抵/质押单关联设备预警 --> E
    E --> F[运营方可编辑对外展示内容]
    F --> G{单条或批量公示?}
    G -- 单条 --> H[发布一条公示快照]
    G -- 批量 --> I[每条预警分别生成并发布独立快照]
    H --> J[风险公示Tab展示]
    I --> J
    J --> K{后续操作?}
    K -- 撤回 --> L[立即停止对外展示并保留公示历史]
    L --> M[允许编辑后重新公示]
    M --> J
```

风险公示使用独立 Tab。公示时不选择目标机构、不发送通知；所有拥有风险公示 Tab 权限的账号均可查看当前已公示内容。公示快照可由运营方编辑，但不得反向修改原始预警、原始处理说明或附件。单条和批量公示均以每条预警为单位保存独立快照、版本和操作记录。

### 12.6 关键业务规则矩阵

| 规则编号 | 规则名称 | 规则描述与系统响应 | 审计要求 |
| :--- | :--- | :--- | :--- |
| R-RISK-01 | 配置与信息隔离 | 风险配置和风险信息使用独立菜单、权限和数据对象；信息页面不得修改规则。 | 记录配置版本、命中版本和风险记录关联。 |
| R-RISK-02 | 规则明细唯一 | 订单配置允许勾选多个类型，但同一订单同一预警类型只能有一条有效规则明细。 | 记录唯一约束冲突和处理结果。 |
| R-RISK-03 | 设备范围校验 | 订单设备类规则只能选择订单关联仓库、库区或库位下的设备，且支持多选。 | 保存配置时设备及位置快照。 |
| R-RISK-04 | 物联本地阈值 | 第三方推送原始采集数据，SYZC 按具体订单或设备规则的区间阈值判断。 | 保存原始值、阈值版本、判断时间和结果。 |
| R-RISK-05 | 未处理预警去重 | 同一规则持续命中只更新当前未处理记录；处理后再次命中才新建。 | 保存首次/最新命中时间和累计次数。 |
| R-RISK-06 | 人工处理 | 预警条件恢复不自动解除；处理说明和附件必填后才可标记已处理。 | 保存处理人、说明、附件摘要和前后状态。 |
| R-RISK-07 | 规则失效影响 | 规则修改、停用或设备移出不删除历史；关联未处理预警变为失效。 | 保存失效原因、时间和配置版本。 |
| R-RISK-08 | 事务通知状态 | 设备事务通知只使用未处理、已处理，列表另有全部筛选；设备移出仅使配置失效。 | 保存通知事件、处理记录和配置失效关系。 |
| R-RISK-09 | 一级通知升级 | 达到配置未处理天数后仅向升级对象发送一次通知，不改变风险状态。 | 保存各渠道发送结果、对象和时间。 |
| R-RISK-10 | 贷中结果不重复建警 | 第三方结果更新订单行风险标识并保留执行历史，不新增押品预警记录。 | 保存模型、订单、执行批次、原始结果和最新标识。 |
| R-RISK-11 | 公示快照独立 | 仅已处理且关联抵/质押单的订单预警或设备预警可公示；对外编辑不覆盖原始数据。 | 保存原始快照、公示版本、编辑、发布、撤回和重发记录。 |
| R-RISK-12 | 不设预警等级 | 风险信息按类型、阈值、实际命中值和处置方式展示，不增加等级字段。 | 保存触发参数和处理依据。 |

### 12.7 角色、权限与数据范围

| 角色/权限主体 | 配置权限 | 信息权限 |
| :--- | :--- | :--- |
| 风险配置人员 | 创建、编辑、启停订单预警、设备预警和事务通知配置 | 按授权查看配置命中结果 |
| 风险处理人员 | 无权在信息页修改规则 | 查看并处理授权范围内预警和事务通知，说明及附件必填 |
| 贷中风控人员 | 选择模型规则，单选/批量执行 | 查看订单行风险标识、指标、报告和执行历史 |

订单预警和贷中风控按订单数据权限控制；设备预警和设备事务通知按设备及仓库数据权限控制，未绑定位置设备按账号设备权限控制；风险公示仅按独立 Tab 权限控制，不在公示时选择目标机构。

### 13.2 风险通知发送失败重试策略
