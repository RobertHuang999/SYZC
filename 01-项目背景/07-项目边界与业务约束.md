# 项目边界与业务约束

## 1. 建设范围

纳入范围以 `04` 的八大功能板块和 `06` 的十二类核心场景为准：仓储收发存与设备监管、数字仓单和货权档案、融资与质押/解押、交易协同、风险预警和处置、审批指令、统计驾驶舱、结算配置及其权限审计能力。

## 2. 不纳入系统核心闭环的事项

| 事项 | 边界 |
| :--- | :--- |
| 银行核心放款、扣款和清算 | SYZC 记录申请、审批和结果接口，不替代资金方核心系统 |
| 法定登记和司法裁判 | 可对接或留存回执，不替代登记机构和法院结论 |
| 仓储现场最终责任 | 系统提供校验、设备联动和证据链，现场责任仍由合同主体承担 |
| 商品价格的法定认定 | 系统使用约定行情源计算风控指标，价格源和折扣由项目配置 |
| 未授权的第三方接口 | 未完成授权、联调和安全评估前不得作为自动放行依据 |

## 3. 强制业务约束

1. 已质押或被风险处置锁定的库存不得直接出库、转让、重复质押或删除。
2. 出库必须按 `06` 的货物类型规则完成对应审批、库存/仓单/质押占用校验，并生成提货单；需要解押或替代担保的情形，必须先取得有效放行指令。抵/质押单项下出库可在控货线/安全线触发提示后继续提交审批，是否通过由审批流程决定。
3. 入库、仓单、质押、解押、补仓、平仓和出库必须幂等，使用 `request_id` 和版本号防并发。
4. 命中配置的阻断条件时，系统必须阻断对应高风险操作；解除阻断必须有授权、证据和审计记录。
5. 已完成业务不得物理删除；数据更正采用冲正、撤销或新版本。
6. 机构、项目、仓库和角色数据权限必须同时生效，审计和导出动作也必须留痕。

## 4. 风险响应

| 触发类型 | 典型事件 | 配置动作 |
| :--- | :--- | :--- |
| 通知类 | 普通任务超时、设备上线/移出、开锁/关锁 | 按配置通知责任人，并可在超时未处理时执行一级通知升级 |
| 处置类 | 设备离线、物联超阈值、盘点差异、图像识别异常 | 生成预警，要求人工填写处理说明并上传附件 |
| 业务联动类 | 抵/质押率命中补仓线或平仓线、权属冲突、重复质押 | 跳转补仓、平仓或部分结清，或按配置阻断相关操作 |

预警类型、阈值、通知对象、通知方式、升级时长和处置权限必须按风险配置保存并保留历史版本。
