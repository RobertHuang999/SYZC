# 监管系统的业务背景

## 1. 业务痛点

| 痛点 | SYZC 的应对方向 |
| :--- | :--- |
| 货物、仓单和合同分散，货权难核验 | 入库证据、数字仓单、货权档案和存证关联 |
| 质押后库存仍可能被错误释放 | 质押占用、出库审批、提货核销和风险规则联动控制 |
| 价格波动导致押品保障不足 | 盯市估值、敞口覆盖率、补仓和处置流程 |
| 现场作业缺乏可验证证据 | 地磅、摄像头、门禁、GPS、盘点和操作日志联动 |
| 多机构协作时权限和责任不清 | RBAC、机构/仓库/项目数据权限和全路径审计 |

## 2. 监管子系统职责

监管能力不是独立于业务的旁路，而是贯穿 `06` 十二类核心场景的控制链：

1. 核验准入、合同、货品和库存事实，形成数字仓单及货权证据链。
2. 对质押、解押、补仓、出库和转让执行权限、状态和一致性校验。
3. 按已启用风险规则对设备、库存、行情、押品和订单异常生成预警，并记录类型、阈值、实际命中值和处置方式。
4. 通过统计报表、驾驶舱、证据链和审计日志支持贷中监管与复核。
5. 在接口授权和合规前提下，对接登记公示、行情、物联网和外部风控系统。

## 3. 与核心流程的对应关系

| 监管目标 | 对应流程 |
| :--- | :--- |
| 货物真实入库并完成确权 | 场景一：货物入库；场景二：仓单开立 |
| 质押资产安全转化为融资依据 | 场景三：抵/质押单开立 |
| 释放货物前保持资金与货权一致 | 场景四：B 端货物出库（按货物类型执行校验和审批） |
| 仓内货物异常可调整且可追溯 | 场景七：异动（差异调整单） |
| 货权转移时保留历史和审批链 | 场景五：货权转让 |
| 仓内位置变化受控 | 场景六：移库（仓内移位） |
| 盘点差异形成闭环处置 | 场景八：盘点 |
| 出库后的身份核验与货物移交可追溯 | 场景九：提货单与货物移交 |
| 设备状态、采集数据和设备事件可追溯 | 场景十：设备管理 |
| 融资申请、押品锁定与抵/质押转化一致 | 场景十一：融资管理 |
| 风险规则、预警处理和对外公示相互隔离且可追溯 | 场景十二：风险信息管理 |

## 4. 合规原则

系统遵循真实、可追溯、最小权限、职责分离和全程留痕原则。外部登记、公示、电子签章、行情和资金系统的法律效力及最终业务结果，以适用法律、合同和外部系统确认为准；未完成授权和联调时采用人工复核和可追溯补录机制。
