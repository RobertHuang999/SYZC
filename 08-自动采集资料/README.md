# 📂 自动采集资料 (历史老系统参考资料库)

> ⚠️ **核心定位与使用规范（重要）**：  
> **本目录内所有资料均为基于老系统（四川享宇科技有限公司）页面自动化采集与提炼的历史现状资料，仅供业务对照与设计参考，严禁直接作为新系统迭代开发与 PRD 的唯一真源！**  
> 新功能与新架构的设计与研发必须严格以 [02-PRD文档/](../02-PRD文档/)、[03-前端原型demo/](../03-前端原型demo/) 以及 [AGENTS.md](../AGENTS.md) 中的最新业务规则为准。

## 一、目录结构与层级关系

本目录收录了 2026-08-03 对老系统进行完整只读采集与提炼沉淀的三个阶段成果：

```
08-自动采集资料/
├── README.md              # 📖 本说明文件（定位与参考边界）
├── 01-系统采集/           # 🔎 阶段一：老系统 75 个独立路由的菜单树、DOM 字段与操作原始采集底稿
├── 02-知识宝典/           # 📚 阶段二：基于 01 采集成果提炼出的按业务模块归纳的页面知识说明
└── 03-基准资料/           # 📋 阶段三：基于 01 与 02 萃取的页面级「当前字段清单」与「当前业务规则与状态」现状快照
```

---

## 二、各子阶段说明

### 1. `01-系统采集`
* **采集来源**：老系统已登录测试环境（`senyun-wrl-test4.sylinker.com`，账号：黄k）。
* **采集方式**：AI 结合浏览器自动化（Browser Automation）按只读边界抓取。
* **包含内容**：
  * `01-系统菜单与页面地图`（.md / .json）：包含 75 个独立路由与菜单层级；
  * `02-页面采集/`：逐页面的表头、查询区、按钮与 Tab 原始采集底稿；
  * `03-模块整理/`：功能矩阵、字段字典与状态汇总。

### 2. `02-知识宝典`
* **提炼来源**：衍生自 `01-系统采集`。
* **主要作用**：按业务模块（01-首页、02-仓储、03-融资、04-交易、05-风控、06-统计、07-结算、08-配置管理）对分散的采集结果进行结构化提炼，形成具有可读性的页面知识文档。

### 3. `03-基准资料`
* **提炼来源**：衍生自 `01-系统采集` 与 `02-知识宝典`。
* **主要作用**：按照技能规范固化为每个页面的「当前字段清单.md」与「当前业务规则与状态.md」，作为老系统现状基准（As-Is Baseline）。

---

## 三、参考与使用守则

1. **仅作参考（Reference Only）**：
   * 在进行需求分析或原型重构时，当需要了解老系统“过去有什么字段、有哪些操作按钮、状态如何展示”时，查阅本目录作为事实线索。
2. **禁止反向覆盖**：
   * 老系统存在部分未命名控件、粗粒度配置或历史遗留字段，新系统重构时不可将老系统的历史缺陷或旧字段盲目反向写入新 PRD。
3. **闭环对齐**：
   * 所有新增/变更需求，必须在 [02-PRD文档/](../02-PRD文档/) 中通过主 PRD、字段清单、业务规则规格完成规范定义，并同步在 [03-前端原型demo/](../03-前端原型demo/) 中实现与标注。
