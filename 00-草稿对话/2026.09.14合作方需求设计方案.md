## 1. 文档目的

本方案用于把“合作方统一管理”和“货主增加证件地址”两个需求放到同一套业务模型中，回答以下问题：

1. 系统中的业务主体、机构、客户账号和系统权限角色分别是什么，不能互相替代；
2. 货主、提货人、接收方、资金方、仓单存货人、仓单持有人等业务角色在哪个作业环节产生，来源于哪类单据；
3. 哪些基础字典、组织、账号和配置必须先维护，业务菜单才能正确引用；
4. 现有菜单需要新增、删除、修改或仅做边界澄清的内容是什么；
5. 证件地址由哪个菜单维护，什么时候必填，什么时候做个人货主地址唯一校验；
6. 业务单据如何引用合作方，历史数据、快照、状态、权限和审计如何处理。

本方案的核心结论是：

> **先建立基础配置和统一合作方主数据，再让业务作业菜单引用合作方；证件地址属于合作方主档，必填与唯一校验都通过配置控制；机构管理方和系统权限角色不承担合作方业务主体管理。**

> **范围说明**：本方案只定义业务对象、业务信息、页面功能和业务规则边界，不定义数据库字段编码、接口字段、表结构、索引或其他技术实现细节。后续技术字段名称应在正式字段清单和技术设计阶段确定。

## 2. 合并后的最终口径

### 2.1 四类对象必须分开

| 对象 | 主要职责 |
|---|---|
| 机构（Institution） | 负责组织层级、账号归属、机构间协作以及仓库、项目和数据权限。 |
| 合作方（Partner） | 负责业务主体、个人/企业身份资料、证件、证件地址、业务角色和业务来源。 |
| 客户账号（Customer Account） | 负责客户端（C端）注册、登录、认证和账号状态，可绑定一个业务主体。 |
| 系统权限角色（RBAC） | 负责后台端（B端）用户可访问的菜单、按钮、数据权限和审批权限。 |

“货主”“提货人”“接收方”“仓单存货人”“仓单持有人”“资金方/质权人”等是**业务角色或业务关系**，不能直接放进“配置管理 → 平台管理 → 角色管理”作为系统登录角色。

“仓库管理方”是仓库基础档案中的识别信息，不因为仓库档案填写了管理方，就自动创建或选择合作方。

### 2.2 机构与合作方当前不做强绑定

本次“货主增加证件地址”和合作方统一管理的前置条件，不是把每个合作方都关联到机构。

- 个人货主、个人提货经办人、个人接收方通常没有所属机构；
- 机构管理继续负责组织层级、B端账号归属和数据权限；
- 合作方管理负责业务主体及业务角色；
- 资金方、仓储机构或监管机构如确实需要同时拥有机构账号和合作方主体，可在后续单独设计“机构与合作方关系”能力；
- 本期不在机构管理中强行增加“关联合作方主体”字段，也不以机构名称文本替代合作方主数据。

### 2.3 仓库管理方保持独立

`配置管理 → 仓库管理 → 仓库管理`中的“管理方”只用于描述仓库基础档案中的识别信息，仍按现有仓库档案逻辑维护：

- 保留管理方类型、名称/姓名、证件号、联系电话、仓库权属关系等字段；
- 可以是人工填写的企业或个人识别信息；
- 不从合作方档案选择；
- 不自动创建“仓库管理方”合作方角色；
- 不接入个人货主证件地址唯一校验；
- 仓库历史资料如需留存管理方信息，保存仓库档案或历史资料快照，不是合作方快照。

### 2.4 地址相关的最终建议

合作方主档统一使用以下字段：

| 业务信息 | 个人主体来源 | 企业主体来源 | 是否本期参与个人地址唯一校验 |
|---|---|---|---|---|
| 证件地址 | 身份证对应地址 | 营业执照或企业认证资料对应地址 | 仅个人货主参与 |
| 证件地址来源 | 身份证 | 营业执照/企业认证资料 | 用于追溯来源，不作为第二个地址字段 |

“证件地址是否必填”和“个人货主证件地址是否唯一校验”是两个独立控制项：

- 地址必填控制解决“当前场景是否必须有地址”；
- 地址唯一控制解决“同一范围内相同个人货主证件地址能否绑定多个身份证号”；
- 两者都应在配置管理中维护，不应写死在某一个入库页面；
- 统一地址信息只在合作方主档维护；业务单据选择已有合作方后不在主表单平铺地址，通过“查看货主”弹窗查看，提交时调用统一准入规则完成校验。

## 3. 建设目标与范围

### 3.1 建设目标

1. 建立以企业统一社会信用代码或个人身份证号为核心的统一合作方主体主数据；
2. 同一主体支持多个业务角色，角色关系保留来源单据、状态和生效时间；
3. 业务单据在作业环节自动复用或沉淀合作方，减少重复录入；
4. 统一维护个人/企业证件地址，支持必填、来源和个人货主地址唯一性配置；
5. 合作方冻结按业务角色隔离，避免一个角色的风险影响其他无关业务；
6. 历史业务以主体标识加业务发生时快照追溯，不因主档后续修改而篡改历史事实；
7. 让客户、仓储、融资/监管、仓单、结算和风险模块使用同一套主体识别口径。

### 3.2 本期范围

- 新增合作方档案菜单；
- 新增合作方准入规则配置入口；
- 建立个人/企业主体字段、证件地址和合作方角色关系；
- 修改客户管理，使客户端（C端）账号可绑定合作方主体；
- 修改入库、出库、提货、转让、仓单、抵质押等作业菜单的主体引用；
- 建立主体状态、角色状态、地址校验、主体复用、角色追加和快照规则；
- 补充权限、数据隔离、敏感信息脱敏和审计要求；
- 规划历史货主数据迁移和手机号识别向身份证/统一社会信用代码识别的过渡。

### 3.3 本期不建设或不改变

- 不把合作方业务角色并入系统权限角色；
- 不在机构管理中强制增加机构与合作方的关联字段；
- 不把仓库管理方改为合作方选择器；
- 不新增独立“证件地址管理”菜单；
- 不新增独立“提货人管理”“接收方管理”“地址冲突审批”菜单；
- 不通过审批中心处理地址重复冲突；
- 不删除现有客户管理、入库、出库、转让、仓单、加工等业务菜单；
- 移动端（H5）暂不新增独立合作方维护菜单，业务页面调用统一合作方能力即可。

## 4. 核心业务模型

### 4.1 合作方主体

合作方主体是系统中可被多个业务单据引用的业务主体，主体类型分为个人和企业。

```text
合作方主体（Partner）
├─ 主体基本资料
│  ├─ 主体类型：个人 / 企业
│  ├─ 内部主体标识：系统生成且不可变
│  ├─ 个人：姓名、身份证号、手机号、证件地址
│  └─ 企业：企业名称、统一社会信用代码、联系人、联系电话、证件地址
├─ 业务角色关系
│  ├─ 货主
│  ├─ 提货主体 / 提货经办人
│  ├─ 接收方
│  ├─ 资金方 / 抵质押权利人
│  ├─ 仓单存货人
│  └─ 仓单持有人
├─ 客户账号与合作方关系
├─ 业务来源与来源单据
├─ 主体状态与角色状态
├─ 资料、证件地址变更记录
└─ 审计日志与历史快照引用
```

### 4.2 主体唯一识别

| 主体类型 | 核心识别字段 | 识别规则 | 说明 |
|---|---|---|---|
| 个人 | 身份证号 | 身份证号在适用租户/项目范围内唯一 | 姓名和手机号不能作为主体唯一识别依据 |
| 企业 | 统一社会信用代码 | 统一社会信用代码在适用租户/项目范围内唯一 | 企业名称不能作为唯一识别依据 |
| 系统主体 | 内部主体标识 | 系统生成、全生命周期不变 | 业务单据保存统一合作方主体关系 |

主体唯一范围需要最终确认是全平台租户、租户内项目，还是“租户 + 项目”组合。设计上建议：

- 主体主档可以按租户隔离；
- 项目可以限制主体可见范围和可使用范围；
- 地址唯一规则按“同一租户/项目业务范围”执行；
- 不同租户之间不做主体和地址比较。

### 4.3 角色关系不使用简单标签数组

同一个主体可能从多个作业环节产生不同角色，因此不能只保存一个角色标签列表而丢失来源。建议在业务上保留“角色关系”信息，至少能够表达：

| 字段 | 含义 |
|---|---|
| 关联主体 | 对应的合作方主体 |
| 业务角色 | 货主、提货人、接收方等角色名称 |
| 角色状态 | 待生效、正常、冻结、失效 |
| 角色来源 | 客户端（C端）认证、入库单、出库单、转让单、仓单、融资/抵质押等 |
| 来源单据 | 来源业务记录和单据号 |
| 生效/失效时间 | 角色关系开始和结束使用的时间 |
| 首次产生时间 | 该角色关系首次产生的时间 |
| 最近使用时间 | 最近一次被业务引用的时间 |
| 冻结原因 | 角色被冻结时的原因和依据 |

示例：

```text
张三 / 合作方主体
├─ 货主：客户端（C端）认证 + 入库单 RK20260907001，正常
├─ 提货经办人：出库单 CK20260908002，正常
└─ 接收方：转让单 ZR20260909003，待转让生效
```

## 5. 业务角色、产生环节与来源

### 5.1 角色总览

| 业务角色 | 主体类型 | 主要产生环节 | 来源单据/数据 | 是否直接影响货主地址规则 | 角色说明 |
|---|---|---|---|---|---|
| 货主 | 个人/企业 | 客户端（C端）认证、入库、转让生效 | 客户认证、入库记录、转让记录 | 是，个人主体成为货主时校验 | 货物权属主体，核心业务角色 |
| 提货主体 | 个人/企业 | 出库申请或提货办理 | 出库记录、提货单 | 否 | 企业提货时可代表实际承运或提货单位 |
| 提货经办人 | 个人 | 企业提货或非本人提货 | 出库记录、提货单 | 否 | 现场实际办理提货的自然人，不等于货主 |
| 接收方 | 个人/企业 | 货物转让 | 转让记录 | 仅在转让生效后成为货主时校验 | 转让业务中的受让主体 |
| 资金方/抵质押权利人 | 企业 | 融资分配、抵质押业务办理 | 融资需求、抵质押单 | 否 | 只能选符合条件的企业主体 |
| 仓单存货人 | 个人/企业 | 仓单开立 | 仓单记录 | 通常复用已有货主，不重复建档 | 仓单开立时的存货/货权主体 |
| 仓单持有人 | 个人/企业 | 仓单流转、抵质押、平仓变更 | 仓单变更记录、货权档案 | 依业务是否成为货主而定 | 时点关系，必须保留变更历史 |
| 仓储机构/监管机构 | 企业/机构 | 项目、仓库或监管合作配置 | 项目、仓库、监管资料 | 否 | 是否纳入合作方角色取决于后续业务选择需求 |

### 5.2 不属于合作方业务角色的身份

以下身份不能写成合作方角色，也不能以此判断业务主体身份：

- 制单人、审批人、业务运营、风控人员；
- 仓库管理员、监管员、平台管理员；
- 账号所属机构；
- 仓库档案中的管理方；
- 客户账号本人（企业客户账号本人可能只是联系人或经办人）。

这些身份分别由统一角色访问控制（RBAC）、机构/账号管理、仓库档案或客户账号关系处理。

### 5.3 角色产生和复用原则

```text
业务环节输入主体标识
        |
        v
按身份证号/统一社会信用代码查询合作方
        |
        +-- 已存在主体：复用统一合作方主体
        |       |
        |       +-- 已有该角色：复用角色关系
        |       +-- 没有该角色：追加角色关系并记录来源单据
        |
        +-- 不存在主体：按当前场景创建简易或完整档案
                |
                +-- 需要成为个人货主：先补证件地址并做地址规则校验
                +-- 仅提货人/接收方等非货主角色：按角色场景要求补资料
```

业务单据可以“静默沉淀”简易合作方，但必须满足：

1. 识别字段经过格式校验；
2. 已存在主体不得重复创建；
3. 新增角色必须记录来源单据；
4. 简易档案标记为“待补全”，不能伪装成已完成认证主体；
5. 一旦新增或生效“货主”角色，必须执行货主准入规则。

## 6. 业务流程设计

### 6.1 客户端（C端）客户注册与认证

```text
客户端（C端）注册账号
    |
    v
个人/企业认证
    |
    +-- 个人认证
    |      |
    |      v
    |   按身份证号创建或绑定个人合作方
    |      |
    |      v
    |   默认增加货主角色
    |      |
    |      v
    |   补充证件地址（来源：身份证）
    |      |
    |      v
    |   根据配置执行必填和地址唯一校验
    |
    +-- 企业认证
           |
           v
        按统一社会信用代码创建或绑定企业合作方
           |
           v
        同步/补充证件地址（来源：营业执照）
           |
           v
        默认增加货主角色（具体以客户业务口径为准）
```

企业客户端（C端）账号绑定的是企业合作方主体；注册账号本人不自动替代企业主体。账号本人如在出库现场办理提货，可以另行形成提货经办人关系。

### 6.2 合作方档案新增、复用与编辑

#### 新增个人主体

1. 选择主体类型“个人”；
2. 录入姓名、身份证号、手机号等信息；
3. 按身份证号查询已有主体；
4. 若已存在，提示进入原主体追加角色或补全资料，不允许重复建档；
5. 若不存在，录入证件地址并记录来源为身份证；
6. 若本次增加货主角色，按当前租户/项目配置执行必填和地址唯一校验；
7. 校验通过后创建主体和角色关系，来源标记为人工建档。

#### 新增企业主体

1. 选择主体类型“企业”；
2. 录入企业名称、统一社会信用代码、联系人和联系电话；
3. 按统一社会信用代码查询已有主体；
4. 若已存在，复用主体并追加角色，不允许重复建档；
5. 维护证件地址，来源标记为营业执照/企业认证资料；
6. 企业地址不参与本次“一个地址只能绑定一个个人身份证号”的规则；
7. 保存后记录企业资料来源和变更日志。

#### 个人货主修改证件地址

```text
合作方档案 → 个人货主详情 → 编辑证件地址
        |
        v
地址标准化
        |
        v
查询同一适用范围内其他有效个人货主
        |
        +-- 命中其他身份证号：阻止保存
        |
        +-- 未命中或仅命中当前身份证号：保存新地址并写入变更记录
```

### 6.3 入库预约与入库记录

涉及菜单：

- `工作中心 → 审批中心 → 客户需求审批 → 客户入库预约`；
- `仓储 → 入库管理 → 入库记录`；
- 移动端（H5）`业务办理 → 客户需求审批 → 客户入库预约`或相应入库页面。

改造后的流程：

1. 选择货主类型；
2. 在现有货主选择控件中选择已有合作方货主，或点击“创建新货主”；
3. 选择已有个人货主时，按原页面展示姓名、身份证号等主体识别信息；
4. 选择已有企业货主时，按原页面展示企业名称、统一社会信用代码等主体识别信息；
5. 点击“查看货主”后，通过弹窗查看货主基础信息、证件地址、地址来源、角色和状态；
6. 点击“创建新货主”后，进入新货主创建流程，按配置补充证件地址并执行地址规则；
7. 继续原有货品、仓库、库位、照片、附件和未堆放数量校验；
8. 生成入库申请并进入原有审批流程。

个人货主地址冲突时：

- 不创建新的个人合作方；
- 不增加货主角色；
- 不创建入库申请；
- 不进入审批中心；
- 不发送新货主认证短信；
- 页面提示统一为：`已有相同证件地址，不能重复入库`。

同一个人可以有多次入库记录。地址唯一规则约束的是“个人货主证件地址 → 身份证号”的关系，不是入库记录数量。

#### 入库页面的最小改造交互

入库新增页和入库详情页不新增独立的证件地址输入区，也不要求把证件地址放在货主选择区旁边长期展示。沿用现有货主选择布局，在货主选择控件附近增加两个入口：

| 入口 | 功能 |
|---|---|
| 查看货主 | 打开只读弹窗，展示主体类型、姓名/企业名称、身份证号或统一社会信用代码的脱敏信息、联系方式、证件地址及来源、业务角色、主体/角色状态和资料完整度；按权限提供“查看合作方详情”或“去补全资料”。 |
| 创建新货主 | 按系统已有的“去发起入库”类跳转/弹窗模式，打开新货主创建流程；创建完成后返回原入库页面，并自动选中刚创建的货主。 |

交互规则：

1. 选择已有货主后，主表单只保留当前页面原有的货主名称、类型和必要识别信息，不平铺证件地址；
2. 证件地址必填、地址来源和地址唯一校验在“创建新货主”、补全资料或提交业务时执行，规则来源于合作方准入配置；
3. 已有货主缺少必填证件地址时，提交时提示资料不完整，并引导用户通过“查看货主”进入补全，不在入库页面新增一套地址编辑逻辑；
4. 个人货主地址冲突仍在创建/绑定或提交校验时阻断，主页面只展示统一提示，不展示冲突主体的敏感信息；
5. 入库详情查看货主时，弹窗可以展示当前合作方信息，但历史入库事实仍以业务发生时保存的主体快照为准。

### 6.4 出库记录与提货单

涉及菜单：

- `仓储 → 出库管理 → 出库记录`；
- `仓储 → 提货单`；
- 移动端（H5）`工作台 → 仓储 → 出库管理`、`提货单`。

改造要求：

- 出库货主引用已有合作方主体；
- 提货主体引用合作方主体；
- 企业提货时保留企业主体和实际提货经办人两层关系；
- 个人提货人按身份证号识别，手机号仅作为检索或联系方式；
- 提货经办人不触发个人货主证件地址唯一规则；
- 出库/提货详情展示业务发生时的主体快照，支持跳转当前合作方详情但不以当前主档覆盖历史快照；
- 已冻结的提货经办人或提货主体按角色状态和风控规则拦截新提货业务，具体拦截范围需与门禁、提货码规则联调。

### 6.5 货物转让

涉及菜单：`仓储 → 货物管理 → 转让记录`，以及移动端（H5）`业务办理 → 业务发起 → 货物转让`。

流程要求：

1. 转让申请录入转让接收方；
2. 按身份证号或统一社会信用代码查找合作方；
3. 已存在则复用并记录“接收方”角色关系；
4. 不存在则沉淀简易主体，角色先处于待生效；
5. 转让生效后，接收方成为新货主时执行货主准入规则；
6. 个人接收方成为货主且地址冲突时，阻止转让生效，不创建新货主关系；
7. 原货主、接收方、货权变更时间和业务发生时主体资料都保存不可变快照。

### 6.6 仓单、货权档案和持有人变更

涉及菜单：

- `仓储 → 仓单管理`；
- `仓储 → 货权管理 → 货权档案`；
- `融资/监管 → 抵质押业务 → 抵质押业务管理 → 货权档案`或复用页面；
- 移动端（H5）`工作台 → 仓单管理`、`货权档案`。

改造要求：

- 仓单存货人优先复用货主主体，不单独创建重复主体；
- 仓单持有人以时点关系管理，必须有变更记录，不能只保存一个永久标签；
- 抵质押、仓单流转、平仓变更后形成新的持有人关系和业务快照；
- 只有持有人在业务上真正成为货主时，才触发个人货主地址规则；
- 历史仓单和货权档案保留开立/变更时主体名称、识别号、地址等快照。

### 6.7 融资需求、资金方和抵质押业务

涉及菜单：

- `融资/监管 → 融资管理 → 客户融资需求线索`；
- `融资/监管 → 抵质押业务 → 抵质押业务办理`；
- `融资/监管 → 抵质押业务 → 抵质押业务管理`；
- `配置管理 → 融资产品配置`及相关资金方候选池。

改造建议：

- 融资需求的客户/货主引用合作方主体；
- 资金方候选池按“合作方角色 = 资金方/抵质押权利人、主体类型 = 企业、状态 = 正常、适用项目/租户”过滤；
- 资金方名称不能靠手工文本判断，也不能直接从系统权限角色推断；
- 如资金方同时需要后台端（B端）账号归属和数据权限，可另外绑定机构，但“机构绑定”不是本期合作方主数据的前置必需条件；
- 资金方状态或角色被冻结时，新增融资派发和抵质押办理按业务规则拦截；
- 已发生的融资、抵质押、授信和结算记录保存当时资金方主体快照。

### 6.8 移库、加工、退货及内部联动

涉及菜单：

- `仓储 → 库存查询 → 库存明细`；
- `仓储 → 货物异动`相关记录；
- `仓储 → 加工管理 → 加工记录`；
- 移库、退货入库、加工产出等相关作业页面。

规则：

- 同一货主的移库、加工产出、退货入库等系统联动流程直接复用原合作方主体；
- 不因为地址已经存在，就阻断同一货主的内部库存流转；
- 加工产出如仍属于原货主，不新增货主主体和地址校验；
- 库存、货物异动、货权档案按统一合作方主体关联；
- 业务发生时的主体名称、识别号和地址根据是否需要作为凭证事实保存快照。

### 6.9 结算、开票和风险联动

涉及菜单：

- `结算 → 监管结算 → 项目结算管理`；
- `结算 → 结算汇总`；
- `风控`下的风险信息、风险公示及相关合作方风险联动能力；
- 统计/看板中的客户、货主、资金方和仓储业务统计。

要求：

- 开票主体引用合作方主体及证件地址；
- 发票、结算单和对账资料保存生成时的地址快照；
- 合作方地址后续修改不得回写历史发票、历史结算单和司法存证材料；
- 风控冻结按角色维度传递：冻结货主角色，不自动冻结仓储机构角色；
- 合作方 360° 视图可汇总关联库存、仓单、融资、抵质押、预警和结算，但下游原菜单仍是各业务事实的维护入口。

### 7.2 菜单动作定义

| 动作 | 含义 |
|---|---|
| 新增 | 创建新菜单、页面、配置入口或统一能力 |
| 修改 | 保留原菜单和原业务职责，调整字段、引用对象、校验或展示 |
| 保留/澄清 | 不改变主要业务，但明确其不应承担的职责，避免重复建设 |
| 取消重复入口 | 不删除核心菜单，只取消模块内重复维护和重复校验 |
| 后续规划 | 本期不作为开发阻断条件，保留后续关系设计空间 |

| `仓储 → 加工管理 → 加工记录` | 修改 | 新增加工、完成、撤销、作废和操作记录 | 原货主复用合作方；加工产出继承主体关系和快照 | 不因内部加工产生重复货主；不重复录入地址 | P1 |
| `仓储 → 库存查询 → 库存明细/存货管理` | 修改 | 库存查询、筛选、详情 | 货主筛选支持合作方主体、名称、身份证或统一社会信用代码脱敏检索；详情显示证件地址状态或快照 | 不以手机号作为长期主体唯一标识 | P1 |
| `融资/监管 → 融资管理 → 客户融资需求线索` | 修改 | 客户融资需求、线索流转 | 客户和货主引用合作方；企业客户账号与企业主体分开显示 | 不把登录账号本人直接当作企业货主 | P1 |
| `融资/监管 → 抵质押业务 → 抵质押业务办理` | 修改 | 选择货主、选择货物、开立抵/质押单 | 货主引用合作方；资金方按合作方角色和状态过滤；保存主体快照 | 不用机构名称文本替代资金方主体；不强依赖机构-合作方绑定 | P1 |
| `融资/监管 → 抵质押业务 → 抵质押业务管理` | 修改 | 抵质押订单管理、风险、出库、解押、平仓等 | 货主、资金方、持有人统一按合作方主体关联；角色冻结按规则影响新增操作 | 不因冻结一个角色而全局冻结多角色机构 | P1 |
| `结算 → 监管结算 → 项目结算管理` | 修改 | 收支结算、结算、结清、作废和下载 | 开票主体引用合作方及证件地址；生成结算单时保存地址快照 | 不直接从当前客户页面临时拼接地址；不回写历史结算资料 | P1 |
| `结算 → 结算汇总` | 修改 | 项目结算汇总和导出 | 支持按合作方主体、角色和项目汇总 | 不按名称文本聚合同名主体 | P1 |
| `风控/风险公示` | 修改/后续联动 | 原有预警、风险处置、公示和审计 | 增加合作方角色状态、冻结来源、关联业务风险展示；需要时触发角色冻结 | 不直接修改历史主体快照和已存证业务事实 | P1 |
| `统计/看板` | 修改/后续联动 | 原有业务统计和图表 | 统一使用合作方主体聚合货主、资金方、仓储等维度 | 不按主体名称或手机号做统计主键 | P1 |

### 8.3 删除、取消和禁止新增的重复内容

这里的“删除”主要是删除重复职责和重复入口，不是删除现有核心业务菜单。

| 取消内容 | 处理方式 | 原因 |
|---|---|---|
| 各业务模块独立维护货主档案 | 删除重复维护入口，统一调用合作方档案/服务 | 避免同一主体多份资料不一致 |
| 各业务模块独立维护提货人、接收方主数据 | 删除重复主数据，改为合作方角色关系 | 保留统一身份识别和来源 |
| 各业务单据独立保存一份可编辑证件地址 | 取消主档职责，业务页面通过“查看货主”弹窗查看；凭证需要时保存不可变快照 | 防止地址多头维护 |
| 各模块各自实现主体重复校验 | 删除模块内重复算法，统一调用主体识别服务 | 保证身份证号/统一社会信用代码口径一致 |
| 单独新增“证件地址管理”菜单 | 不新增；地址作为合作方档案字段维护 | 地址不是独立业务对象 |
| 单独新增“地址冲突审批”菜单 | 不新增；在适用业务提交前同步阻断 | 冲突属于准入校验，不是常规审批事项 |
| 通过机构名称判断资金方、仓储方或货主 | 删除文本判断逻辑 | 机构和业务主体不是同一个对象 |
| 通过系统权限角色判断货主/提货人 | 删除混用逻辑 | 统一角色访问控制（RBAC）角色与业务角色职责不同 |

## 9. 新增菜单一：合作方档案

### 9.1 页面定位

`合作方管理 → 合作方档案`是全平台业务主体的统一主档入口，负责主体资料和角色关系，不负责维护具体入库、出库、仓单或融资业务。

### 9.2 列表功能

筛选项建议包括：

- 主体类型：个人、企业；
- 主体名称/姓名；
- 身份证号或统一社会信用代码；
- 合作方角色：货主、提货主体、提货经办人、接收方、资金方、仓单存货人、仓单持有人；
- 主体状态：正常、冻结、注销；
- 角色状态：正常、冻结、失效、待补全；
- 创建来源：客户端（C端）认证、人工建档、入库单沉淀、出库单沉淀、转让单沉淀、仓单沉淀、融资/抵质押沉淀；
- 证件地址状态：已录入、未录入、待核验；
- 创建时间、最近使用时间。

列表展示建议：

| 列 | 展示要求 |
|---|---|
| 主体名称 | 个人姓名或企业全称，点击进入详情 |
| 主体类型 | 个人/企业 |
| 身份标识 | 个人身份证号脱敏；企业统一社会信用代码按权限脱敏 |
| 业务角色 | 多角色标签，展示正常/冻结/失效状态 |
| 证件地址 | 只展示“已录入/未录入/待核验”或按权限脱敏，不默认展示完整地址 |
| 来源 | 首次创建来源，详情展示全部来源 |
| 主体状态 | 正常、冻结、注销 |
| 风险标识 | 有关联高风险时展示风险状态，不泄漏无关风险详情 |
| 最近使用 | 最近被业务单据引用的时间 |
| 操作 | 详情、编辑、追加角色、冻结/解冻、注销（按权限展示） |

### 9.3 新增/编辑功能

#### 个人主体字段

| 字段 | 必填建议 | 说明 |
|---|---|---|
| 主体类型 | 是 | 固定为个人后展示个人字段 |
| 姓名 | 是 | 与身份证资料一致 |
| 身份证号 | 是 | 脱敏展示；作为主体识别键 |
| 手机号 | 按场景 | 联系方式，不作为唯一主体键 |
| 证件地址 | 按准入规则 | 来源为身份证；个人成为货主时按规则校验 |
| 证件地址来源 | 系统生成 | 个人固定来源为身份证，用户不可自由改成营业执照 |
| 资料状态 | 系统生成/可补全 | 完整、简易、待补全、待核验 |
| 合作方角色 | 按权限 | 追加货主、提货人、接收方等角色关系 |

#### 企业主体字段

| 字段 | 必填建议 | 说明 |
|---|---|---|
| 主体类型 | 是 | 固定为企业后展示企业字段 |
| 企业名称 | 是 | 与营业执照一致 |
| 统一社会信用代码 | 是 | 作为主体识别键 |
| 证件地址 | 按企业认证要求 | 来源为营业执照或企业认证资料 |
| 证件地址来源 | 系统生成/资料选择 | 推荐取营业执照或企业认证资料 |
| 联系人姓名 | 按角色/场景 | 企业对接人，不等于企业主体 |
| 联系电话 | 按角色/场景 | 企业联系信息 |
| 合作方角色 | 按权限 | 货主、接收方、资金方等 |

### 9.4 详情页页签（Tab）

建议详情包含以下页签（Tab）：

1. **基础档案**：主体基本资料、证件资料、证件地址及来源、资料完整度；
2. **业务角色**：角色关系、角色状态、产生环节、来源单据、生效/失效时间；
3. **关联客户账号**：客户端（C端）账号、认证状态、绑定时间和解绑记录；
4. **关联业务单据**：入库、出库、提货、转让、仓单、融资、抵质押、结算；
5. **库存与货权**：当前库存、仓单、货权变更、持有人时间轴；
6. **地址及资料变更**：地址版本、来源、修改前后摘要、操作人、时间和原因；
7. **风险与操作日志**：冻结、解冻、风险关联、查询和变更审计记录。

### 9.5 主体状态与角色状态

主体状态：

| 状态 | 含义 |
|---|---|
| 正常 | 主体可按角色参与正常业务 |
| 冻结 | 主体存在限制，但具体业务拦截按角色和规则执行 |
| 注销 | 不允许产生新的业务关系，只保留历史查询和审计 |

角色状态：

| 状态 | 含义 |
|---|---|
| 待补全 | 业务单据自动沉淀的简易角色，资料未补全 |
| 正常 | 该主体可以在该业务角色下参与业务 |
| 冻结 | 只限制该角色相关新增或高风险业务 |
| 失效 | 该角色关系不再使用，但历史关系保留 |

冻结原则：

- 采用“按角色隔离冻结”；
- 货主角色因违约冻结，不自动冻结该主体作为仓储机构或提货经办人的其他角色；
- 新增业务接口必须校验主体状态和适用角色状态；
- 存量业务的查看、历史台账和必要的履约动作按照各业务规则处理；
- 后台端（B端）账号原则上不因合作方冻结而锁死，保留历史查阅，但服务端拦截受限写操作；
- 解冻需要人工处理或审批，并记录原因、依据和审计日志。

## 10. 新增菜单二：合作方准入规则

### 10.1 页面定位

`配置管理 → 平台管理 → 合作方准入规则`是合作方业务角色和字段校验的配置入口。它不是字典维护页面，也不是审批中心，而是控制“业务场景产生某种合作方角色时需要什么资料、执行什么校验”的规则页面。

### 10.2 规则配置维度

每条规则至少包含：

| 配置项 | 说明 |
|---|---|
| 规则名称/编码 | 便于识别和审计 |
| 适用主体类型 | 个人、企业或全部 |
| 适用业务角色 | 货主、提货主体、提货经办人、接收方、资金方等 |
| 适用业务场景 | 客户端（C端）认证、入库、出库、转让、仓单、抵质押等 |
| 业务信息要求 | 姓名、身份证号、信用代码、手机号、证件地址等 |
| 是否必填 | 必填/非必填/按条件必填 |
| 信息来源 | 身份证、营业执照、客户端（C端）认证、业务单据、人工录入 |
| 唯一性校验 | 主体标识唯一、地址唯一、其他后续规则 |
| 标准化规则 | 地址比较值、证件号格式、名称空格和大小写处理 |
| 冲突处理 | 阻断、提示并允许继续、转人工核验；本期地址冲突为阻断 |
| 自动沉淀 | 是否允许业务单据创建简易合作方 |
| 角色追加 | 已存在主体是否自动追加当前角色 |
| 作用范围 | 租户、项目或租户+项目 |
| 生效时间/版本 | 新规则生效时间、版本号、变更历史 |
| 历史检查 | 开启规则前检查历史缺失和冲突数据 |

### 10.3 地址相关的两个控制项

推荐在规则页面把地址规则拆成两个清晰的开关/选项：

| 控制项 | 选项 | 作用 |
|---|---|---|
| 个人货主证件地址要求 | 必填/非必填 | 控制个人主体新增或成为货主时是否必须填写地址 |
| 个人货主证件地址唯一校验 | 开启/关闭 | 控制同一范围内相同证件地址能否绑定不同身份证号 |

两项互不替代：地址可以配置为“非必填 + 开启唯一校验”，此时已填写地址必须唯一，未填写地址不参与地址比较；也可以配置为“必填 + 关闭唯一校验”，此时必须有地址但不阻断相同地址。

推荐默认规则：

- 个人货主证件地址：必填；
- 个人货主证件地址唯一校验：开启；
- 个人提货人/提货经办人：是否必填按出库业务现有要求，不继承货主地址规则；
- 企业证件地址：按企业认证资料要求，不参与本次个人地址一对一校验。

默认值最终以产品评审为准，不应在研发中自行固化。

### 10.4 规则生效和版本

- 规则采用版本号；
- 新版本保存后只影响新产生或新生效的业务关系；
- 已完成业务的字段和快照不回写；
- 修改地址必填/唯一校验开关必须记录操作人、时间、前后值和原因；
- 开启唯一校验前执行历史数据检查；
- 若历史数据已存在地址冲突，建议阻止规则直接生效，先处理冲突或明确例外策略；
- 若历史货主缺失地址，开启“地址必填”前必须明确补录窗口和存量业务处理方式。

## 11. 证件地址详细规则

### 11.1 字段语义

“证件地址”是证件上的登记地址，不是收货地址、仓库地址、开户地址、联系人地址或实际居住地址。

- 个人：身份证对应地址，来源为身份证；
- 企业：营业执照或企业认证资料对应地址，来源为营业执照/企业认证资料；
- 合作方档案和“查看货主”弹窗展示“证件地址”，通过辅助文案显示来源；业务主表单不默认平铺展示；
- 不新增第二个“家庭地址”或“入库地址”字段来代替证件地址；
- 地址完整原文按敏感资料权限控制，列表默认仅展示状态或脱敏内容。

### 11.2 唯一校验范围和对象

地址唯一关系定义为：

```text
同一适用租户/项目
+ 有效个人合作方
+ 已拥有货主角色
+ 证件地址的标准化比较结果相同
→ 只能对应一个身份证号
```

明确不纳入本次规则的对象：

- 企业货主；
- 只有提货人角色的个人；
- 只有接收方角色且尚未成为货主的个人；
- 仓库管理方；
- 地址字段为空的主体；
- 不同租户之间的个人主体；
- 同一个身份证号下的多条入库记录。

### 11.3 触发场景

需要执行个人货主地址规则的场景：

1. 客户端（C端）个人认证首次成为货主；
2. 合作方档案新建个人货主；
3. 已有个人主体追加货主角色；
4. 个人货主修改证件地址；
5. 转让接收方在转让生效后成为新货主；
6. 入库新增个人货主；
7. 资金/仓单业务明确将个人主体变更为货主的场景。

不应触发的场景：

1. 个人作为普通提货人或提货经办人；
2. 个人作为尚未生效的转让接收方；
3. 同一个人重复入库；
4. 原货主的移库、退货入库、加工产出等内部复用；
5. 仓库管理方资料维护；
6. 仅查询历史单据或查看库存。

### 11.4 地址标准化

唯一校验不能直接依赖用户输入字符串。业务上需要区分并保留：

- 证件地址原文：用于展示和审计；
- 地址标准化比较结果：用于唯一校验；
- 证件地址来源：用于追溯身份证或营业执照等资料来源；
- 地址版本或变更序号：用于记录地址变更历史。

标准化至少应统一：

- 前后空格、连续空格和全角半角；
- 省、市、区县等行政区划表达；
- 常见行政区划后缀和道路、号、栋、室等格式；
- 不应未经业务确认擅自把“同音、近似地址、不同门牌”判为相同地址。

地址标准化规则需要由业务和研发共同确认，尤其要明确行政区划变更、证件地址简称和历史地址的处理。

### 11.5 冲突处理

在个人货主新增、绑定、追加货主角色或修改地址时，若命中其他身份证号：

```text
阻止当前动作
→ 不创建新主体
→ 不追加货主角色
→ 不提交相关业务申请
→ 不进入审批
→ 记录校验失败审计日志
```

统一提示：

> `已有相同证件地址，不能重复入库`

提示中不能展示已有主体的姓名、身份证号或完整地址，避免泄露个人敏感信息。后台授权人员可在权限范围内查看冲突摘要和处理日志。

### 11.6 地址修改和历史快照

- 主档地址修改必须保留旧值版本，不允许物理覆盖后无法追溯；
- 新地址先执行格式、来源和唯一性校验，再提交保存；
- 已产生的入库、仓单、抵质押、结算、开票和风险存证记录不回写；
- 单据详情可以同时展示“业务发生时地址快照”和“当前主档地址”，并明确标识二者性质不同；
- 地址修改应记录操作人、时间、来源资料、修改原因和前后版本。

## 12. 基础配置与实施顺序

实际落地不能从入库页面开始改。业务页面能够选择和校验“某某是什么主体/角色”，前提是底层字典、权限、主数据和配置入口已经具备。

### 阶段一：机构、字典、账号和权限基础

涉及：

- `配置管理 → 平台管理 → 机构类别`；
- `配置管理 → 平台管理 → 机构管理`；
- `配置管理 → 平台管理 → 角色管理`；
- `配置管理 → 平台管理 → 账号管理`。

工作内容：

1. 确认机构类别，按实际组织需要维护资金方、仓储机构、监管机构等分类；
2. 机构类别仅描述组织属性，不作为货主、提货人等业务角色字典；
3. 保留机构层级、机构归属、账号归属和数据权限；
4. 为合作方档案、准入规则及相关业务按钮配置系统权限；
5. 明确租户、项目、机构和仓库数据权限边界；
6. 本阶段不强制建立机构-合作方关联。

### 阶段二：合作方主体、角色和地址基础

涉及：

- `合作方管理 → 合作方档案`；
- `配置管理 → 平台管理 → 合作方准入规则`。

工作内容：

1. 建立个人/企业主体业务模型；
2. 建立身份证号/统一社会信用代码唯一识别；
3. 建立角色关系和来源单据；
4. 增加证件地址和地址来源信息；
5. 配置个人货主地址必填/非必填；
6. 配置个人货主地址唯一校验开关；
7. 建立地址标准化、冲突阻断和审计能力；
8. 建立合作方冻结、解冻、注销和简易档案补全能力。

### 阶段三：客户账号和可选的机构协作关系

涉及：

- `交易 → 客户管理`；
- `配置管理 → 融资产品配置`；
- 必要时 `配置管理 → 机构管理`。

工作内容：

1. 客户端（C端）个人/企业认证账号与合作方主体绑定；
2. 企业账号和企业主体分开保存；
3. 资金方候选池引用具有资金方角色且状态正常的合作方；
4. 只有存在账号归属、数据权限或外部协作需要时，才设计机构与合作方的可选关系；
5. 不以该关系作为个人货主建档的前置条件。

### 阶段四：核心作业菜单接入

按以下顺序接入：

1. 客户入库预约；
2. 入库记录；
3. 出库记录和提货单；
4. 货物转让；
5. 仓单和货权档案；
6. 融资需求、抵质押办理和管理；
7. 加工、移库、退货等内部联动。

每个菜单只负责业务操作，主体创建、复用、角色追加和地址规则调用统一服务。

### 阶段五：下游展示、快照、风险和结算

涉及：

- 库存明细、存货管理、库存流水；
- 货权档案、仓单持有人变更；
- 风险信息、风险公示、合作方冻结联动；
- 项目结算、结算汇总、开票；
- 统计看板和审计报表。

工作内容：

1. 全部下游引用统一合作方主体；
2. 需要证明业务发生事实的菜单保存不可变快照；
3. 统一敏感字段脱敏和数据权限；
4. 统一按合作方主体聚合统计；
5. 将地址、角色和状态变更写入审计链路。

## 13. 权限、数据隔离和审计

### 13.1 权限动作

| 权限动作 | 平台超管 | 业务运营 | 风控人员 | 项目管理员 | 外部合作方账号 |
|---|---:|---:|---:|---:|---:|
| 查看合作方列表 | 是 | 按数据权限 | 按数据权限 | 按项目权限 | 否，除非查看自身业务主体 |
| 查看合作方详情 | 是 | 按数据权限 | 按数据权限 | 按项目权限 | 仅自身范围 |
| 新增合作方 | 是 | 是 | 按授权 | 按授权 | 否 |
| 编辑普通资料 | 是 | 按授权 | 原则上只读 | 按授权 | 仅允许受限资料维护 |
| 编辑个人证件地址 | 是 | 授权后 | 可查看/核验 | 按授权 | 原则上不直接修改 |
| 追加/移除业务角色 | 是 | 授权后 | 可冻结/解冻角色 | 按授权 | 否 |
| 冻结/解冻角色 | 是 | 否或按授权 | 是 | 按授权 | 否 |
| 注销主体 | 是 | 否 | 否 | 否或按授权 | 否 |
| 修改准入规则 | 是 | 否 | 否或会签 | 是或按授权 | 否 |
| 查看完整身份证/地址 | 按敏感权限 | 最小必要 | 按风控权限 | 最小必要 | 否 |

具体权限编码需要在权限清单中另行落表，本表仅定义业务边界。

### 13.2 数据隔离

- 合作方主档按租户隔离；项目可配置可见范围和可用范围；
- 外部合作方默认只能查看自身主体及与自身相关的业务台账；
- 平台运营和风控角色可在授权范围内查看跨业务关联；
- 机构数据权限仍由机构、账号和角色控制；
- 合作方角色不能直接突破机构和项目数据权限；
- 地址冲突提示不得泄露其他主体信息；
- 身份证号、证件地址在列表和传输层脱敏或加密。

### 13.3 审计和不可变快照

以下操作必须全量审计：

- 主体新增、复用命中、编辑和资料补全；
- 身份证号/统一社会信用代码校验结果；
- 角色新增、追加、移除、冻结、解冻、失效；
- 证件地址新增、修改、冲突拦截和来源变更；
- 主体冻结、解冻和注销；
- 准入规则新增、编辑、启停、生效和历史版本；
- 业务单据引用合作方和创建简易档案；
- 查询完整敏感资料的行为。

业务快照至少包含：

- 合作方主体及其内部标识；
- 主体名称/姓名；
- 身份证号或统一社会信用代码的加密/脱敏版本；
- 业务发生时证件地址及来源；
- 角色、来源单据号、业务时间；
- 快照版本和生成时间。

主档后续变化不能修改既有快照、历史单据、结算凭证或司法存证材料。

## 14. 历史数据迁移与兼容

### 14.1 现状问题

当前多个页面存在以手机号、姓名或企业名称作为货主展示或检索标识的情况，部分入库流程已有个人货主身份证号和货主档案沉淀，但尚未形成统一合作方主档和证件地址入口。

### 14.2 迁移原则

1. 个人主体优先以身份证号合并，手机号只作为联系方式和辅助检索；
2. 企业主体优先以统一社会信用代码合并，企业名称只作为展示和辅助检索；
3. 无身份证号/统一社会信用代码的历史记录不强行合并，进入待核验池；
4. 同一识别号对应多份历史档案时，保留主记录和合并日志，不物理删除历史事实；
5. 历史单据的旧名称、手机号和地址必须保留原快照；
6. 合作方主档补全不会回写或改写历史业务发生事实；
7. 开启地址必填或唯一校验前，先统计历史缺失和冲突数据。

### 14.3 迁移步骤

```text
盘点各模块主体字段
    → 建立身份证号/统一社会信用代码映射
    → 生成合作方主体和角色关系
    → 标记来源单据和待补全数据
    → 处理重复主体及地址冲突
    → 校验业务查询、权限和报表
    → 分批切换业务菜单引用统一合作方主体
    → 保留旧字段只读兼容和回溯能力
```

## 15. 业务规则摘要

| 规则编号 | 规则名称 | 规则摘要 |
|---|---|---|
| 规则1 | 主体唯一识别 | 个人按身份证号、企业按统一社会信用代码识别；已存在则复用，不重复建档 |
| 规则2 | 角色关系留痕 | 业务角色必须记录来源场景、来源单据、状态和生效失效时间 |
| 规则3 | 静默沉淀 | 业务单据可沉淀简易主体，但必须标记待补全并记录来源 |
| 规则4 | 货主准入 | 新增或生效货主角色前，按租户/项目配置执行信息必填和地址校验 |
| 规则5 | 地址一对一 | 同一范围内有效个人货主的标准化证件地址只能绑定一个身份证号 |
| 规则6 | 地址冲突阻断 | 地址冲突不创建主体、不追加货主角色、不生成申请、不进入审批 |
| 规则7 | 内部流程复用 | 移库、加工产出、退货等复用原货主，不因地址规则阻断 |
| 规则8 | 角色隔离冻结 | 冻结作用于特定主体角色，不能默认全局封禁多角色主体 |
| 规则 9 | 账号不等于主体 | 客户端（C端）账号、后台端（B端）账号和业务合作方主体分别管理 |
| 规则10 | 管理方独立 | 仓库管理方属于仓库档案属性，不从合作方中选择 |
| 规则11 | 历史快照不可变 | 主档修改不回写已产生的业务、结算、风险和存证快照 |
| 规则12 | 配置版本 | 准入规则和地址规则使用版本管理，变更只影响新业务关系 |

## 16. 评审和验收关注点

### 16.1 基础数据

- 是否明确机构类别和合作方角色的边界；
- 是否能够不依赖机构就创建个人货主；
- 是否能够按身份证号/统一社会信用代码复用主体；
- 是否能记录同一主体多个角色和多个来源；
- 是否能把客户端（C端）客户账号绑定到个人/企业合作方。

### 16.2 地址规则

- 是否有单独、可发现的合作方准入规则配置入口；
- 是否可以独立设置“地址必填”和“地址唯一校验”；
- 个人货主新增、追加角色和修改地址是否执行规则；
- 提货人、普通接收方、仓库管理方是否不会误触发规则；
- 地址冲突是否统一阻断并使用统一提示；
- 是否不会泄露其他主体的敏感信息；
- 地址修改后历史单据和发票是否保持原快照。

### 16.3 菜单改造

- 入库、出库、转让、仓单和融资菜单是否均引用统一合作方；
- 是否取消了各菜单的重复主体维护和重复校验；
- 仓库管理方是否仍为基础识别信息而不是合作方选择器；
- 机构管理是否没有被强行改造成合作方主档；
- 角色管理是否仍只维护系统权限；
- 移动端（H5）是否与电脑端（PC）使用一致的主体和规则服务。

### 16.4 风险和审计

- 冻结是否支持按业务角色隔离；
- 受限账号是否仍可查看历史台账但不能发起受限新业务；
- 主体、角色、地址、规则和冲突是否都有审计记录；
- 历史快照是否不可变；
- 统计、风险和结算是否使用合作方主体而不是名称文本聚合。

## 19. 结论

本需求不是简单给入库页面增加一个“证件地址”字段，而是一次主体主数据和业务角色来源的统一。正确的实现顺序应为：

```text
机构/权限基础
    → 合作方主体主档
    → 业务角色及来源关系
    → 合作方准入规则与地址开关
    → 客户、入库、出库、转让、仓单、融资等作业引用
    → 库存、货权、风险、结算和统计联动
```

其中，合作方是业务主体主数据；机构是组织和权限载体；客户账号是登录与认证载体；系统角色是统一角色访问控制（RBAC）载体；仓库管理方是仓库档案识别信息。只有先把这些边界固定，后续“某某是什么机构”“某某是否是货主”“货主地址是否必填”“相同地址是否允许再次入库”等问题，才能在系统中用统一、可配置、可审计的方式处理。
