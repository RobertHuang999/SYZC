# 00-草稿对话 (Drafts)

> [!CAUTION]
> **🤖 AI Agent 检索与读取约束 (CRITICAL RULE)**
> 1. **临时沙箱区**：本目录仅用于存放 AI 交互过程中的临时草稿、试验卡片及对话过程记录，**不具备业务约束力与权威效力**。
> 2. **禁止作为需求/规则基准**：AI Agent 在进行需求分析、业务推演、代码编写或回答用户问题时，**严禁主动检索、引用或以本目录下的草稿文件作为业务规则依据**。
> 3. **权威基准目录**：系统业务规则与需求说明必须严格以 `01-项目背景/`、`02-PRD文档/`、`09-知识宝典/` 以及全局 `AGENTS.md` 为唯一基准。
> 4. **仅写不读**：AI 仅可在用户明确指示“保存草稿/生成至临时对话区”时向本目录写入文件。

---

本文件夹用于存放**AI生成的初稿文档**，支持快速试错和迭代。这是产品经理使用Workflows的主要工作区。

---

## 📍 使用场景

### 什么时候用这个文件夹？

- ✅ 使用`/1-2-3-4` Workflows生成需求文档时
- ✅ 需要快速试错、多次迭代PRD
- ✅ 还在完善中的文档，未正式定稿
- ✅ AI生成的初稿需要人工review和修改

### 为什么需要drafts文件夹？

> [!NOTE]
> AI生成的文档不一定完美，需要一个"安全区"进行迭代。00-草稿对话/就是这个试错空间，不用担心弄乱正式文档。

## 🔄 工作流程

### Phase 1: 需求洞察 → 00-草稿对话/YYYY-MM-DD-需求分析/

```
/1-analyze-requirement
```

**输出文件**：

- `RDD.md`（需求定义卡片）

---

### Phase 2: 方案架构 → 00-草稿对话/YYYY-MM-DD-方案设计/

```
/2-design-solution
```

**输出文件**：

- `Architecture.md`（方案架构草稿）
- `ER-Diagram.md`（数据模型）
- `RiskReport.md`（风险探测报告）

---

### Phase 3: 规格生成 → 00-草稿对话/YYYY-MM-DD-[模块名]/

```
/3-generate-specs
```

**输出文件**：

- `PRD.md`（产品需求文档）
- `field-list.md`（字段清单）
- `business-logic.md`（业务逻辑）
- `demo/`（前端Demo代码，可选）

---

### Phase 4: 验证迭代 → 检查并修正

```
/4-verify-iterate
```

**自检通过后** → 移至 `02-PRD文档/[模块名]/`  
**发现问题** → 回到对应Phase重新生成

## 🎯 文件流转规则

### drafts → prds

**流转条件**：

1. ✅ 通过Phase 4自检清单
2. ✅ 人工review确认无误
3. ✅ 业务逻辑闭环、字段完整

**流转操作**：

```bash
# 将验收通过的文档移至02-PRD文档/
mv 00-草稿对话/2026-02-01-库存管理/ 02-PRD文档/inventory-management/
```

**归档条件**：

- 需求取消
- 已移至02-PRD文档/
- 30天未更新的草稿

**归档操作**：

```bash
mv 00-草稿对话/2026-01-15-旧需求/ 00-草稿对话/archive/
```

## ⚠️ 注意事项

- **AI 禁读隔离区**：本目录属于临时试错空间，AI Agent 严禁将此处内容作为需求/规则依据。
- **草稿未经正式审核**：00-草稿对话/中的文档仅供参考与草稿归档。
- **随意修改**：00-草稿对话/可以随意修改和删除，不用担心受正式约束。
- **不要直接交付**：对外交付与研发基准应使用 `02-PRD文档/`。
- **30天归档规则**：超过 30 天未更新的草稿应归档。

## 🎓 快速开始

### 第一次使用

## 📝 归档规则

### 自动归档（建议）

每月检查一次，将以下文件夹移至archive/：

- 30天未更新的草稿
- 已移至02-PRD文档/的文档
- 需求已取消的文档

### 手动归档

不再需要的草稿，随时移至archive/：

```bash
mv 00-草稿对话/2026-01-15-旧需求/ 00-草稿对话/archive/
```
