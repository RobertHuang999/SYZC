# 需求定义卡片 (RDD - Requirement Definition Draft)

> **创建日期**: 2026-07-24  
> **需求名称**: 抵质押存货与普通存货形态转换（1:N / N:1 / N:N）  
> **原始需求**: 我需要将抵质押单中货物和库存中的普通货物进行加工转换成另一种形态。货物形态支持 1:N、N:1、N:N。  

---

## 1. 核心洞察 (Insight)

### 真实痛点
在供应链金融存货监管中，企业在生产运营过程中需要对存货进行加工、拆分或组合（如原木加工为板材、钢卷剪切为钢板）。传统系统仅支持普通自由库存的拆装，无法满足**“质押存货在监管状态下发生物理形态变更”**的需求：
1. **货权断层**：质押货物加工后，新产物无法自动延续质押物身份，导致质押监管脱节。
2. **风控漏洞**：加工过程中的损耗或贬值可能导致质押存货货值跌破警戒线，资方无法实时感知与拦截。
3. **仓单混淆**：若允许交易所电子仓单或仓单质押中的货物随意加工，将引发严重的法律与货权纠纷。

### JTBD (Jobs-to-be-Done)

> **用户要雇佣这个功能来完成什么任务？**

- **借款企业/仓库监管员** 想要在线上完成存货的加工形态转换登记，以便在不中断合法质押监管的前提下顺利开展生产经营。
- **金融风控官/资方** 想要实时掌握质押物形态转换后的货值变动与质押覆盖率，以便在货值不足时第一时间要求补质或保证金追加，防范坏账风险。

### 业务价值评估

- [x] **High**: 核心业务流程，不做严重影响供应链金融监管的货权穿透与实物监管闭环。

**量化依据**:
1. 避免传统“先解押再加工再重新质押”繁琐流程带来的 3~5 天审批停滞，提升监管效率 80% 以上。
2. 实现了质押物加工全过程 100% 货值重估与跌价风险自动拦截，防范货权虚高与重复质押漏洞。

## 2. 用户故事 (User Story)

### Story 1: 仓库监管员 / 企业操作员 (发起转换)
> **As a** 仓库监管员 / 企业操作员  
> **I want to** 选择普通存货或同属一个质押单的抵质押存货发起 1:N、N:1 或 N:N 的形态转换申请  
> **So that** 能够合规扣减投入原料并报备即将入库的成品形态。

### Story 2: 风控审计官 / 资方代表 (货值试算与风险感知)
> **As a** 资方风控官  
> **I want to** 在转换申请提交时自动获取基于大宗市场行情的货值试算与质押率评估  
> **So that** 一旦转换后货值跌破警戒线能触发弹窗补质提示，若企业执意提交能立即接收到高风险告警。

### Story 3: 审批流管理员 (流程配置)
> **As a** 流程配置管理员  
> **I want to** 自定义形态转换单的审批流程与节点角色  
> **So that** 涉及质押物转换时可按需加入第三方监管员或资方审核人的审批节点。

## 3. 验收标准 & NFR (Acceptance Criteria & Non-Functional Requirements)

### 功能验收标准 (AC)

- [ ] **AC-01（仓单隔离）**: 投入物选择列表中，必须严格排查过滤；若货物处于`仓单中`（电子仓单/仓单质押状态），系统直接禁止勾选并提示“仓单货物严禁加工转换”。
- [ ] **AC-02（同源禁混）**: 选择原料时，系统校验必须为纯普通存货或同属于同一质押单的质押存货，若勾选不同来源原料（如普通+质押或跨质押单），提交时硬性阻断提示“禁止混合加工转换”。
- [ ] **AC-03（形态比例支持）**: 系统必须完整支持 1:N（1原料多产出）、N:1（多原料1产出）、N:N（多原料多产出）明细录入。
- [ ] **AC-04（行情基准计价）**: 录入产出物后，系统自动联动大宗商品市场行情基准价计算各产出物单价及总货值。
- [ ] **AC-05（跌价试算与高警报）**: 当抵质押存货转换后总货值跌破质押警戒线时，系统主动弹出“追加保证金/补充质押物”警告弹窗；若用户选择执意提交，单据及关联质押单必须标记【高风险告警】。
- [ ] **AC-06（状态流转闭环）**: 转换单流转全生命周期：`草稿 -> 待审批 -> 待出库扣减 -> 加工中(在产) -> 成品待入库 -> 已完成`。
- [ ] **AC-07（质押状态继承）**: 抵质押存货转换完成后，产出的新货物必须自动挂载至原质押单下，继承原质押单的监控属性与风控标记。
- [ ] **AC-08（防并发锁定）**: 转换单进入“待审批”及“加工中”状态时，对应的原料库存必须在物理/系统层面锁定，禁止发起重复解押或二次转换。

### 非功能性需求 (NFR)

| 维度 | 要求 | 备注 |
| :--- | :--- | :--- |
| **性能** | 行情联动计价与跌价试算响应时间 < 1.5秒 | 基于实时行情接口缓存与内存计算 |
| **强一致性** | 原料扣减、成品挂载与质押单货值更新具备数据库事务原子性 | 严禁出现“原料已扣但质押物未生成”数据不一致 |
| **全路径审计** | 转换单提交、风控执意提交警告、审批流节点留痕 100% | 记录操作人、IP、时间戳、试算快照镜像 |
| **并发锁控制** | 存货转换状态锁粒度为 SKU + 批次号/质押单号 | 防止高并发下的重复扣减或超卖 |

## 4. 建议方案 (Proposal)

### MVP方案 (最小可行产品)

**目标**: 以最低风控漏洞成本实现普通存货及抵质押存货的 1:N / N:1 / N:N 严密形态转换

**方案概述**:
- **前端转换单创建页**：支持按类型（普通存货 / 抵质押存货）检索原料，联动过滤“仓单中”货物，校验同源规则。
- **大宗行情计价引擎**：对接系统大宗商品基准价，自动计算产出物价值与比例分摊。
- **风控试算弹窗与高警报标记**：内置质押覆盖率试算逻辑，提供拦截提醒与执意提交的风险打标能力。
- **自定义审批流绑定**：对接现有工作流引擎（Flow Engine），在流程配置中可独立编排形态转换单审批流。
- **库存及质押单状态继承**：转换完成后，成品入库，自动写回原质押单明细表，更新质押单总货值。

**不做什么 (明确范围)**:
- ❌ **不支持仓单货物转换**：处于“仓单中”状态的货物一律不支持转换。
- ❌ **不支持跨质押单/普通与质押混合加工**：一期严禁混合配比，简化货权划分。
- ❌ **不支持人工任意手动篡改产出物单价**：产出物单价一律强制读取实时大宗商品行情基准价。

---

### 理想方案 (长期规划)

**适用场景**: 未来结合物联网（IoT）及智能工厂 BOM 自动核销场景

**扩展功能**:
- **BOM 配方库集成**：预设标准加工损耗率与 BOM 配方，创建转换单时自动按配方比例生成产出物与预估损耗。
- **IoT 视频/传感器在产监控**：联动仓库摄像头与 weight 传感器，自动感知加工出库与成品入库动作并拍照留痕。
- **混合质押份额按比例拆分**：支持普通存货与质押存货混合加工，按投入成本比例自动划分新产物的质押与自由份额。

## 5. 影响范围分析 (Impact Analysis)

### 上游影响
- **基础库存模块**: 需要在库存状态字段中明确区分 `普通`、`抵质押` 及 `仓单中`，并开放状态锁 API。
- **大宗行情服务**: 需要提供根据物料分类/规格实时查询基准行情价的高可用 API。

### 下游影响
- **质押单管理模块**: 需要新增“质押物形态转换变更”日志记录，并支持动态更新质押物清单及总货值。
- **风控预警引擎**: 需要接收转换单发出的【高风险告警】事件，更新风险仪表盘与警戒线指标。
- **自定义审批流程引擎**: 需要新增【形态转换单】这一业务对象及对应的表单字段上下文。

### 风险提示
- ⚠️ **货权法律风险**: 若未严格阻断“仓单中”货物，可能引发与仓储企业或电子仓单交易所的司法纠纷。
- ⚠️ **行情价格波动风险**: 大宗商品市场行情若出现剧烈波动，会导致转换试算价值与实际变现价值偏差，需设定行情刷新频次阈值。

## 💡 专家建议 (PM Insights)

> 1. **严守“同源投料与禁仓单转换”两条红线**：一期坚定拒绝混合加工与仓单转换，能为系统省去 70% 复杂的货权法律纠纷与份额拆分逻辑，保证核心质押物监管的绝对穿透与合规。
> 2. **行情基准价的强制性是防范道德风险的关键**：产出物价值由大宗市场行情接口自动计算，杜绝了企业或仓库人工高估产出物货值来虚增质押覆盖率的作假空间。
> 3. **高警报打标机制形成风控闭环**：允许用户强行提交（避免卡死紧急生产线），但通过打上【高风险告警】将决策压力显性化转移至风控与资方审批环节，做到了“灵活经营与严密风控”两不误。
