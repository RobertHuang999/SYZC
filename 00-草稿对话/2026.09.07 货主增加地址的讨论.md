# 货主增加地址的讨论记录

> **文档属性**：内部讨论稿，非正式 PRD，暂不作为开发与验收基准
>
> **讨论日期**：2026-09-07
>
> **讨论主题**：货主增加个人身份证登记地址和企业营业执照登记地址，并校验个人地址唯一性
>
> **核心目标**：个人货主维护身份证登记地址，企业货主维护营业执照登记地址；同一项目/租户内，一个家庭地址只能对应一个个人货主身份证号，地址同时用于后续开票主体识别。

---

## 一、已确认的业务结论

### 1. 地址规则与地址来源

1. 校验范围为同一项目/租户，不跨项目/租户比较。
2. 校验对象为个人合作方的“货主”角色，不是所有个人合作方。
3. 同一项目/租户内，个人货主的 `registered_address`（登记地址）只能绑定一个个人身份证号。
4. 地址相同但身份证号不同，禁止新增或绑定为个人货主。
5. 个人货主修改身份证登记地址时，执行同样的唯一性校验。
6. 同一个人可以多次入库，不是“一地址只能有一条入库记录”。
7. 个人货主的 `registered_address` 来源为身份证登记地址，用于本次个人地址唯一校验。
8. 企业货主的 `registered_address` 来源为营业执照登记地址，地址应以企业营业执照或企业认证资料为准。
9. 企业 `registered_address` 不参与本次“一个地址只能绑定一个个人身份证号”的校验。
10. 地址冲突时使用提示：`已有相同身份证地址，不能重复入库`。

### 2. 地址字段统一建议

个人和企业合作方统一使用同一个业务字段，避免字段清单、接口和主数据出现两套名称：

| 字段编码 | 中文名称 | 个人主体 | 企业主体 |
|---|---|---|---|
| `registered_address` | 登记地址 | 身份证登记地址 | 营业执照登记地址 |

- 页面统一展示“登记地址”，根据主体类型显示辅助说明：个人“来源：身份证”，企业“来源：营业执照”。
- 建议增加系统属性 `registered_address_source`，取值为 `ID_CARD` / `BUSINESS_LICENSE`，用于记录地址证明来源；该属性不是第二个地址字段，也不作为用户单独填写的地址。
- 地址唯一校验使用系统生成的标准化比较值，不新增第二个用户填写地址字段；唯一范围仍为同一项目/租户内的个人货主。

### 3. 客户管理与合作方管理边界

当前业务口径为：

- **客户管理**：管理 C 端注册产生的客户用户及个人/企业认证信息，客户主要作为货主使用。
- **合作方管理**：管理系统业务侧统一的个人/企业主体及其业务角色。
- **入库、出库、转让、仓单等业务**：不再各自维护一套货主或人员主数据，统一引用合作方主体。

客户账号与业务主体不是同一个概念。个人 C 端客户通常绑定个人合作方并默认拥有“货主”角色；企业 C 端客户绑定企业合作方，注册账号本人属于联系人或操作人，不应直接替代企业主体。

### 4. 地址维护位置

统一字段 `registered_address`（登记地址）属于合作方主档，不属于入库单临时字段。

- 新增或补全个人货主时，在合作方管理中录入登记地址，来源标记为身份证。
- 新增或补全企业货主时，在合作方管理中维护登记地址，来源标记为营业执照，原则上与企业认证资料保持一致。
- 入库页面选择已有货主后，只读带出统一的登记地址；页面根据主体类型显示地址来源说明。
- 登记地址的修改均在合作方管理中完成；个人货主修改时必须执行本次唯一校验。
- 后续开票使用合作方对应的登记地址；历史单据或发票需要保存业务发生时的地址快照。

## 二、当前系统与草稿现状

### 1. 当前入库流程

当前入库记录新增页已经有个人货主、身份证号和新货主认证流程，但没有个人身份证登记地址或企业营业执照登记地址入口。

```text
选择企业/个人货主
        |
        v
个人货主填写或带出身份证号
        |
        v
货品、库位、照片等入库校验
        |
        v
新货主短信二元认证（如适用）
        |
        v
生成入库申请并进入审批
        |
        v
审批通过后写入库存和货权档案
```

现有规则中，个人货主身份证号在入库新增页条件必填，新货主在提交时会沉淀到货主档案，见[入库记录业务规则规格](../02-PRD文档/🌟🌟🌟-最新基准版/B端PC/02-仓储/09-入库管理-入库记录/入库记录业务规则规格.md:96)和[入库记录字段清单](../02-PRD文档/🌟🌟🌟-最新基准版/B端PC/02-仓储/09-入库管理-入库记录/入库记录字段清单.md:38)。

### 2. 客户管理现状

现有“交易 → 客户管理”主要展示 C 端客户账号、个人认证、企业认证和注册时间，不是统一业务角色主档，见[客户管理页面知识](../09-知识宝典/04-交易/04-交易-客户管理.md:8)。

### 3. 合作方草稿现状

[合作方管理需求](./合作方管理需求.md)已经提出：

- 以个人身份证号或企业统一社会信用代码识别主体；
- 货主、提货人、接收方、仓单存货人、仓单持有人等角色统一管理；
- 已有主体自动追加角色，业务单据可以静默沉淀合作方。

但[合作方管理设计方案](./合作方管理设计方案.md:49)当前仍以企业机构为主要模型，`creditCode` 为必填，个人主体字段和个人业务角色尚未完整展开。本需求需要在此基础上补充个人主体模型。

## 三、统一合作方业务模型

```text
+--------------------------------------------------------------------------------+
| 合作方主体                                                                    |
+--------------------------------------------------------------------------------+
| 主体类型: 个人 / 企业                                                         |
| 内部主体ID: partner_id                                                        |
|                                                                                |
| 个人主体: 姓名、身份证号、登记地址（来源：身份证）、手机号                   |
| 企业主体: 企业名称、统一社会信用代码、登记地址（来源：营业执照）、联系人、联系电话 |
|                                                                                |
| 业务角色: 货主 / 提货人 / 接收方 / 仓单存货人 / 仓单持有人 / 其他               |
| 创建来源: C端注册 / 人工建档 / 入库单沉淀 / 出库单沉淀 / 转让单沉淀              |
| 主体状态: 正常 / 冻结 / 注销                                                   |
+--------------------------------------------------------------------------------+
```

地址唯一关系只作用于以下集合：

```text
同一项目/租户
    |
    +-- 有效的个人合作方
          |
          +-- 已拥有“货主”角色
                |
                +-- 登记地址（registered_address） -> 身份证号（一对一）
```

提货人、接收方等其他角色可以与货主登记地址相同；只有其被新增或绑定“货主”角色时，才执行个人地址唯一校验。

企业主体的 `registered_address` 来源为营业执照，不适用本次个人地址一对一规则。企业地址是否需要建立独立的重复校验规则，不纳入本次需求。

## 四、业务流程影响

### 1. C 端客户注册与认证流程

```text
C端注册用户
    |
    v
个人/企业认证
    |
    +-- 个人客户
    |      |
    |      v
    |   创建/绑定个人合作方
    |      |
    |      v
    |   默认增加“货主”角色
    |      |
    |      v
    |   补充登记地址（来源：身份证）
    |      |
    |      v
    |   地址唯一校验（开关开启时）
    |
    +-- 企业客户
           |
           v
        创建/绑定企业合作方
           |
           v
        同步/补充登记地址（来源：营业执照）
           |
           v
        默认增加“货主”角色
```

### 2. 合作方新增/编辑流程

```text
进入合作方管理
    |
    v
选择主体类型
    |
    +-- 个人：录入身份证号
    |      |
    |      +-- 身份证号已存在：复用主体，禁止重复建档
    |      |
    |      +-- 身份证号不存在：录入登记地址（来源：身份证）
    |             |
    |             +-- 地址已绑定其他身份证号：禁止增加“货主”角色
    |             |
    |             +-- 地址未绑定：创建主体并增加“货主”角色
    |
    +-- 企业：录入统一社会信用代码和登记地址（来源：营业执照）
           |
           v
        已存在则复用主体并核对登记地址，不重复建档
```

个人货主修改地址：

```text
合作方详情 → 编辑登记地址（个人/身份证）
    |
    v
标准化新地址
    |
    v
查询同一项目/租户内其他有效个人货主
    |
    +-- 命中其他身份证号：阻止保存
    |
    +-- 未命中或仅命中当前主体：保存并记录变更日志
```

企业货主修改地址：

```text
合作方详情 → 编辑登记地址（企业/营业执照）
    |
    v
根据企业认证资料/营业执照核对新地址
    |
    v
保存并记录地址变更日志
```

### 3. 入库流程

```text
仓储 → 入库管理 → 入库记录 → 新增入库
    |
    v
选择货主类型
    |
    v
选择已有合作方货主
    |
    +-- 已有个人货主：带出身份证号和登记地址（来源：身份证），只读
    |
    +-- 已有企业货主：带出统一社会信用代码和登记地址（来源：营业执照），只读
    |
    +-- 没有合作方：进入“新增合作方”流程
           |
           v
        按主体类型录入身份证号/登记地址（来源：身份证），或统一社会信用代码/登记地址（来源：营业执照）
           |
           v
        个人货主执行身份证地址重复校验，企业货主不执行本次地址唯一校验
           |
           +-- 冲突：提示“已有相同身份证地址，不能重复入库”
           |
           +-- 通过：继续货品、库位、附件和审批校验
                          |
                          v
                     生成入库申请
                          |
                          v
                     进入入库审批
```

地址冲突时不应：

- 创建新的个人合作方；
- 增加“货主”角色；
- 创建入库申请；
- 进入审批中心；
- 发送新货主短信认证。

### 4. 其他业务角色流程

```text
出库/提货/转让/仓单/加工业务
    |
    v
按身份证号或统一社会信用代码查询合作方
    |
    +-- 已存在：复用主体，追加业务角色
    |
    +-- 不存在：按当前业务规则沉淀简易合作方
    |
    +-- 新增“货主”角色：执行身份证地址唯一校验
    |
    +-- 仅新增“提货人/接收方”等角色：不执行货主地址唯一校验
```

退货、移库、加工产出等同一货主的系统联动入库，应直接复用原合作方，不得因为地址已经存在而阻断正常内部流转。

H5 端暂不新增独立“合作方管理”菜单。H5 的客户入库预约、出库、转让等页面调用统一合作方选择和创建能力；如果后续要求移动端直接维护合作方，再另行增加 H5 菜单。

### 2. 菜单职责边界

```text
配置管理 → 平台管理 → 角色管理
    └─ 管理 B 端登录账户可使用哪些系统菜单、按钮和数据权限

合作方管理 → 合作方档案
    └─ 管理业务主体及业务角色：个人/企业、货主、提货人、接收方等

交易 → 客户管理
    └─ 管理 C 端注册账户、认证状态，以及客户账户与合作方主体的绑定关系
```

合作方的“货主/提货人/接收方”等属于业务角色，不属于系统登录权限角色。`角色管理`可以配置哪些系统用户有权访问“合作方管理”，但不负责维护合作方的业务角色。

### 3. 菜单影响明细

| 菜单 | 增删改 | 主要调整内容 |
|---|---|---|
| `合作方管理 → 合作方档案` | 新增 | 合作方列表、主体新增/编辑、业务角色维护、冻结/解冻/注销、详情、操作日志 |
| `配置管理 → 平台管理 → 基础配置` | 修改 | 增加“个人货主身份证地址重复校验”开关，范围为项目/租户 |

| `交易 → 客户管理` | 修改 | 增加客户账号与合作方主体的绑定和查看入口，继续保留 C 端账号管理职责 |
| `工作中心 → 审批中心 → 客户需求审批 → 客户入库预约` | 修改 | 货主改为引用合作方，地址冲突在提交/生成申请前拦截 |
| `仓储 → 入库管理 → 入库记录` | 修改 | 货主选择器引用合作方，新增合作方时进入统一建档，提交时执行校验 |
| `仓储 → 出库管理 → 出库记录` | 修改 | 货主、提货人引用合作方；提货人不触发货主地址规则 |
| `仓储 → 提货单` | 修改 | 提货人引用合作方，支持按身份证号/手机号检索 |
| `仓储 → 货物转让 → 转让记录` | 修改 | 转让接收方引用合作方；新增货主角色时执行地址校验 |
| `仓储 → 仓单管理` | 修改 | 存货人、持有人引用合作方 |
| `仓储 → 加工管理 → 加工记录` | 修改 | 货主引用合作方，系统生成产出入库时复用主体 |
| `仓储 → 货权管理 → 货权档案` | 修改 | 货主/持有人显示合作方主体并支持跳转详情 |
| `结算 → 监管结算` | 后续修改 | 开票时引用合作方地址，历史凭证保存地址快照 |

### 3. 删除或取消的内容

```text
不删除现有核心菜单：
- 交易 → 客户管理
- 仓储 → 入库管理 → 入库记录
- 客户入库预约
- 出库、提货、转让、仓单、加工等业务菜单

取消重复入口和重复逻辑：
- 各业务单据内独立维护 `registered_address` 登记地址
- 各业务模块各自维护货主/人员主数据
- 各业务模块各自实现主体重复校验
- 单独新增“身份证地址校验”菜单
- 单独新增“地址冲突审批”流程
```

## 七、权限与审计影响

合作方管理至少需要以下权限动作：

| 权限动作 | 建议角色 |
|---|---|
| 查看合作方列表/详情 | 平台管理员、业务运营、风控人员，按项目/租户隔离 |
| 新增合作方 | 平台管理员、业务运营 |
| 编辑登记地址 | 平台管理员、授权业务运营；按主体类型核对身份证/营业执照资料，并记录原因 |
| 追加/移除业务角色 | 平台管理员、授权业务运营 |
| 冻结/解冻 | 风控人员、平台管理员 |
| 注销合作方 | 平台管理员；需校验无存量业务约束 |
| 修改地址唯一校验开关 | 平台管理员或项目管理员 |

身份证号和个人来源的 `registered_address` 属于敏感个人信息；企业来源的 `registered_address` 属于企业主体资料：

- 列表只展示脱敏值或地址状态；
- 冲突提示不展示已存在主体的姓名、身份证号或完整地址；
- 业务单据保存合作方 ID，并按需要保存加密地址快照；
- 新增、修改、冲突拦截、角色变更、冻结解冻和开关变更均写入审计日志。

## 八、内部讨论待确认事项

以下事项尚未作为最终开发口径：

1. “项目/租户”在系统数据模型中是否为同一个唯一性作用域，最终使用 `project_id` 还是 `tenant_id`。
2. 个人 C 端注册时是否必须立即填写身份证登记地址，还是在首次成为货主时补录。
3. 历史个人货主没有地址时，开启开关后是否要求在下一次使用时补录。
4. 开关关闭期间产生的地址重复数据，重新开启前是否必须先清理。建议开启前检查，存在冲突则禁止启用。
5. 个人货主地址是否允许自助修改，还是只能由后台授权人员修改。
6. 地址标准化的具体规则：省市区、道路、门牌号、空格、标点和常见简称如何统一。
7. 货主角色被注销或移除后，原地址是否释放给新的个人货主使用；历史入库和发票地址是否永久保留。
8. 转让接收方后续成为货主时，地址校验是在转让环节完成，还是在后续入库环节完成。建议在新增“货主”角色时完成。
9. 是否允许内部授权的异常处理流程。当前建议不设置业务绕过按钮，确需处理时通过合作方档案数据治理完成。
10. 企业营业执照登记地址是在企业认证时自动同步，还是允许合作方管理后台手动录入；地址变更是否需要重新提交企业认证。
