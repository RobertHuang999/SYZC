# 03-移动端详情页与时间线规范

---

## 🏛️ 1. 扁平化二层结构（杜绝卡片套娃）

在移动端详情页中，**严格禁止使用超过 2 层的卡片内嵌套（严禁：单据 -> 仓单 -> 货物 -> 批次 -> 属性 这种 5 层展开套娃）**。

### 标准扁平化二层架构：
1. **第 1 层：主资产汇总卡片 (Summary Card)**
   - 展示资产总件数/吨数、核定总货值、质押状态进度分布（例如：`共 1,200吨：800吨质押中 / 400吨自由`）。
2. **第 2 层：批次与货位明细表格 (Detail Table / Drawer)**
   - 点击汇总卡片直接展开平铺明细列表，包含“批次号、库位、入库时间、单价”，不再在明细内嵌套折叠卡片。

---

## 🔄 2. 关键业务流向链路式表达 (Traceability & Flow)

涉及物权变更或物理空间位移的业务场景，必须以直观的**链路式箭头 (➔)** 进行表达：

### 2.1 移库场景 (源 ➔ 目标)
* ❌ **反面设计**：仅展示出库货位，完全看不到目标新货位，表头还写成“出库数量”。
* ✅ **标准规范**：
  ```text
  📦 热轧卷板 Q235B (批次: RZ-0825-01 · 450 吨)
  └─ [源货位] 宝山立体库 A区-03 垛位  ➔  [目标新货位] 宝山立体库 B区-11 垛位
  ```

### 2.2 货物加工转化 (原料 ➔ 产成品)
* ❌ **反面设计**：上下放两个孤立的蓝灰文本框，看不出物料守恒与出成率。
* ✅ **标准规范**：
  ```text
  【投入原料】苹果-优质 100公斤 ➔ ⚙️加工转化 (出成率 92%) ➔ 【产出成品】12粒装(100盒) + 24粒装(50盒)
  ```

### 2.3 货权转让 (出让方 ➔ 受让方)
* ❌ **反面设计**：上下两行简单罗列人名，缺乏流向指示。
* ✅ **标准规范**：
  ```text
  [出让方] 江苏宏达贸易 (王全)  ════ 货权过户 ════➔  [受让方] 无锡锡通科技 (李四)
  ```

## 🧱 3. 多子板块块状详情（台账类）

与 PC 详情 **语义分块一致**，在移动端用**扁平板块**表达，仍遵守本章第 1 节「最多 2 层结构」。

### 3.1 板块结构

```text
┌──────────────────────────────────────┐
│ 板块标题（15～16px 加粗）              │
├──────────────────────────────────────┤
│ 字段名（12px 灰色）                    │
│ 字段值（14px 主色）                    │
│ … 块内可双列 Key-Value 网格 …          │
└──────────────────────────────────────┘
     ↓ 板块间距 12px
┌ 下一板块 … ──────────────────────────┐
```

1. **板块划分**：基本信息 / 业务事实 / 附件凭证 / 处置材料 / 操作记录（按 PRD 裁剪，无数据不渲染块）。
2. **字段排布**：默认 **字段名在上、内容在下**；块内指标类可 **双列 Key-Value**（见列表规范 Body 区），禁止再套第三层 Card。
3. **顶栏摘要**：NavBar 下可选一条摘要条（单号 + 状态 Tag），Detail 板块内不重复主标题。
4. **通栏内容**：表格型明细、图片九宫格、地图/链路图占满板块宽度，不拆成多个小 Card。

## ⏱️ 4. 轻量化时间轴与审批流规范 (Timeline)

### 4.1 节点合并原则
* ❌ **反面设计**：将“发起申请”和“审核通过”拆成 2 个独立大卡片，一次简单审批撑满一整屏；节点名称出现系统开发变量名（如 `任务名称xxx:`）。
* ✅ **标准规范**：
  - **单节点聚合**：将“申请发起人 + 审批结论 + 审核意见 + 处理用时”合并在同一个时间线节点卡片内；
  - **状态徽标清晰**：`[已通过]`（绿色）、`[已驳回]`（红色）、`[待处理]`（橙色）、`[抄送知会]`（蓝色）。

---

## 🛡️ 5. 存证与空字段处理规范

1. **存证信息上提或抽屉化**：
   - 中仓登全国统一编码、区块链哈希等权属存证凭证，统一以徽标形式展示在页面头部或单号下方（如：`中仓登记码: CWRR... [复制]`），点击直接唤起区块链存证溯源报告抽屉，严禁横插在 Tab 与明细中间阻断浏览。
2. **空数据条件渲染 (Conditional Rendering)**：
   - 当字段无有效值（如授信金额全为 `--`、注销时间未到期）时，**直接不渲染该字段**，严禁使用多个 `--` 宫格强行占位。
