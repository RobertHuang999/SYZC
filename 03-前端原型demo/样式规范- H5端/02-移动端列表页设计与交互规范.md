# 02-移动端列表页设计与交互规范

---

## 📋 1. 列表卡片标准结构（三段式布局）

移动端列表卡片必须统一采用 **“卡片头部 (Header) + 核心指标 (Body) + 经办与操作 (Footer)”** 的标准化三段式结构：

```
┌────────────────────────────────────────────────────────┐
│ [类型Icon] 单据编号 / 业务主体名称         [状态Tag]    │ ➔ 头部 (Header)
├────────────────────────────────────────────────────────┤
│  ┌──────────────────────────────────────────────────┐  │
│  │ 货物/规格: 热轧卷板 Q235B (3.5*1500*C)           │  │ ➔ 主体 (Body)
│  │ 在库吨数: 1,250.00 吨     核定货值: ¥4,875,000  │  │   双列 Key-Value
│  │ 存储位置: 宝山1号智能立体仓 A区-03垛位           │  │   浅灰底背景块
│  └──────────────────────────────────────────────────┘  │
├────────────────────────────────────────────────────────┤
│ 制单人: 张三 · 2026-08-25 10:30        [查看详情] [···]│ ➔ 底部 (Footer)
└────────────────────────────────────────────────────────┘
```

## ⚠️ 2. 常见反面设计与优化对照

### 2.1 痛点 1：“更多操作”直接在卡片内平铺展开
* ❌ **反面设计**：点击卡片底部的“更多操作”，卡片内部直接展开 6 个操作方块（仓单入库、仓单补货、仓单出库、移库等），卡片高度瞬间翻倍，页面剧烈跳动，一屏仅能看 1 条数据。
* ✅ **标准优化**：卡片右下角仅保留 1 个高频主按钮（如“查看详情”或“去审批”），其余次要操作通过“··· 更多”唤起**底部 ActionSheet 抽屉面板**，卡片高度保持恒定紧凑。

### 2.2 痛点 2：“详细”文字链接泛滥
* ❌ **反面设计**：货物名称右侧放蓝色“详细”、数量右侧又放“详细”、仓库又放图标，整张卡片到处是微小的可点击文字，单手操作误触率极高。
* ✅ **标准优化**：彻底移除字段内嵌的“详细”文字，点击卡片任意非按钮区域统一进入详情页。

### 2.3 痛点 3：不可读 UUID 占据卡片首行
* ❌ **反面设计**：设备列表将长串不可读哈希 `aed2b40126ba4a9dbd58536fc4b4878b` 放在卡片首行。
* ✅ **标准优化**：卡片主标题必须展示**业务可识别名称**（如：`宝山1号仓-AI球机008#`），技术 ID 收敛至详情页或副标题。

### 2.4 痛点 4：高危操作（删除）在列表右上角裸露
* ❌ **反面设计**：卡片右上角直接放置“删除（垃圾桶）”图标，单手滑动时极易误触直接删除监管硬件。
* ✅ **标准优化**：列表卡片右上角**严禁放置危险操作图标**；删除、注销、平仓等敏感操作必须进入详情页或通过二次密码/弹窗确认。

## 🔍 3. 顶部筛选与搜索降噪规范

1. **组合式紧凑搜索栏**：
   - 顶部搜索框占位符明确指引（如：`输入单号 / 货主 / 货物规格`）；
   - 右侧常驻 `筛选 (Filter)` 按钮，点击唤起右侧抽屉式高级筛选（支持时间段、仓库多选、金额范围等）。
2. **状态分段选择器 (Segmented Control)**：
   - 高频状态（全部、待处理、正常、预警中）以横向滚动胶囊或分段器呈现，高度控制在 36px 以内；
   - 严禁“多层 Tab + 多层下拉”层叠堆砌占用超过 1/3 屏幕高度。
