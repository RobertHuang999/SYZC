# 原型双端标注对齐说明（PC / H5）

> **全局真源**：仓库根目录 [`AGENTS.md`](../AGENTS.md) **4.2.1 节**。  
> **业务真源**：各菜单三件套（主 PRD / 字段清单 / 业务规则规格）；标注不得另立业务规则。

---

## 1. 为什么要对齐

同一菜单在 PC 与 H5 上 **状态机、字段、权限、规则 ID 必须一致**。若 H5 单独写一套 annotation 文案，评审时会出现「双端说法两套、编号对不上」——违反 **AGENTS.md 4.0 三件套 SSOT**。

---

## 2. 硬性规则（AI / 人写标注前先读）

| # | 规则 | 说明 |
| :---: | :--- | :--- |
| 1 | **共享正文真源** | 列表 / 详情 / 表单等业务块标注，写在 `03-前端原型demo/shared/{模块}/annotations/*.annotations.shared.ts`（或同等路径）；**PC 只 re-export，禁止在 PC 独占文件里改业务正文**。 |
| 2 | **同 id · 同 number · 同 title · 同 details** | H5 与 PC 使用 **相同** `id`、`number`、`title`、`details`（含 Mermaid、字段表）；侧边检查器按序号应对得上。 |
| 3 | **H5 只允许两处差异** | ① `targetId`（DOM 挂载点不同）；② `content` 末尾追加 **一条**以 `【H5 端差异】` 开头的短句（入口、控件形态、Sheet/Dialog、底栏 vs 页头等）。**禁止**重写业务规则或另起编号。 |
| 4 | **bindings 文件** | H5 工程内 `{feature}/annotations/*-h5.annotation-bindings.ts` 只放 `targetId` / `contentSuffix` 映射；正文用 `applyH5PrototypeAnnotationBindings()`（`shared/annotations/prototype-annotation.shared-types.ts`）生成。 |
| 5 | **三件套挂载** | 双端 `documents/*.ts` 指向 **同一份** PRD / 字段清单 / 规则 Markdown；H5 不得挂精简版规则。 |
| 6 | **卡片首屏摘要** | 共享 `content` 保持 1～2 句说人话；深度材料放 `details` 展开。端差异句不计入「第二套正文」。 |

---

## 3. 目录与文件约定（标杆：合作方档案）

```
03-前端原型demo/
├── shared/
│   ├── annotations/
│   │   └── prototype-annotation.shared-types.ts   # 类型 + applyH5PrototypeAnnotationBindings
│   └── partner-archives/annotations/
│       ├── partner-archive-list.annotations.shared.ts
│       ├── partner-archive-detail.annotations.shared.ts
│       └── partner-archive-form.annotations.shared.ts
├── B端PC/src/features/partner-archives/annotations/
│   └── *.annotations.ts                           # re-export shared
└── B端H5/src/features/partner-archives/annotations/
    ├── partner-archive-h5.annotations.ts          # apply bindings → 导出三组数组
    └── partner-archive-h5.annotation-bindings.ts
```

新菜单落地双端时：**先写 shared → PC re-export → H5 bindings + 页面 targetId 与 PC 同 id 挂载**。

---

## 4. 自检清单

- [ ] PC / H5 同一页面的 annotation **id 集合一致**（允许 H5 某靶点因布局合并而少挂载，但 **不得少 id 定义**；未挂载的 id 应补 DOM 或合并到等价区块并注释）。
- [ ] H5 每条有端差的 `content` 均含且仅含一段 `【H5 端差异】…`。
- [ ] 未在 H5 单独维护与 PC 矛盾的「业务结论句」。
- [ ] 字段清单 / 主 PRD 中 **8.x H5** 节与 bindings 中的端差异一致。

---

## 5. 与页面布局的关系

布局差异见 [`原型页面布局速查.md`](./原型页面布局速查.md) 与样式规范 H5/PC 章节；**布局写在页面结构与 bindings，业务写在 shared**。
