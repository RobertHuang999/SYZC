# 06-PC 端表格行与操作列规范

> 本章专门管表格的「一行里面怎么排」：**内容区**每一列放什么、怎么对齐、多行怎么排；**操作区**放哪、多宽、按钮怎么摆。
> 颜色、表头高度、固定列底色见 [05-色彩、字体与表格视觉规范](./05-PC端色彩与表格视觉规范.md) 第 4 节。

---

## 0. 先搞清楚：这一列是哪个字段

列表里的业务列**不是设计时随手定的**，每一列都必须能在该菜单的《字段清单》里找到出处。

| 列的来源 | 依据 | 例子（入库记录） |
| :--- | :--- | :--- |
| **业务列** | 字段清单里「**列表展示 = 是**」的字段 | 入库单号、货主名称/标识、入库类型、入库日期、仓库名称、关联单号、货品名称、入库数量、制单人 |
| **筛选项** | 字段清单「筛选控件与匹配」列 | 入库单号（输入）、货主名称（输入）、入库类型（下拉）、仓库（级联） |
| **系统列** | 不由字段清单定义，由规范统一 | 序号、复选（批量选择）、操作 |
| **派生展示** | 字段清单「取值说明 / 备注」规定的格式 | 时间两行、数量千分位 + 单位、状态标签、单号可复制 |

三条硬规矩：

1. **名称、枚举、单位、精度与字段清单一致**；字段清单改了口径，列表跟着改。
2. 字段清单里「列表展示 = 否」的字段**不得上列表**（例如货品标识只在详情展示）。
3. 想加一个字段清单里没有的列 → **先补字段清单，再改原型**，不允许原型先斩后奏。

> 依据：`AGENTS.md` 4.0「三件套分层」——字段清单是字段的唯一定义真源；主 PRD 只写页面骨架与交互，字段细节引用字段清单，不自行发明。

## 1. 一行由三段组成

```text
┌──────┬──────┬───────────────────────── 数据列 … ─────────┬────────────────┐
│ 复选  │ 序号  │ 单号 / 主体 / 类型 / 时间 / 数量 / 状态 …   │ 操作（固定右侧） │
│ 48px │ 64px │  按内容类型给宽度                            │ 80～220px      │
└──────┴──────┴────────────────────────────────────────────┴────────────────┘
   ↑ 左固定                                ↑ 可横向滚动        ↑ 右固定
```

- **左侧固定**：复选列、序号列，横向滚动时不跟着走。
- **中间数据列**：按第 3 节的列宽目录分配，列多时整表横向滚动。
- **右侧固定**：操作列，永远贴在右边，底色不透明（见第 5 节）。

## 2. 行的基本参数

| 项 | 实际值 | 说明 |
| :--- | :--- | :--- |
| 行高 | **标准 `72px`** / 紧凑 `44px` | 标准档用于台账与主数据（支持 1～3 行内容）；紧凑档只用于单行短值的流水表；**同一张表内所有行等高**，不随内容忽高忽低 |
| 单元格内边距 | 上下 `0`、左右 `16px` | 由 `.page-surface` 统一给，页面里写 `py-2.5` 不生效 |
| 单元格字号 | `13px` | 页面里写 `text-sm`（14px）不生效 |
| 单元格文字色 | `#4e5969` | 需要强调时在内容里单独加 `text-foreground` |
| 行分隔线 | `#f2f3f5` | |
| 悬停底色 | `#f7faff` | |
| 斑马纹 | **不用** | 行多时靠分隔线和悬停区分 |
| 行内边距/描边 | 行不加圆角、不加边框 | 圆角只在外层容器上 |

### 2.1 固定行高怎么用（省宽度的前提）

「固定行高 + 格内换行」是一套组合拳：**行高固定，内容在格子里换行，列宽就不用为了放下长内容而撑大**。

| 规则 | 说明 |
| :--- | :--- |
| 行高 | 台账类统一 `h-[72px]`；行的实际高度 = 72px，不因某行内容少而变矮 |
| 格内行数 | 标准档最多 **3 行**：1 行主信息（14px）+ 2 行次要信息（12px）；超过 3 行省略并给 `title` |
| 典型容量 | 人员+组织+日期+时间（3 行）✓；19 位单号折 2 行 ✓；主体名 + 标识（2 行）✓ |
| 操作列 | 4 个操作排 2×2 时，按钮统一 28px 高、面板总高 68px，仍在 72px 内（`index.css` 已有覆盖规则） |
| 不达标的表现 | 行高忽高忽低（有的 44、有的 77）、操作列把行撑到 80+、格内第 4 行被硬塞 —— 都算不合格 |

> **现状**：入库记录列表已按 72px 落地；其余老表仍是 44px 内容自适应。改到哪张表，就把哪张表换成 72px，不做专项返工。

### 2.2 行状态

| 状态 | 表现 |
| :--- | :--- |
| 默认 | 白底 |
| 悬停 | `#f7faff` 底，鼠标变手型（可点击的行） |
| 勾选 | **浅主色底**（`bg-blue-50/60`）+ 复选框选中；**当前工程尚未实现行高亮**，只勾了复选框，属于待补项 |
| 禁用 / 不可操作 | 文字用次要灰，操作的禁用项置灰并在 `title` 里写原因 |

> 没有「选中行」的底色反馈时，用户只能靠复选框判断选没选，批量操作容易出错，新页面请补上。

## 3. 内容区：一列只干一件事

### 3.1 列宽目录（照抄，不要随手给宽度）

| 列类型 | 建议宽度 | 对齐 |
| :--- | :--- | :--- |
| 复选列 | `48px` | 居中 |
| 序号列 | `64px` | 居中 |
| 业务单号 | `150px`（19 位两行折行）；16 位以内单行时可给 `200px` | 左 |
| 主体名（货主 / 客户 / 供应商） | `210px` | 左 |
| 类型 / 分类 | `100px` | 左 |
| 日期 | `110px` | 左 |
| 时间（含秒） | `130px`～`160px` | 左 |
| 仓库 / 库房 | `150px` | 左 |
| 关联单号 | `130px`（长单号两行折行） | 左 |
| 货品名称 | `180px` | 左 |
| 数量 / 重量 | `100px`～`120px` | **右** |
| 金额 | `120px`～`140px` | **右** |
| 制单人（人 + 时间两行） | `140px` | 左 |
| 状态 | `110px` | 居中 |
| 开关 | `80px` | 居中 |
| 图片 / 缩略图 | `64px`～`80px` | 居中 |
| 操作 | 见第 5.2 节 | 居中 |

- 次要列（如「关联单号」）可以在窄屏隐藏：`hidden xl:table-cell`，但**不能**把关键列（单号、主体、状态、操作）隐藏掉。

| 入库类型 | 100 | 入库数量 | 100 |

| | | **操作**（2×2，4 个按钮） | 142 |

**设备预警列表（12 列，整表最小宽 1180px）**

| 列 | 宽 | 列 | 宽 |
| :--- | :--- | :--- | :--- |
| 复选 | 48 | 现场照片 | 64 |
| 序号 | 64 | 预警抓拍 | 64 |

### 3.2 单元格内容类型目录

| 类型 | 怎么排 | 示例 |
| :--- | :--- | :--- |
| **单行文本** | 单行省略 + `title` 显示全文；不要撑高整行 | 仓库名称、货品名称 |
| **主体 + 标识（两行）** | 上：名称 `14px` 中等字重；下：标识 `12px` 次要灰、等宽数字；两行都单行省略 | 森云科技有限公司 / `91xxxxxx` |
| **业务单号** | 完整显示、**不出现省略号**；17 位以上超长单号允许**折成 2 行**（`break-all`），列宽 `130px`～`150px`；主色可点；**悬停出现复制按钮**，复制后 1.5 秒显示「✓」 | `2026101015300000123`（两行） |
| **日期 / 时间** | **表格内一律两行**：日期一行、时分秒一行（用 `stackedPlain`），两行都是正文字体；详情页字段、弹窗里的小表格可用单行（`plain`） | `2026-06-03` / `10:15:00` |
| **人 + 时间** | 两行：人名上行、时间下行；要带组织、要秒级时间时改用 `TablePersonOrgTimeCell`（三行，见 3.3 节） | 张三 / 2026-06-03 10:15 |
| **数量 / 金额** | 右对齐、中等字重、数字等宽；单位用小号次要灰紧跟在后 | `1,250.00 吨` |
| **状态** | 状态标签（浅底 + 描边 + 深字），颜色见 05 第 3.3 节；同状态全站同色 | `待处置` / `已结案` / `已作废` |
| **类型 / 分类** | 小号描边标签，不用彩色 | `普通入库` / `质押入库` |
| **开关** | 原生风格开关，居中 | 启用 / 停用 |
| **图片** | 小缩略图 + 数量角标，点击看大图 | 现场照片（3） |
| **长文本** | 省略号 + 悬停浮层看全文（`HoverOverflowText`），浮层最大宽 28rem | 预警内容、备注 |
| **空值** | 统一显示「—」（半角长横），次要灰 | — |

### 3.3 多行单元格：挤不下就拆行，不要平铺

一个格子里如果同时有**人员、组织、年月日、时分秒**，平铺出来是 20 多个字，列宽要撑到 280px 左右，别的列就被挤扁了。做法是把一格拆成**最多 3 行，每行只放一类信息**。

#### 3.3.1 什么时候必须拆

出现任意一条就拆：

1. 一格里的完整信息超过 12 个汉字；
2. 一格里有两类以上不同性质的信息（人 / 组织 / 时间）；
3. 同一类信息有主次两层（名称 + 编号、名称 + 标识）；
4. 估算内容宽度超过该列可用宽度（列宽减 32px 内边距）。

#### 3.3.2 四种标准模板（照着选）

| 模板 | 行数 | 每行放什么 | 字号 / 颜色 | 建议列宽 |
| :--- | :---: | :--- | :--- | :--- |
| **A · 主体两行** | 2 | ① 名称 ② 标识 / 编号 | ① `14px` 主文本 ② `12px` 次要灰 | `210px` |
| **B · 人 + 时间两行** | 2 | ① 人员 ② 日期时间 | ① `14px` 主文本 ② `12px` 次要灰 | `140px`～`160px` |
| **C · 人 + 组织 + 时间三行** | 3 | ① 人员 + 组织 ② 年月日 ③ 时分秒 | ① 人员 `14px`、组织 `12px` 灰（同一行）② ③ `12px` 次要灰 | `180px` |
| **D · 纯时间两行** | 2 | ① 年月日 ② 时分秒 | 两行都 `12px` 次要灰 | `110px`～`130px` |

**C 模板（你提到的场景）长这样：**

```text
┌────────────────────────────┐
│ 张三   森云科技             │ ← 人员 14px 主文本 + 组织 12px 次要灰
│ 2026-06-03                 │ ← 年月日 12px 次要灰、数字等宽
│ 10:15:00                   │ ← 时分秒 12px 次要灰、数字等宽
└────────────────────────────┘
            列宽 180px
```

> **组件**：`TablePersonOrgTimeCell`（`B端PC/src/shared/components/TableCells.tsx`）已实现 C 模板 —— 有组织且有时间时渲染三行（人员 + 组织 / 年月日 / 时分秒），无组织时自动退化为两行（人员 / 日期时间），每行独立省略、整格带 `title`。入库记录列表的「制单人」列已接入。

#### 3.3.3 拆行细则

1. **每行各自单行**：`whitespace-nowrap` + 超长省略；**不要**依赖单元格自动换行，否则行高会失控。
2. **行距 2px**（`flex flex-col gap-0.5`），行高 `leading-snug`。
3. **只有第 1 行可以用 `14px` 中等字重**；第 2、3 行统一 `12px` 次要灰 + 数字等宽（`tabular-nums`）。
4. **组织跟在人员后面同一行**，中间空 4～8px；超长时**省略组织**，人员名不省略。
5. **秒要么都给，要么都不给**：同一列里不能一半 `10:15`、一半 `10:15:00`。
6. **最多 3 行**：第 4 类信息换一列，或收进详情页。
7. 整个格子加 `title`（完整串），悬停能看到全量；长内容用 `HoverOverflowText`。
8. 日期 / 时分秒用 `splitDateTime`（`B端PC/src/features/inbound-records/lib/list-utils.ts`）拆，不要自己切字符串。

#### 3.3.4 什么时候不拆

- 列宽 ≥ `200px`、总字数 ≤ 14 个 → 可以单行（如「张三 · 森云科技」）。
- 只需要人、不需要组织与秒 → 用 B 模板两行，不要为了「统一」硬凑三行。

#### 3.3.5 禁止

| ❌ | ✅ |
| :--- | :--- |
| `张三 森云科技 2026-06-03 10:15:00` 平铺成一长串 | 按 C 模板拆三行 |
| 在格子里塞 `<br>` 或换行符 | 用 `flex-col` 分行，每行独立元素 |
| 三行都用 `14px`，看起来一样重 | 只有第 1 行主文本，其余次要灰 |
| 组织把人员名挤到省略号 | 省略组织，保住人名 |
| 同一列时间格式一半带秒一半不带 | 全列统一格式 |

### 3.4 三条内容规矩

1. **一列只表达一件事**：不要把「货主 + 仓库 + 货品」塞进同一格；需要合并时按 3.3 节拆行，而不是用顿号串起来。
2. **数字和文字分开对齐**：数量、金额、比例右对齐；文本、单号、名称左对齐；状态、开关、图片、序号、操作居中。
3. **单元格不放大按钮**：行里的操作一律走操作列（第 5 节），内容区只放「可点进去的链接」或「可展开的小交互」。

### 3.5 常见空值写法（要统一）

| 写法 | 现状 | 规范 |
| :--- | :--- | :--- |
| `—` | 多数页面 | ✅ 统一用这个 |
| `--`（半角双横） | 货品列表的收集项摘要 | ❌ 改成「—」 |
| `——`（双长横） | 操作列组件无按钮时 | ❌ 改成「—」（组件待改） |
| 空白 | 少数页面直接不渲染 | ❌ 至少给「—」，避免看起来像加载失败 |

### 3.6 让整张表不再横向滚动的做法

目标是：**列不多时，一屏放下，不拖横向滚动条**；列确实很多时再让它滚。

| 优先顺序 | 做法 | 效果 |
| :---: | :--- | :--- |
| 1 | 长单号、超长编号**折两行**（列宽 130～150） | 每个单号列省 50～70px |
| 2 | 主体名 / 标识、人员 / 组织 / 时间**纵向堆叠**（见 3.3 节） | 每列省 40～80px |
| 3 | 低优先级列（关联单号、备注）**窄屏隐藏**（`hidden xl:table-cell`），详情页可看 | 窄屏直接省一整列 |
| 4 | 合并同源字段为一列（如「计量参数(单位)」） | 少一列 |
| 5 | 仍放不下 → 允许横向滚动，**序号列与操作列固定** | 保证首尾信息始终可见 |

判定线：

- **≤ 8 列**：目标是在 `1440px` 屏幕上完整展示（内容区约 1080～1100px）。
- **9 列以上**：允许横向滚动；滚动时左侧序号、右侧操作必须固定。
- 任何情况下都**不允许**为了省宽度去截断单号、压窄状态列或缩小操作列按钮。

实测参考：入库记录 11 列、1516px —— `1440px` 屏横向滚动，`1920px` 屏（内容区约 1566px）**不滚动**，行高统一 72px。

## 4. 表头与列的对齐

- 表头文字：`13px`、字重 `600`、色 `#4e5969`；页面里写 `text-xs font-medium` 会被覆盖成这个效果。
- **对齐跟内容一致**：内容右对齐的列，表头也右对齐；内容居中的列，表头也居中。
- 表头支持排序时，在文字右侧加排序箭头（上下两个小三角），不换行。
- 表头两侧不放操作按钮；批量工具条放在表格上方（见 02 第 5.2 节）。

## 5. 操作区

### 5.1 位置与底色

- 操作列**固定在右侧**：`sticky right-0`，横向滚动时不动。
- 表头操作列底色：`bg-slate-100`；数据行操作列：`bg-white`，悬停 `group-hover:bg-slate-50`。
- 左侧隔离：`border-l border-border/80` + 阴影 `shadow-[-8px_0_16px_-4px_rgba(0,0,0,0.08)]`。
- 层级：表头 `z-20`、数据行 `z-10`，避免压住弹层。
- **禁止半透明**：`bg-white/80`、`bg-muted/40`、`backdrop-blur` 这类写法会让左侧内容透过来，一律不许用。

### 5.2 操作列宽度

按一行放几个按钮定宽，**不要**随手写 `w-44`：

| 一行按钮数 | 操作列宽度 | 说明 |
| :--- | :--- | :--- |
| 1 个 | 约 `82px` | |
| 2 个 | 约 `150px` | 最常见 |
| 3 个 | 约 `218px` | |
| 4 个 | 约 `150px`（2×2 两行） | 行高会变成两行 |
| 5～9 个 | 约 `218px`（3+2 / 3×2 / 3×3） | 最多直出 9 个 |
| 10 个及以上 | 约 `218px` + 「更多」 | 前 8 个直出，其余进「更多」下拉 |

> 宽度是「每格 4 个汉字 ≈ 58px + 间距，再加左右内边距」算出来的；按钮文案超过 4 个字时会被省略号截断，所以**操作文案要控制在 2～4 个字**。

### 5.3 必须用组件，不要手写

操作列统一用 `B端PC/src/shared/components/TableRowActionPanel.tsx`：

| 能力 | 组件已经处理好的事 |
| :--- | :--- |
| 排版 | 按按钮数自动算列数（1/2/3 列、4 个排 2×2、5 个排 3+2） |
| 宽度 | 自动算操作列宽，页面只需要在表头写一次宽度 |
| 溢出 | 超过 9 个自动收进「更多」下拉（弹层宽 176px），危险操作自动加分割线 |
| 语气 | 主操作（默认主色）、提醒类（琥珀）、危险类（红色）三种 |
| 空态 | 无可用操作时显示「—」 |
| 禁用 | 置灰但保留文案，悬停提示禁用原因 |
| 链接跳转 | 支持 `to` 直接跳路由，或 `onClick` 触发弹窗 |

> **现状**：全部表格里只有 7 个用了这个组件，另外有 6 处是手写 `<Button variant="link">`。差别在手写版本宽度不受控、换行不可控、危险项没有分隔。改动这些页面时统一换成组件。

### 5.4 按钮长什么样

| 项 | 规范 |
| :--- | :--- |
| 形态 | 文字链接（不是实心按钮、不是描边按钮、不是图标按钮） |
| 字号 | `14px`、常规字重 |
| 颜色 | 默认主色；提醒类琥珀（如「解除」）；危险类红色（如「删除」「停用」） |
| 悬停 | 出现下划线（不是加底色） |
| 行高 | 每格最小 `28px` |
| 对齐 | 居中，超长文案省略并 `title` 提示 |
| 行内图标 | 只在「更多」按钮上加一个下箭头，其他操作不加图标 |

### 5.5 按钮放几个、按什么顺序

- **一行最多 3 个**，最多直出 9 个；能放进 3 个的页面不要放 5 个。
- 顺序固定（从左到右）：
  1. 查看类：详情 / 查看
  2. 编辑类：编辑 / 修改
  3. 业务主操作：审批、解除、发布、入库…
  4. 状态变更：启用 / 停用
  5. 危险操作：删除（放最右，红色）
- 没有可用操作时不要留空，显示「—」。
- 需要二次确认的操作（删除、停用、平仓），点击后弹确认框并写清后果。

### 5.6 行高与两行排列

- 操作超过 3 个时，操作列变成两行；按钮固定 `28px` 高、行间距 `8px`，两行合计 `68px`，**仍在标准行高 72px 内**，不会把整行撑高（`index.css` 已有覆盖规则）。
- 两行排列的顺序是「先左后右、先上后下」，读起来顺；不要做成竖排。
- 如果某一行因为操作太多导致行高超过 72px，说明该收进「更多」了，而不是让行变高。

## 6. 反面设计

| ❌ 禁止 | ✅ 应做 |
| :--- | :--- |
| 操作列半透明、加毛玻璃 | 不透明底色 + 左侧隔离线 + 阴影 |
| 每行堆 5 个以上的操作按钮 | 最多 3 个/行，超出进「更多」 |
| 操作列宽度随手给 `w-44`、和按钮数不匹配 | 按第 5.2 节按按钮数定宽 |
| 操作列用实心主色按钮，整列一片蓝 | 文字链接，危险项才用红色 |
| 行内放「删除」图标按钮 | 删除放操作列最右，红色文字 + 二次确认 |
| 时间列写成一行 `2026-06-03 10:15:00`，把列撑到 160px | 日期一行、时分秒一行，列宽 110～130 |
| 时间列上下两行字号/颜色不一致 | 两行都正文字体，用 `stackedPlain` |
| 单号列截断成 `RK2026…` | 完整展示；超长号折两行 + 悬停复制 |
| 为了塞下长内容把单号列撑到 240px 以上 | 单号折两行、列宽 130～150，把宽度省给别的列 |
| 行高跟着内容忽高忽低（44 / 60 / 77 混排） | 整表统一 72px，内容在格内换行 |
| 把 4 行内容硬塞进 72px 的行里 | 最多 3 行，超出省略 + `title` |
| 数量、金额左对齐 | 右对齐 + 数字等宽 |
| 状态列写纯色文字 | 用状态标签，全站同色 |
| 一格塞三件事（货主、仓库、货品） | 一列一件事，最多主次两行 |
| 空值一片空白，或混用 `--` / `——` | 统一「—」 |
| 勾选行没有任何底色反馈 | 浅主色底 + 复选框 |
