# 04-PC 端新增编辑与配置页规范

> 本章管「填表」这一类页面：新增、编辑、多策略配置。
> 与之配套的色值、控件尺寸、弹窗宽度见 [05-色彩、字体与表格视觉规范](./05-PC端色彩与表格视觉规范.md)。

---

## 1. 适用范围

| 类型 | 特征 | 用本章哪部分 |
| :--- | :--- | :--- |
| 简单新增 / 编辑 | 字段少于 8 个、一次提交 | 第 2 节骨架 + 第 3 节基本信息 |
| 复杂配置 / 多策略 | 多个策略块、逐块保存、逐块校验 | 第 2～6 节全部 |
| 仓储类单据 | 基本信息 + 货物明细 | 第 2 节骨架 + 第 7 节 |

---

## 2. 页面骨架

```text
┌─ 面包屑 ────────────────────────────────────────────────┐
├─ 顶栏 Card ─────────────────────────────────────────────┤
│ [← 返回]  页面标题（新增/编辑 + 业务主键）    [全局操作?] │
└─────────────────────────────────────────────────────────┘
┌─ Card · 基本信息 ───────────────────────────────────────┐
│ 规则名、关联订单/设备、通知对象等 · 两列栅格              │
└─────────────────────────────────────────────────────────┘
┌─ Card · 策略 / 明细区 ──────────────────────────────────┐
│ 卡头：区块标题 + 业务约束说明（如「逐条独立保存」）       │
│ 策略 1 [开关] ─ 展开字段 / 内嵌表格 ─ [保存该策略]       │
│ 策略 2 …                                                │
└─────────────────────────────────────────────────────────┘
```

- 页面根节点：`className="space-y-4 p-6"`；区块之间 `space-y-4`。
- **不强制用页签**：策略块用卡片内折叠、或纵向多卡片组织即可；只有业务步骤超过 3 个大阶段，才允许改用页签，且每个页签内部仍然用卡片分块。

---

## 3. 基本信息区

1. 独立 `Card` + `CardHeader`（标题写「基本信息」这类业务名）+ `CardContent`。
2. 字段栅格：默认 `grid gap-4 md:grid-cols-2`（与工程现状一致）；字段多且短的可以 `lg:grid-cols-3`，但**不要**再往 4 列挤，输入框会窄到看不清内容。
3. 每项：`Label` 在上、控件在下，单项间距 `space-y-1.5`；必填星号紧贴 `Label`。
4. 控件宽度 `w-full`，高度由覆盖层统一成 `34px`。
5. 关联主数据（订单号、设备范围）变更时，下方策略区要联动刷新，并提示「下方策略有未保存修改」。

**表单辅助文案分层**（两种不能混着写）：

| 类型 | 用哪个组件 | 写法 |
| :--- | :--- | :--- |
| 给用户看的上线说明、字段解释 | `ProductFieldHint` | 用大白话讲「这个字段填什么、会带来什么影响」 |
| 规格对照、PRD 编号、规则出处 | `PrototypeSpecCallout` | 可以带规则编号与条款引用 |

两者不要塞进同一段灰字里；页面上如果只有规格说明，也要用 `PrototypeSpecCallout` 包起来，方便后续一眼分辨「哪些是给用户看的」。

---

## 4. 策略 / 多区块区

1. 卡头写清业务约束，例如「预警策略配置（逐条独立保存 · 至少启用 1 项）」——约束文案来自 PRD，不要自己编。
2. **单个策略块**：
   - 块头：序号 + 策略名 + 启用开关。
   - 块体：该策略专属字段；需要明细时用内嵌可编辑表格，不要用弹窗代替整张表（行级选择除外）。
   - 块脚：主按钮「保存该策略」，只有该块有改动时可点。
3. **每个策略块要显示保存状态**，三种文案固定：

| 状态 | 展示 | 含义 |
| :--- | :--- | :--- |
| 有改动 | `● 未保存` | 该块改过但没保存，离开要拦 |
| 已保存 | `✓ 已保存` | 与最近一次保存一致 |
| 已回退 | 按钮「恢复上次保存内容」 | 放弃当前块的改动，恢复成上次保存值 |

4. **关闭 / 停用策略**：开关关到关闭时，如果 PRD 要求确认，弹窗说明后果（例如「该策略下未处理流水将作废」），确认后才写入表单状态。
5. **至少保留一项有效**：关闭最后一项有效策略时，用轻提示拦截，不允许提交。

---

## 5. 业务弹窗

| 场景 | 做法 |
| :--- | :--- |
| 选择设备 / 货物 / 订单 | 大号弹窗（`672px`～`820px`），内含筛选 + 表格勾选，确认后回显到表单 |
| 删除 / 停用 / 偏离推荐配置 | 确认弹窗，写清后果，取消在左、确认在右 |
| 处置方式偏离推荐 | 单独确认弹窗，左右对比「推荐值 / 当前值」 |
| 图片 / 凭证 | 预览弹窗，不要让表单卡片被图片无限撑高 |

- 弹窗宽度档位与按钮规则见 05 第 6 节。
- 破坏性操作确认按钮用红色，并且**必须写清后果文案**，不能只靠颜色表态。

---

## 6. 改动拦截（Dirty）

1. **块级拦截**：任一策略块有未保存改动时，点「返回」或切换路由要弹确认，例如「当前有未保存的策略修改，确定离开吗？」。
2. **页面级拦截**：整页表单有改动时，关闭页签、刷新浏览器也要拦。
3. 现状说明：工程里已落地块级确认（用浏览器原生 `window.confirm`），**浏览器刷新拦截（`beforeunload`）还没接**。要做到第 2 条需要补 `beforeunload` 监听，属于工程待办；在此之前，新页面至少要把块级确认做全。
4. 保存成功后给一条轻提示（写法见 05 第 7 节）+ 清除对应块的未保存标记；编辑态可展示版本号或更新时间。

## 7. 与台账表单的区别

| 维度 | 台账新增（如入库单） | 配置 / 策略页 |
| :--- | :--- | :--- |
| 保存方式 | 底部一次提交 | 分块保存 + 可选整单发布 |
| 结构 | 基本信息 + 货物明细卡片 | 基本信息 + 多个策略卡片 |
| 弹窗 | 关联单、附件、审批流选择 | 设备/订单选择、策略停用确认 |
| 校验时机 | 提交时整表校验 | 每块保存时校验该块 + 提交前整表校验 |

简单入库 / 出库表单可以复用本章的卡片结构；明细用可折叠行卡片。**步骤超过 2 段**时，优先改成路由分步或顶部步骤条（步骤语义与 H5 一致，步数按 PRD）。

## 8. 反面设计

| ❌ 禁止 | ✅ 应做 |
| :--- | :--- |
| 10 个策略一次性保存，没有任何块级状态 | 逐策略保存 + `● 未保存 / ✓ 已保存` |
| 设备选择用原生多选框 | 弹窗 + 表格勾选 |
| 停用策略没有确认 | 弹窗说明业务后果 |
| 表单页没有返回入口 | 面包屑 + 顶栏返回 + 回到列表的深链 |
| 表单页字段堆到 4 列，输入框只剩几十像素 | 两列为主，必要时三列 |
| 用户说明和 PRD 编号写在同一段灰字里 | 分别用 `ProductFieldHint` 与 `PrototypeSpecCallout` |
| 改完直接离开，改动悄悄丢掉 | 块级确认 + 页面级拦截 |
