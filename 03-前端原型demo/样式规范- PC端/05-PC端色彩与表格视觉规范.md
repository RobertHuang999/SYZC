# 05-PC 端色彩、字体与表格视觉规范

> 本章是 PC 端视觉的「地基」：色值、字体、控件尺寸、表格样式都在这里。
> **新建页面前先读第 1 节**，否则会出现「类名写了、页面没变」的困惑。

---

## 1. 先看：样式到底由谁说了算

原型工程的样式分三层，优先级从低到高：

| 层级 | 位置 | 管什么 |
| :--- | :--- | :--- |
| 第一层 · 设计令牌 | `src/index.css` 的 `@theme` 与 `:root` | 品牌色、中性色、圆角、字体变量 |
| 第二层 · 基础层 | `@layer base` | 全局字体栈、默认边框色、body 底色 |
| 第三层 · 页面容器覆盖 | `.page-surface ...` 一组选择器 | 内容区里的标题、卡片、输入框、按钮、表格 |

**关键结论**：第三层没有包进 `@layer`，属于「无分层样式」，**优先级永远高于 Tailwind 工具类**。

所以在业务页面里写 `text-2xl`、`rounded-xl`、`h-9` 这类工具类，只要元素落在下表里，**实际渲染结果都会被改写**。这不是 bug，是原型工程有意做的「后台密集型」压缩。

### 1.1 页面容器（`page-surface`）覆盖清单

| 元素 | 实际生效值 | 说明 |
| :--- | :--- | :--- |
| 页面一级标题 `h1` | `20px` / 行高 `28px` / 外边距 `0` | 页面里写 `text-2xl`（24px）**不生效**，实渲染仍是 20px |
| 二级标题 `h2` | 颜色 `#1d2129` | 字号不覆盖 |
| 卡片 `Card` | 圆角 `8px`、边框 `#f0f1f3`、无阴影 | 写 `rounded-xl` 会被压成 8px |
| 卡片内容 `CardContent` | 文字色 `#4e5969` | |
| 输入框 / 下拉触发器 / 多行文本 | 高 `34px`、字号 `13px`、圆角 `6px`、边框 `#e5e6eb`、占位色 `#a9aeb8` | 多行文本最小高 `80px` |
| 按钮 | 最小高 `32px`、圆角 `6px` | 表格行内操作按钮例外，固定 `28px` 高（见 06 第 5 节） |
| 表格外容器 | 横向滚动、边框 `#f2f3f5`、圆角 `12px` | |
| 表格 | 最小宽 `980px`、字号 `13px`、文字色 `#4e5969` | 列多时容器内横向滚动 |
| 表头单元格 | 背景 `#f7f8fa`、高 `45px`、内边距 `0 16px`、字重 `600` | |
| 数据单元格 | 高 `44px`、内边距 `0 16px`、分隔线 `#f2f3f5` | |
| 数据行悬停 | 背景 `#f7faff` | |
| 分页按钮 | `28px × 28px`、圆角 `4px`；当前页 `#165dff` 字色 + `#e8f3ff` 底 | |
| 下拉面板 | 圆角 `6px`、边框 `#e5e6eb`、阴影 `0 8px 24px rgb(15 35 95 / 12%)` | |
| 主按钮底色 | `#165dff` | `bg-primary` 被显式重写 |
| 次要文字 | `#86909c` | `.text-muted-foreground` 被重写 |

**要突破覆盖怎么办**：改 `src/index.css` 的对应规则，**不要**在页面里加 `!important` 硬顶，也不要在页面里重复声明同一属性去和覆盖层打架。

## 2. 字体与排版

### 2.1 首选字体：PingFang SC（苹方）

工程里现在有**三处**字体声明，写法并不一致：

| 位置 | 声明的字体栈 |
| :--- | :--- |
| `@theme --font-sans / --font-heading` | `"PingFang SC", -apple-system, BlinkMacSystemFont, "Microsoft YaHei", "Segoe UI", Roboto, sans-serif` |
| `@layer base`（网页、按钮、输入框等） | 同上 |
| `body` 规则（实际绝大多数文字继承这一条） | `"PingFang SC", "SF Pro Display", "Helvetica Neue", Arial, sans-serif` |

- 苹果电脑上三处结果一致，看不出差别。
- **Windows 上会露馅**：`body` 那条在 Windows 找不到「SF Pro Display」和「Helvetica Neue」，会直接掉到 `Arial`，中文再交给系统默认字体，**拿不到微软雅黑**。
- 因此规范要求：**新增页面不要自带字体**；Windows 字体回落问题作为工程待办，统一到带「Microsoft YaHei」的那套字体栈（改 `body` 规则即可，不要在页面里补）。

### 2.2 `font-mono` 的处理

- `@theme` 里 `--font-mono` 已被**重新定义成苹方**，所以在 PC 里写 `font-mono`、`font-sans`、`font-heading` 得到的都是同一套字体，不会变成等宽英文。
- 这是兜底，不是许可。**业务单号、日期时间、数量、社会信用代码仍然禁止主动写 `font-mono`**，避免以后有人把兜底删掉时全站崩字形。

### 2.3 `tabular-nums`（等宽数字）：允许使用

- 旧条文把 `tabular-nums` 和 `font-mono` 一起禁掉了，这条**已修正**。
- `tabular-nums` 只让数字宽度对齐，字体仍是苹方，表格里上下行数字能对整齐，**鼓励在金额、吨数、时间列使用**。
- 统一时间组件 `DateTimeText` 本身就带 `tabular-nums`，属于标准做法。

### 2.4 单号与日期时间的标准写法

| 场景 | 标准 | 反例 |
| :--- | :--- | :--- |
| 列表单号列 | 16 位以内：列宽 `w-[200px]`、`whitespace-nowrap font-medium`；17 位以上超长号：列宽 `w-[130px]`～`w-[150px]`、`whitespace-normal break-all` 折两行。链接态加 `text-primary hover:underline`；悬停出现复制按钮，复制后 1.5 秒显示「✓」。**两种都要求完整可见** | 加 `truncate` 把单号截成 `...` |
| 单号单元格组件 | 复用 `B端PC/src/features/inbound-records/components/InboundDocNoCell.tsx`（完整展示 + 悬停复制） | 每个页面各写一套复制逻辑 |
| 列表日期列 | `TableDateTimeCell` **一律用 `stackedPlain`**（日期上行、时分秒下行，两行都是正文字体） | 时间下半截单独加 `font-mono text-xs`，或整串单行把列撑宽 |
| 单元格内人 + 时间 | `TablePersonTimeCell` / `TableProcessedInfoCell`；无值统一显示「—」 | 一个格子塞三段不同字号 |
| 长文本列 | `HoverOverflowText`（默认省略号，悬停浮层看全文） | 直接撑高整行 |

## 3. 色板

### 3.1 品牌色与激活色

| 用途 | 色值 | 对应变量 / 用法 |
| :--- | :--- | :--- |
| 主色（按钮、链接、选中） | `#165dff` | `--primary`；主按钮 `bg-primary`，链接 `text-primary` |
| 主色浅底（选中态、标签底） | `#e8f3ff` | `--accent`；侧边栏选中、分页当前页 |
| 主色浅边框 | `#bedaff` | 次要按钮选中描边 |
| 焦点圈 | `#85a9ff` | `--ring` |
| **模块导航与页签的激活橙** | 字色 `#d99020`、底色 `#fff6e8`、边框 `#f7dfb8` | 顶部一级模块选中、页签选中 |

> 橙色只用于「当前所在模块 / 当前页签」这类**导航位置**提示；业务状态、按钮、标签**不要**用橙色，避免和预警态混淆。

### 3.2 中性色（页面与表格）

| 用途 | 色值 |
| :--- | :--- |
| 页面底色 | `#f7f9fc`（向下渐变到 `#f5f7fa`） |
| 卡片 / 面板白底 | `#ffffff` |
| 主标题 / 强调文字 | `#1d2129` |
| **正文（表格、表单、详情内容）** | `#4e5969` |
| 次要文字 / 字段标签 | `#86909c` |
| 占位符 / 极弱提示 | `#a9aeb8` |
| 分割线、卡片边框 | `#f0f1f3` |
| 控件边框 | `#e5e6eb` |
| 表格分隔线 | `#f2f3f5` |
| 浅底块（表头、禁用底） | `#f7f8fa` / `#f2f3f5` |
| 行悬停 | `#f7faff` |
| 滚动条滑块 | `#c9cdd4` |

### 3.3 状态语义色（标签 / 徽标）

统一用「浅底 + 同色描边 + 深一档文字」三段式，例：`border-emerald-200 bg-emerald-50 text-emerald-700`。

| 语义 | 用色 | 典型场景 | 实际类名组合 |
| :--- | :--- | :--- | :--- |
| 正常 / 已通过 / 已启用 | 翠绿 Emerald | 审核通过、启用中、设备在线 | `border-emerald-200 bg-emerald-50 text-emerald-700` |
| 待处理 / 待审核 / 预警 | 琥珀 Amber | 待处置、预警待确认、临期提醒 | `border-amber-200 bg-amber-50 text-amber-700` |
| 公示中 / 特定业务档 | 橙色 Orange | 未公示、预警等级档位 | `border-orange-200 bg-orange-50 text-orange-700` |
| 驳回 / 高危 / 失败 | 玫红 Rose | 审批驳回、跌破平仓线、校验失败 | `border-rose-200 bg-rose-50 text-rose-700` |
| 已作废 / 已停用 / 历史 | 中性灰 Slate | 单据作废、规则停用、已归档 | `border-slate-200 bg-slate-50 text-slate-600` |
| 提示信息 / 中性强调 | 主色蓝 Blue | 说明条、可点击提示 | `border-blue-200 bg-blue-50 text-blue-700` |

规则：

1. **同一业务状态在列表、详情、弹窗里必须用同一组颜色**，不许列表绿、详情蓝。
2. **等级色走字典**：预警等级、严重程度等由后台字典返回颜色，前端只渲染色点 + 名称（见 `SeverityLevelDisplay`），禁止在页面里硬编码彩虹色。
3. 危险操作按钮用 `destructive`（`#f53f3f`），并且**同时给文案说明后果**，不能只靠颜色。

### 3.4 深色模式

工程里保留了深色模式的变量（`.dark`），但业务页面没有做深色适配，也没有切换入口。
**规范口径：原型只做浅色，新增页面不需要写 `dark:` 变体。** 少数历史页面残留的 `dark:` 类可保留，新页面不要再加。

## 4. 表格

### 4.1 容器

- 表格外层统一用带边框的圆角容器，横向溢出在容器内滚动：`overflow-hidden rounded-lg border`（部分老页面用 `rounded-md`，新页面统一 `rounded-lg`）。
- 表格最小宽度：普通台账 `min-w-[980px]`～`min-w-[1000px]`；列多（10 列以上）的复杂台账 `min-w-[1240px]`～`min-w-[1520px]`（入库记录 11 列现为 1516px）。
- 小屏时**滚动，不压缩列宽**，不允许把文字挤到两三字就换行。

### 4.2 表头与行

| 项 | 规范 |
| :--- | :--- |
| 表头背景 | `#f7f8fa`（由覆盖层统一给）；页面若显式写了 `bg-slate-100`，以显式为准，但**同一页面内必须统一** |
| 表头字 | `13px`、字重 `600`、色 `#4e5969` |
| 表头高 | `45px` |
| 数据行高 | `44px` |
| 单元格内边距 | 左右 `16px` |
| 分隔线 | `#f2f3f5` |
| 行悬停 | `#f7faff` |
| 数值列 | 右对齐；小数位按 PRD |
| 状态列 | 用标签，不用纯色文字 |

### 4.3 固定操作列（防穿透）

横向滚动时，左侧内容会从操作列下方滑过，所以操作列**必须是 100% 不透明底色**，并加左侧分隔与阴影：

- 表头操作列：`bg-slate-100`
- 数据行操作列：`bg-white`，行悬停时 `group-hover:bg-slate-50`
- 隔离线 + 阴影：`border-l border-border/80 shadow-[-8px_0_16px_-4px_rgba(0,0,0,0.08)]`
- 半透明底色（`bg-white/80`、`bg-slate-50/50`、毛玻璃）**一律禁止**；一旦出现，滚动时就能看到后面的字透出来。

> 操作列的宽度、按钮排布、语气色、溢出规则，统一见 [06-表格行与操作列规范](./06-PC端表格行与操作列规范.md) 第 5 节。

### 4.4 行内容

单元格放什么、怎么对齐、多行怎么排、空值怎么写，统一见 [06-表格行与操作列规范](./06-PC端表格行与操作列规范.md) 第 2～4 节。

一句话概括：**一列只表达一件事，数字右对齐，状态用标签，空值统一「—」。**

### 4.5 空态

- 无数据时表格内显示一行居中提示，文案要说明原因，例如「暂无数据，可调整筛选条件后重试」；有筛选的页面在空态旁给「重置筛选」。
- **不允许**留一个空白表身，也不允许用 10 行假的空记录凑高度。
- 目前工程里多数页面只有一行「暂无数据」文字、没有插画和重置按钮，属于**待补齐项**；新页面按上面的要求做。

## 6. 弹窗（Dialog）宽度档位

| 场景 | 宽度 | 示例 |
| :--- | :--- | :--- |
| 确认、二次提醒 | 约 `400px`（`max-w-md`） | 删除确认、停用确认 |
| 普通表单 | 约 `512px`（`max-w-lg`） | 新增等级、改价 |
| 主数据选择、明细编辑 | `672px`～`820px`（`sm:max-w-2xl` 或 `sm:max-w-[820px]`），高度上限 `85vh`，内部区域滚动 | 选设备、选订单、编辑货品行 |

- 弹窗底部按钮：取消在左（`outline`），确认在右（`default`）；破坏性操作确认按钮用红色并写明后果。
- 弹窗内容超过一屏时，**只有中间内容区滚动**，标题和底部按钮固定。

## 7. 轻提示（Toast）

工程里**没有**统一的轻提示组件，各页面自己写浮层。为保持观感一致，新页面按下面这条标准写法：

```text
fixed bottom-6 left-1/2 z-[120] max-w-md -translate-x-1/2 rounded-md
bg-foreground px-4 py-2 text-center text-sm text-background shadow-lg
```

- 停留时间统一 **2500 毫秒**（现存 2400 / 2500 / 2600 / 2800 / 3000 五种，属于历史遗留，新页面按 2500）。
- 校验失败：字段旁给红字提示（`text-rose-600`），同时在顶部或底部给一条汇总提示，不能只弹窗。
- 浏览器原生 `alert` 禁止使用；`window.confirm` 仅允许用于「离开页面 / 放弃未保存内容」这类拦截。

## 8. 反面设计

| ❌ 禁止 | ✅ 应做 |
| :--- | :--- |
| 想改标题字号就去改 `text-2xl`，结果怎么改都不变 | 先看第 1 节覆盖清单，要改就改 `index.css` 里的覆盖规则 |
| 单号列加 `truncate` 变成 `2026-10…` | 完整展示：16 位内 200px 单行，超长号 130～150px 折两行 + 悬停复制 |
| 时间列下半截单独套等宽字体 | 统一用 `TableDateTimeCell` |
| 同一状态列表用绿色、详情用蓝色 | 按第 3.3 节语义色，全站一致 |
| 操作列半透明底、滚动后文字叠在一起 | 不透明底色 + 左侧隔离线 + 阴影 |
| 操作按钮直接堆 8 个 | 用 `TableRowActionPanel`，超过 9 个进「更多」 |
| 每个页面自己写一套 Toast、停留时间随便定 | 按第 7 节标准写法与 2500 毫秒 |
| 等级颜色在页面里写死彩虹色 | 取字典色，只渲染色点 + 名称 |
