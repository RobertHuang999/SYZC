## 1. 核心洞察 (Insight)

### 真实痛点

描述用户当前面临的实际问题（而非用户提出的解决方案）。

### JTBD (Jobs-to-be-Done)

> **用户要雇佣这个功能来完成什么任务？**

用户想要\_**\_，以便\_\_**。

### 业务价值评估

- [ ] **High**: 核心业务流程，不做严重影响收入/体验
- [ ] **Medium**: 重要优化，能显著提升效率或满意度
- [ ] **Low**: 锦上添花，可延后或不做

**量化依据**: (如：可节省X小时/天，或提升Y%转化率)

## 2. 用户故事 (User Story)

> **As a** (角色)...  
> **I want to** (功能/动作)...  
> **So that** (价值/收益)...

**示例**:

> **As a** 采购员  
> **I want to** 快速查看待审批的采购单列表  
> **So that** 我能在1分钟内找到紧急订单并优先处理

### 功能验收标准 (AC)

- [ ] **AC-01**: (明确的可测试标准，如：用户点击"提交"后3秒内跳转到详情页)

### 非功能性需求 (NFR)

| 维度         | 要求               | 备注                        |
| :----------- | :----------------- | :-------------------------- |
| **性能**     | 页面加载时间 < 2秒 | 基于3G网络环境              |
| **并发**     | 支持100人同时在线  | 初期规模                    |
| **数据保留** | 历史数据保留3年    | 符合财务合规要求            |
| **可用性**   | 99.5%可用性        | 允许月停机时间不超过3.6小时 |

## 4. 建议方案 (Proposal)

### MVP方案 (最小可行产品)

**目标**: 最小成本解决核心痛点

**方案概述**:

- 功能1: ...
- 功能2: ...

**不做什么** (明确范围):

- ❌ 不包含导出功能（二期再做）
- ❌ 不支持批量操作（一期仅单条处理）

### 理想方案 (长期规划)

**适用场景**: 如果有充足资源和时间

**扩展功能**:

- 高级筛选与自定义视图
- 批量操作与导入导出
- 移动端适配
