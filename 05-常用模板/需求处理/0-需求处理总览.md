# 需求处理总览

> **用途**：按流程节点使用本目录。每个节点以“输入 → 输出”成对呈现；复杂需求走完整链路，简单需求可按影响范围裁剪。

## 你只需要提供什么

1. 原始需求或会议结论。
2. 关联的基准 PRD、已有页面、原型或业务资料。
3. 已知的范围、角色、上下游影响与待确认问题；未知内容可明确标注“待确认”。

| 流程节点 | 什么时候使用 | 输入 | 输出 |
| :--- | :--- | :--- | :--- |

| 3. 字段设计 | 需要定义页面展示、筛选、录入与审计信息 | [3-1 (输入)字段设计](./3-1%20(输入)字段设计.md) | [3-2 (输出)字段清单模板](./3-2%20(输出)字段清单模板.md) |

## 最小使用路径

| 需求情况 | 建议路径 |
| :--- | :--- |
| 新增独立菜单、跨模块或高风险业务 | `1 → 2 → 3 → 4 → 5` |
| 已有流程，仅新增或调整状态、校验、权限、计算 | `2 → 3 → 4`；需要原型时再进入 `5` |
| 已有流程和规则，仅新增或调整业务字段 | `3 → 4`；需要原型时再进入 `5` |
| 仅调整页面文案、布局或交互，且不改字段和规则 | 直接使用 `4 → 5`，引用既有三件套 |

跳过节点的前提是该节点对应的既有产物已经存在且仍然有效；任何影响状态、规则或字段的变更，都必须回写三件套。

## 全局表达边界

- 只输出产品设计需要的业务字段，不产生数据库列、接口参数、技术主键、报文或其他研发实现内容。
- 状态、枚举、页面文案默认使用中文；既有系统编码仅在确有必要时写成“中文名称（既有编码）”。
- 场景、规则、操作、验收和待确认项必须写为“【中文名称】(编号)”，不单独出现编号。
- 所有正式输出文档必须在文末保留“修订记录”，至少记录版本、修订日期、修订内容与修订人；首次输出标记为 `V1.0` 与“初稿发布”。
