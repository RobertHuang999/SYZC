# SYZC 菜单 PRD 套件交叉走查指南

> **定位**：对单个独立菜单所生成的 PRD 套件（流程推演、主PRD、字段清单、用例推演、Demo PRD）进行严密的交叉对比与一致性审查。  
> **适用范围**：SYZC 交付件评审前的一键式自动化走查与质检验收。  
> **输出目标**：`[对应模块路径]/[菜单名]-PRD套件交叉走查报告.md`

---

## 喂入文件

请让 AI 读取以下文件：

- `AGENTS.md`（项目业务规范、合规防线与设计真源）
- 当前菜单的全套产物：
  - `[对应模块路径]/[菜单名]-业务流程推演.md`
  - `[对应模块路径]/[菜单名]主PRD.md`
  - `[对应模块路径]/[菜单名]字段清单.md`
  - `[对应模块路径]/[菜单名]-用例数据推演.md`
  - `[对应模块路径]/[菜单名]_Demo_*.md`（或 ASCII 版）

---

## 提示词

```text
请读取以上文件。现在对【{业务模块}-{菜单名称}】的完整 PRD 套件进行交叉走查。

请注意：

- 发现任何冲突、遗漏或不一致时，必须明确指出“以谁为权威准绳”，并指出应回写修正哪个文件。
- 走查必须严格依据 AGENTS.md 业务真源与字段唯一权威源原则进行审查。

请创建或更新：
{对应输出目录}/{菜单名称}-PRD套件交叉走查报告.md

请按以下结构输出走查报告：

# {菜单名称}-PRD套件交叉走查报告

## 一、走查范围与基准
- 列出本次走查读取的文件清单与版本号。
- 明确权威源原则：字段以《字段清单》为准；状态流转与业务规则以《主PRD》为准；页面表现以《Demo PRD》为准。

## 二、字段字典一致性走查
用表格输出比对结果：
| 检查项 | 走查发现 | 状态（PASS / WARN / FAIL） | 待修正文件与建议 |
- 检查 1：主 PRD 中引用的字段是否 100% 存在于字段清单？
- 检查 2：Demo PRD 列表列、查询项、表单字段是否都来自于字段清单，且必填/只读规则一致？
- 检查 3：字段清单中是否存在一物多名、命名不规范或缺失精度/单位的情况？
- 检查 4：外部关联字段（如货主、仓库、设备）是否明确标注了快照机制？

## 三、状态机与业务流闭环走查
| 检查项 | 走查发现 | 状态（PASS / WARN / FAIL） | 待修正文件与建议 |
- 检查 1：业务流程推演图、主 PRD 状态流转图、Demo PRD 状态 Tab 是否完全对齐？
- 检查 2：状态机是否存在死状态（无法流转到终态，或终态后仍有非法动作）？
- 检查 3：动作能力矩阵是否覆盖了所有状态下的全部按钮显隐与禁用策略？

## 四、SYZC 核心合规与业务防线专项走查
| 检查项 | 走查发现 | 状态（PASS / WARN / FAIL） | 待修正文件与建议 |
- 检查 1【自审禁止（P06/R11）】：涉及审批的菜单，是否明确禁止审批人审批本人申请？本人视角是否已移除“去审批”？
- 检查 2【规则版本不回写（C08）】：涉及规则配置的菜单，是否明确版本递增生效且不回写存量告警？
- 检查 3【物联穿透闭环】：涉及设备预警的菜单，是否具备“设备告警 → 订单穿透 → 现场核销解除”的闭环说明？
- 检查 4【数据权限隔离】：是否说明了租户级隔离与仓库/机构数据权限的过滤策略？
- 检查 5【防误删保护】：基础档案类/主数据类是否严禁物理删除，统一采用“停用”？

## 五、页面交互与异常防护走查
| 检查项 | 走查发现 | 状态（PASS / WARN / FAIL） | 待修正文件与建议 |
- 检查 1：敏感操作（如作废、解除、解押、停用）是否有二次确认弹窗并强制录入原因（<= 200 字）？
- 检查 2：表单编辑离开时是否有脏数据未保存确认拦截？
- 检查 3：并发提交与幂等防护机制是否到位？

## 六、综合走查结论与整改清单
- 总结本次走查评估：【符合交付标准】 / 【需回写整改后交付】
- 用待办清单明确指出需要回写的具体文件与具体行数段落。
```
