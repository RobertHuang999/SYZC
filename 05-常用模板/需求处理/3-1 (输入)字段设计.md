# 3-1（输入）字段设计

## 何时使用

用于定义用户需要看到、筛选、录入、确认或业务审计所需的信息。

## 输入资料

- 业务流程推演与业务规则规格。
- 关联菜单已有字段、页面和业务单据。
- 需展示、筛选、录入、查看历史或审计的业务信息。

## 产出文档

| 条件 | 产出 |
| :--- | :--- |
| 所有独立菜单 | `{菜单名}字段清单.md` |
| 有独立操作弹窗、敏感核发或需单独录入的操作 | `{菜单名}操作字段清单.md`，作为字段清单的受控补充 |

## 完成标准

- 明确业务字段名称、业务含义、展示位置、展示形式、必填性、可编辑性、取值与校验来源。
- 状态和枚举中文优先；已有系统编码只可作为中文名称的括注。
- 只写业务字段，不生成数据库列、接口参数、技术主键、消息结构或技术日志字段。

## 编写参考

先从流程识别业务对象与关键业务信息，再根据规则补齐状态、计算输入、权限边界、快照与审计信息；最后明确字段在筛选、列表、详情、表单和操作弹窗中的展示方式。

字段粗纲不再作为独立产物。独立操作弹窗、敏感凭证下发或需录入原因、附件、现场信息时，操作字段清单作为字段清单的受控补充，操作写为【操作名称】(Oxx)。
