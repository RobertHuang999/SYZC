# 2-1（输入）规则设计

## 何时使用

用于需要明确状态流转、业务校验、计算口径、权限范围、快照要求或跨模块协同边界的菜单。

## 输入资料

- `01-业务梳理`产出的业务流程推演。
- 原始需求中的业务限制、合规要求与已确认决策。
- 关联菜单的既有 PRD、规则规格；跨模块时读取承接推演。
- 字段尚未完整时，只补充业务字段缺口，不编造研发字段。

## 产出文档

| 必选性 | 产出 |
| :--- | :--- |
| 必选 | `{菜单名}业务规则规格.md` |
| 高风险协同菜单 | 在同一规则规格中增加“业务协同契约”附录，不单独新建文档 |

## 完成标准

- 状态、动作、前置条件、业务结果、异常处置和审计要求闭环。
- 每条规则采用【规则名称】(Rxx/Cxx/Pxx/Fxx/Sxx)；引用其他编号时也写全名称。
- 只说明业务信息、触发条件、结果回写、失败补偿与完成边界，不写接口参数、报文或研发实现。

## 编写参考

- 状态必须明确业务阶段、允许动作、禁止动作、进入条件与离开条件；状态不可由页面下拉框直接修改。
- 【自审禁止】(R11)：审批人不得审批本人发起的申请；本人记录仅展示详情，不提供审批入口。
- 【历史流水不回写】(C08)：规则保存后生成新版本，仅影响后续新事件；既有流水保留产生时快照。
- 涉及质押、解押、库存锁定、凭证下发、物联或外部风控协同时，在规则规格中补充协同名称、触发条件、业务结果回写、重复处理、超时、补偿、快照、审计与完成边界。
