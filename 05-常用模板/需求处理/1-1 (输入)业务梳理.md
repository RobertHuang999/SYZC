# 1-1（输入）业务梳理

## 何时使用

用于新菜单、流程调整，或需求会影响其他菜单、单据、台账、预警、审批时。

## 输入资料

- 原始需求、会议结论或问题描述。
- 关联基准 PRD、已有页面、原型或现场业务资料。
- 已知角色、业务对象、上下游菜单及待确认事项。

## 产出文档

| 条件 | 产出 |
| :--- | :--- |
| 所有流程类需求 | `{菜单名}业务流程推演.md` |
| 存在字段继承、状态回写、跨菜单跳转、协同或补偿 | `{菜单名}跨模块承接推演.md` |

## 完成标准

- 覆盖主流程、异常分支与逆向或结案路径。
- 明确谁在什么节点处理什么业务对象，以及会影响哪些下游对象。
- 未确定内容登记为【待确认事项】(Qxx)，不自行补造规则。

## 编写参考

1. 先明确需求来源、目标角色、菜单边界与本期不做事项。
2. 梳理业务对象、触发动作、主流程、异常分支与结案路径。
3. 出现上游继承、下游派生、状态回写、跨菜单跳转、外部协同或失败补偿时，在流程推演中增加“跨模块承接”章节。
4. 流程只描述业务角色、业务对象和业务动作，不描述研发接口、报文或技术字段。
