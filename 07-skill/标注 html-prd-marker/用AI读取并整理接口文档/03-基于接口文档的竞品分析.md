# 第3个提示词：基于接口文档的竞品分析

请基于已获得的接口文档，观察目标产品的功能结构、业务对象、接口能力和可推断的产品设计线索。

本任务与第2步不同：第2步是把指定单据读懂、拆清；本步是从接口资料里看产品骨架和能力边界。不要把本步塞进第2步的`<任务类型>`里。接口文档只是一类证据，不能替代页面走查，也不能当成完整竞品PRD。

```text
01 抓取：用当前Chrome把接口文档落到本地
02 拆解：按产品问题做解释、字段挖掘、翻译或对接说明
03 竞品：基于接口资料观察产品能力和设计线索
```

## 一、输入

```text
目标产品或竞品名称：<名称>
接口文档：<第1步地图，或本地文件/文件夹>
可选对比资料：<自家接口、页面清单、PRD或其他竞品资料；可空>
分析范围：<指定模块、单据、Tag或整套文档>
输出目录：<输出目录>
```

优先读已保存的接口文档；若有第2步专项结果，可作辅助，不要重复全量摘抄。没有对比资料时，只做单产品观察，不虚构对比对象。输出单独落到`06-接口竞品分析`，不要写进`05-接口专项整理`。

## 二、分析边界

1. 不调用接口，不用竞品账号做测试，不尝试绕过权限。
2. 文档明确写出的接口、字段、状态、回调和错误码，才可作为直接证据。
3. 由命名、对象关系或字段结构推断的内容，必须标为「初步判断」。
4. 接口存在 ≠ 页面一定存在；开放接口 ≠ 所有用户都能用；文档没写 ≠ 产品没有该能力。
5. 记录文档版本、更新时间和本次分析范围；文档可能不完整或只覆盖对接场景。

## 三、分析内容

1. **功能和模块地图**：从Tag、接口名、业务对象中整理可能对应的模块，区分「文档明确」「初步判断」「无法判断」。
2. **单据、对象和字段**：核心字段、枚举、状态、上下游对象，以及批量、导入导出、查询、回调等能力。
3. **设计线索**：接口动作（创建、查询、取消、审核、收货、发运、回传、异常等）能说明什么产品设计；把「接口动作」和「真实页面操作」分开写。
4. **对比**（仅在有对比资料时）：模块覆盖、单据对象、字段深度、状态设计、开放能力和对接门槛。
5. **观察结论**：只写有证据的差异或特点，每条带依据和待验证点。

## 五、交付前检查

1. 是否区分了文档明确能力和结构推断？
2. 是否没有把接口能力写成完整页面功能？
3. 是否记录了版本、时间和分析范围？
4. 是否没有调用接口或绕过权限？
5. 缺少对比资料时，是否避免虚构竞品差异？
