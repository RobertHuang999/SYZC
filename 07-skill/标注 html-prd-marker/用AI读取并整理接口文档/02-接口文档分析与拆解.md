# 第2个提示词：接口文档分析与拆解

请读取已保存的接口文档，围绕指定模块或单据做产品经理可读的专项整理。

本阶段不重新全量抓取，不调用接口，不编造文档中没有的字段、状态或规则。竞品观察请用第3步，不要在本步用「竞品调研」充当任务类型。

```text
01 抓取：用当前Chrome把接口文档落到本地
02 拆解：按产品问题做解释、字段挖掘、翻译或对接说明
03 竞品：基于接口资料观察产品能力和设计线索
```

## 一、输入

```text
接口文档：<第1步产出路径，或其他本地文件/文件夹>
目标模块或单据：<例如：入库单>
任务类型：<解释接口 / 字段挖掘 / 中文翻译 / 对接说明>
当前要解决的问题：<例如：看清入库单创建要传哪些字段>
输出目录：<输出目录>
```

输入可以是第1步的接口文档地图，也可以是已手工复制/导出的本地文件。先定位与目标相关的接口，再读参数、返回、枚举、错误码、示例和关联关系。无关接口不要为了凑完整而复述。

若仍需回看在线页，可用当前Chrome只读打开；打不开就记缺口，不要发接口请求。

## 二、任务类型

每次只选一种。四种问法共用同一份资料，输出重点不同；课堂演示可优先选「字段挖掘」或「对接说明」，英文文档可先做「中文翻译」：

| 任务类型 | 重点输出 |
|---|---|
| 解释接口 | 这个接口做什么、服务哪个单据、何时会用、关键必传参数、返回核心信息、状态/错误码、仍待确认什么 |
| 字段挖掘 | 请求/返回字段清单：位置、类型、是否必传、枚举、文档描述、与页面字段可能的对应关系 |
| 中文翻译 | 把接口名称、参数说明、返回说明、错误信息译成中文；路径、字段名、枚举值、错误码、JSON结构保持原文 |
| 对接说明 | 鉴权、调用顺序、必传参数、请求/返回示例、回调、重试或幂等、错误码、联调待确认问题 |

约束：

- 字段挖掘时：接口有、页面未见的字段，只写「接口中出现，页面对应关系待确认」
- 中文翻译时：不为了通顺改字段名；歧义处保留原文并标「译义待确认」
- 对接说明时：文档没写调用顺序或回调，就写「未说明」，不要补流程

## 三、证据规则

每条关键结论标来源（接口名、方法路径、字段或章节），并区分：

1. `文档明确写出`
2. `基于接口结构的初步判断`
3. `待确认`

接口存在 ≠ 页面一定有该功能；返回字段 ≠ 已确认的后台业务规则。

## 四、输出

```text
<输出目录>/05-接口专项整理/<目标模块或单据>-<任务类型>.md
```

按任务类型组织正文，不要四种内容各写一遍。公用骨架如下：

```markdown
# <目标模块或单据> · <任务类型>

## 分析范围
- 接口文档来源：
- 目标模块或单据：
- 任务类型：
- 实际阅读范围：

## 结论
用简短文字写本次最重要的发现。

## 正文
（按上方任务类型表格展开；字段类优先用表）

## 待确认问题
| 问题 | 涉及接口或字段 | 需要补充的证据 |

## 可沉淀内容
可进入模块知识、对接说明或后续PRD上下文的条目。
```

## 五、交付前检查

1. 是否只覆盖目标模块或单据？
2. 是否区分了文档事实、结构推断和待确认？
3. 翻译是否未改动路径、字段名、枚举和代码？
4. 是否没有发接口请求，也没有把接口能力写成已确认页面功能？
