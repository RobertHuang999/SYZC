# 第3个提示词：整理模块级结果

请读取第2步的页面记录，整理为目标模块的结构化摸排结果。

本阶段不重新打开浏览器，不重新采集页面，不补写材料里没有的业务规则。有第1步页面地图时优先用来对齐`pageId`；没有地图也可以只依据页面记录整理。

## 一、输入

```text
目标模块或页面大类：<例如：入库模块>
页面采集目录：<系统采集>/02-页面采集/<目标范围>/
页面地图：<可选><系统采集>/01-系统菜单与页面地图.json
输出目录：<系统采集>
```

没有页面地图时，菜单路径、页面ID或URL缺失处写「未提供」。页面记录不足时，列入待确认清单，不要回头再抓页面。

## 二、整理原则

1. 页面记录是原始证据，整理结论不能超出材料能证明的范围。
2. 每条关键结论标明来源：至少写出`pageId`、记录文件和对应章节。
3. 证据状态区分：
   - `已观察`：记录里直接看到；
   - `候选`：跨页面归纳、尚未验证；
   - `待确认`：材料不足或说法冲突。
4. 同名字段、状态或操作有差异时，并列保留，不要静默合并。
5. 「页面上没出现」不等于「系统不存在」；按钮名称不等于完整业务规则。
6. 不要逐页复述原文，重点整理页面之间、字段之间、单据状态之间的关系。

## 三、整理内容

### 1. 页面功能矩阵

每个页面的可见用途、关键输入、关键输出、主要操作和关联入口。用途说不清就写「待确认」。

### 2. 字段字典

合并同模块重复字段，保留所属页面、位置、展示形式、必填或可见条件、选项。  
「材料中的说明」只抄记录里已有的描述或备注；没有就写「未提供」，不要自行解释业务含义。说不清的列入待确认。

### 3. 单据与状态

只整理材料里实际出现的单据、对象、状态和操作：

- 哪些页面涉及同一单据或对象；
- 当前看到哪些状态；
- 各状态下可见哪些操作；
- 页面之间已观察到的关联；
- 哪些流转关系只是候选。

可用表格或Mermaid，但必须区分`已观察`和`候选`，不要为了完整补画状态机。

### 4. 待确认清单

汇总字段含义、状态条件、按钮权限、页面关联、前置条件、角色或租户差异等问题，并写上来源和建议补充材料。

## 四、输出

```text
<系统采集>/03-模块整理/
  <目标范围>-页面功能矩阵.md
  <目标范围>-字段字典.md
  <目标范围>-单据与状态整理.md
  <目标范围>-待确认清单.md
```

文件名中的斜杠、冒号等替换为短横线。

### 1. 页面功能矩阵

```markdown
# <目标范围>页面功能矩阵

## 整理范围
- 页面采集目录：
- 页面地图：有 / 无
- 页面数量：

| 页面ID | 页面名称 | 类型 | 页面可见用途 | 关键输入 | 关键输出或列表列 | 主要操作 | 关联页面或单据 | 来源与证据状态 |
```

### 2. 字段字典

```markdown
# <目标范围>字段字典

| 字段名 | 所属页面 | 所在区域 | 展示形式 | 必填或可见条件 | 可见选项或状态 | 材料中的说明 | 来源与证据状态 |

## 字段差异
同名字段在不同页面中的展示、选项或说明差异。
```

### 3. 单据与状态整理

```markdown
# <目标范围>单据与状态整理

## 单据或对象范围
| 单据或对象 | 涉及页面 | 页面上观察到的用途 | 来源与证据状态 |

## 已观察到的状态和操作
| 单据或对象 | 状态 | 出现页面 | 当前可见操作 | 关联页面 | 来源与证据状态 |

## 状态关系
只画材料能支持的关系。无法确认的标为候选或待确认，并说明依据和缺口。

## 尚未确认的状态条件
```

### 4. 待确认清单

```markdown
# <目标范围>待确认清单

| 编号 | 待确认问题 | 涉及页面、字段或状态 | 当前依据 | 为什么无法确认 | 建议补充的材料 | 优先级 |

## 已发现的材料矛盾
列出冲突，不要自行裁决。

## 下一步建议
只基于当前缺口提出，例如补读接口、确认角色权限或询问业务同事；不编造具体人员或规则。
```

## 五、交付前检查

1. 是否只用了页面地图和页面记录中的内容？
2. 页面、字段、状态、操作是否都能追溯到来源？
3. 是否区分了`已观察`、`候选`、`待确认`？
4. 是否保留了同名字段或操作的页面差异？
5. 是否没有把按钮名、页面名直接写成业务结论？
6. 四份文档中的页面数、字段名、状态名是否基本一致？

完成后，这批模块文档即可用于写PRD、和研发沟通，或继续沉淀进知识宝典。有新页面或新版本时，在保留原始记录的前提下增量维护，不要另起一套平行文档。
