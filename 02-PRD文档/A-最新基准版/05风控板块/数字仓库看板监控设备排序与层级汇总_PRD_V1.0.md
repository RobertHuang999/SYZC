## 一、概述（为什么做）

### 1.1 产品概述及目标

#### 1.1.1 背景介绍
在供应链金融存货监管中，“数字仓库大屏/看板”是风控与运营人员监控全辖区仓库物联网（IoT）设备覆盖率、物权安全及设备健康度的核心决策中枢。
由于仓储实际业务场景的复杂性，物联网设备（包括 AI 摄像枪机、球机、地磅摄像头、温湿度传感器、RFID 读写器、边缘网关等）支持绑定在不同的空间层级上：
- **仓库层级**（如：大门门禁、进出库地磅摄像头）
- **库房层级**（如：1号库房内部高位球机）
- **分区层级**（如：A区3号货架温湿度传感器）

在现有看板实现中，统计逻辑仅按“单层精确匹配”（仅统计直接绑定在仓库根节点的设备数量）。这种做法忽视了树状拓扑下“库房”与“分区”下属设备的汇总，导致下辖数十台监控设备的仓库因为根节点未绑定设备而被误算为 `设备数 = 0`，从而在看板中被判定为“无监控”并排在末尾，造成看板数据严重失真，无法满足供应链金融的资产监管合规要求。

#### 1.1.2 产品概述
本功能重新设计了数字仓库看板的**“设备层级卷算 (Rollup Aggregation)”**与**“复合排序算法”**：
1. **全级汇总卷算 (Rollup)**：打通“仓库 ➔ 库房 ➔ 分区”树状空间拓扑，每个仓库的设备统计不仅包含仓库直属设备，还向上穿透汇总其辖下所有库房与分区的设备。
2. **重构监控判定与排序**：以“全级汇总设备数 (`total_rollup_device_count > 0`)”作为该仓库是否属于“有监控仓库”的唯一判定标准，实施四级复合排序规则，确保“有监控的仓库优先置顶”。
3. **UX 视图重构**：看板卡片展示“汇总总数大字 + 层级拆解明细”，支持用户悬浮查看分布及一键下钻。

#### 1.1.3 产品目标

**业务目标**
| 目标 | 指标 | 目标值 | 达成时间 |
|---|---|---|---|
| 提高看板监控数据准确率 | 仓库设备总数与拓扑下属设备一致率 | 100% 准确汇总 | 上线后立即生效 |
| 优化监控仓库置顶排序 | 有监控仓库排在前面的准确率 | 100% 优先置顶 | 上线后立即生效 |
| 降低风控误判率 | 因设备统计不准引发的风控告警误判 | 降低 95% | 上线后 1 个月 |

**用户目标**
| 目标用户 | 用户目标 | 衡量指标 |
|---|---|---|
| 平台风控专员 / 金融资金方 | 在看板上一目了然看到真正拥有监控的仓库排名，快速识别无监控裸奔仓库 | 看板首屏 1 秒识别风险仓库 |
| 仓库运营主管 | 清楚查看仓库辖下各库房、分区的设备分布明细 | 卡片支持层级拆解与下钻查看 |

### 1.2 名词说明

| 名词 | 说明 |
|---|---|
| 空间拓扑 (Spatial Topology) | 仓储物理空间的树状结构：仓库 (Warehouse) ➔ 库房 (Storehouse) ➔ 分区 (Zone)。 |
| 直属设备 (Direct Devices) | 直接绑定在当前空间节点（如仓库根节点）上的设备。 |
| 全级汇总设备数 (`total_rollup_device_count`) | 当前仓库根节点 + 下属所有库房 + 下属所有分区绑定的设备总数。 |
| 有监控仓库 (`is_monitored`) | 布尔标记：当 `total_rollup_device_count > 0` 时判定为 `true`，优先置顶。 |
| 全路径编码 (`tree_path`) | 空间拓扑表中的物化路径（如 `/1/10/100/`），用于实现高性能 SQL 卷算。 |

### 2.2 复合排序算法规则矩阵 (Sorting Matrix)

看板仓库卡片/列表渲染时，系统强制执行以下**四级复合排序规则**：

| 排序优先级 | 排序字段 / 判定条件 | 排序方向 | 规则说明 |
|---|---|---|---|
| **第一优先级 (主排序)** | `is_monitored` | **DESC** (降序) | **有监控仓库 (`true`) 强制置顶**；无监控仓库 (`false`) 排在末尾 |
| **第二优先级 (次排序)** | `total_rollup_device_count` | **DESC** (降序) | 同样有监控时，**全级汇总设备总数**多的仓库排在前面 |
| **第三优先级 (辅排序)** | `online_rate` (在线率) | **DESC** (降序) | 设备总数相同，设备在线率高（设备健康度好）的排在前面 |
| **第四优先级 (托底排序)** | `warehouse_code` / `created_at` | **ASC** (升序) | 前三项均相同时，按仓库编码升序排列托底 |

## 三、功能需求（怎么做）

### 3.1 树状空间拓扑全级卷算 (Rollup) 机制

1. **物化全路径 (Materialized Path) 建模**：
   - 空间拓扑表 `sys_spatial_node` 存储 `tree_path` 字段。
   - 示例：仓库 A (`/1/`) ➔ 库房 A1 (`/1/10/`) ➔ 分区 A1-1 (`/1/10/100/`)。
2. **卷算范围涵盖规则**：
   - 当计算仓库 A 的 `total_rollup_device_count` 时，后端查询条件为：
     `WHERE tree_path LIKE '/1/%' AND device_status != 'DELETED'`
   - 自动包含：仓库 A 直属设备 + 库房 A1 直属设备 + 分区 A1-1 直属设备。

## 四、非风控与非功能需求

### 4.1 性能与响应要求
- **看板加载时延**：即使全辖区有 50 个仓库、200 个库房、1000 个分区、5000 台设备，看板 API 响应时间必须 `< 300ms`。
- **预计算/缓存机制**：基于 Redis 缓存全级卷算结果，当有新设备绑定/解绑/离线时，异步触发 Redis Hash 缓存刷新。

### 4.2 数据一致性
- 设备在库房或分区重新绑定/变更位置后，父级仓库的 `total_rollup_device_count` 必须在 3 秒内完成自动重新重算与看板同步。

## 五、附录

### 5.1 验收标准与测试要点

1. **下属设备卷算测试**：
   - 建立一个仓库 A，根节点不绑定任何设备（直属设备 = 0）。
   - 在其下属的 1号库房绑定 5 台摄像头，A区分区绑定 3 台传感器。
   - 验证看板中该仓库显示设备总数 = 8 台，且 `is_monitored = true`。
2. **排序位置校验测试**：
   - 验证设备总数为 8 台的仓库 A 成功排在没有任何设备（总数 = 0）的仓库 B 前面。
3. **明细拆解展示测试**：
   - 悬浮卡片，验证能准确区分直属 (0台)、库房 (5台)、分区 (3台) 的明细。

| 序号 | 待确认事项 | 影响范围 | 默认建议值 |

| 1 | 处于“离线”状态的设备是否计入 `total_rollup_device_count`？ | 监控判定 | 建议计入总数（表示有硬件安装），但在线率下降，排在同设备数的全在线仓库之后 |
