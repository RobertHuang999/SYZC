# 入库管理主PRD（B端H5）

> **端**：B端H5（移动机构端）  
> **moduleId**：`ws-inbound-mgr`（工作台 · 入库记录）、`biz-init-inbound`（业务办理 · 入库发起）  
> **菜单路径**：工作台 → 仓储 → 入库管理；业务办理 → 业务发起 → 入库发起  
> **原型路由**：`/m/workspace/inbound-records` · `/m/inbound/initiate` · `/m/inbound/initiate/goods` · `/m/workspace/inbound-records/:id`  
> **PC 对照**：[B端PC 入库记录](../../../../B端PC/02-仓储/09-入库管理-入库记录/入库记录主PRD.md)  
> **编写依据**：[入库管理字段清单.md](./入库管理字段清单.md) · [入库管理业务规则规格.md](./入库管理业务规则规格.md)  
> **跨端规则真源**：单据状态、未堆放清零 R13、库房同审核属性 R06、新货主核验 R03、影像 R16/R18 等与 PC 入库记录共用编号，本文件仅定义 **移动端页面、步骤与交互差异**。

---

## 1. 业务背景与移动端定位

移动端承担现场收货、理货堆放与入库申请发起，对齐现网 `wrl-agency-native` 入库单填写与入库详情能力。监管员在库区完成货主确认、多货品多库位分配、现场拍照后提交审批；在工作台查阅本人及权限范围内入库流水（含审核中/已通过/未通过/已撤销），与 PC「入库记录」已通过台账形成 **全状态移动视图 + PC 归档视图** 互补。

## 3. 页面功能说明

### 3.1 入库管理列表（`P-H5-INBOUND-LIST`）

- **路径**：`/m/workspace/inbound-records`  
- **入口**：工作台 → 仓储 → 入库管理（`ws-inbound-mgr`）  
- **布局**：顶栏标题 + 审核状态下拉 + 搜索框；卡片列表（单号、货主、类型、仓库、货品摘要、数量、状态 Badge）；右下角悬浮【入库】。  
- **数据范围**：当前登录账号仓库数据权限；列表展示 **全流转状态**（与 PC 列表仅已通过不同）。  
- **行操作**：点击卡片进入详情；无列表内编辑。

### 3.2 入库发起（`P-H5-INBOUND-INIT`）

- **路径**：`/m/inbound/initiate`（基础信息）→ `/m/inbound/initiate/goods`（货品明细）；对齐 native `warehousing-order.vue` + `warehousing-details.vue`。  
- **入口**：业务办理 → 入库发起（`biz-init-inbound`）；或列表页悬浮【入库】。  
- **步骤条**：① 基础信息 → ② 货品明细（与 native `step-list` 默认两步一致）。  
- **步骤 0 · 基础信息（单页）**：**货主信息**卡片：货主类型（企业/个人）、货主名称搜索、货主标识、个人身份证号或企业联系电话；企业支持 OCR Mock。**入库信息**卡片：入库日期、入库类型（普通/质押/抵押/监管服务/仓单）、关联单号（非普通入库）、入库仓库、入库库房（多选且同审核属性 R06）、备注（最多 140 字，字数计数）。页内橙色【下一步】，校验通过后写入会话并进入步骤 1。  
- **步骤 1 · 货品明细**：合计信息 +【添加货物】；每卡片含大类/品类/规格联动、计量参数与单位、未堆放数量实时试算、【+ 添加位置】库房/分区/具体位置/堆放数量、现场照片（必填 1~10）、补充资料。底栏【上一步】【提交审核】；触发 R13、R16、R03 校验（无单独确认步）。  
- **底栏汇总（步骤 1）**：货品品类数、货品总数量、堆放总数量（与 PC 新增页统计口径一致）。

### 3.3 入库详情（`P-H5-INBOUND-DETAIL`）

- **路径**：`/m/workspace/inbound-records/:id`  
- **布局**：单号 + 状态章、制单信息、货主/日期/类型/仓库；Tab【入库明细】【审核记录】；已通过展示二维码 Mock；附件含现场照片与 **IoT 设备抓拍**（R18）。  
- **审核中**：底部【撤销申请】；未通过/已撤销只读追溯。

---

## 4. 状态与权限摘要

移动端列表可见 `审核中`、`已通过`、`未通过`、`已撤销`；详情状态章文案与 PC 内部编码一致。撤销仅制单人在审批完成前可操作。规则详见 [入库管理业务规则规格.md](./入库管理业务规则规格.md)。

---

## 5. 验收要点

1. 双入口（工作台列表、业务办理发起）路由与菜单 `customRoute` 可达。  
2. 发起页两步可完整走通，未堆放大于 0 时提交阻断并提示 R13。  
3. 新货主名称不在建档集合时，提交前弹出短信核验（Mock 验证码 123456）。  
4. 详情页展示至少 1 条 IoT 抓拍与审核时间轴。  
5. 原型挂载本目录三件套，规则 ID 与 PC 入库记录规格一致。
