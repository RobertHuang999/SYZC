# 设备事务通知配置字段清单

> **文档定位**：设备事务通知配置页面所有业务字段和系统字段的唯一定义来源。业务流程、业务规则、原型及接口设计引用本文件的字段口径，不重复定义字段规则。
>
> **引用规则**：下游引用设备事务通知配置字段时，标注“继承自设备事务通知配置”；设备主数据、在线状态、资产分类以设备管理所属模块定义为准。
>
> **修改原则**：字段定义变化只修改本文件，并同步更新版本和修订记录。历史规则补充后，业务流程与业务规则规格只引用本文件，不在正文重复维护字段定义。
>
> **版本**：V1.0 | 更新时间：2026-08-18
>
> **页面范围**：当前版本仅覆盖设备事务通知配置的查询区、列表页、新增页、编辑页和详情展示字段；通知信息由独立的设备事务通知管理页面负责展示。

## 0. 字段层级说明

本文件将字段分为基础识别字段、事务控制与设备配置字段、通知配置字段和系统字段：

1. **基础识别字段**：定义事务通知规则的基础识别信息，包含列表展示、规则名称与事务类型。
2. **事务控制与设备配置字段**：定义具体事务类型（开锁、关锁、上线、移除）的触发条件、设备范围限制（在线限制、新设备继承等）及关联选取的设备列表。
3. **通知配置字段**：定义事务通知方式（邮件、短信）及通知人员。
4. **系统字段**：由系统生成或维护，用户不直接编辑。

> **状态管理设计意图**：事务通知规则状态为“启用/停用”，属于人工控制的事件即时推送开关，支持管理员或操作人随时启用/停用；区别于订单/设备预警跟随业务对象生命周期自动“生效中/已失效”的被动流转模型。

“操作”属于列表交互列，不作为业务字段；详情、新增、编辑、停用、删除及状态流转的权限、前置条件和后置影响，统一由业务流程和业务规则规格定义。

## 二、数据模型与事务控制字段

### 1. 数据模型

事务通知配置采用“一条主规则 + 多条事务类型明细”模型：

| 数据层级 | 保存内容 | 说明 |
| :--- | :--- | :--- |
| 主规则 | 规则名称、通知渠道、发件人、抄送对象、通知对象、状态及审计字段 | 一条页面配置对应一条主规则；主规则停用或删除后，其全部事务类型明细停止匹配后续事件 |
| 事务类型明细 | 事务类型（单选）、关联设备或“针对新设备”标记及专属条件 | 一条主规则下可添加多条事务明细；**每条明细内“事务类型”为单选**；同一主规则内以及同一租户下，每条明细的【事务类型 + 设备/设备类型】配置必须唯一，不能重复 |

### 2. 事务触发与设备选择字段

> 在主规则下添加事务明细时，**每条明细单选一个“事务类型”**，并联动配置其对应的【选择设备】或【针对新设备】：
> - **开锁通知 / 关锁通知**：【选择设备】仅可选择“在线”状态的智能挂锁或人脸门禁（离线不可选，无新设备选项）；
> - **设备上线**：可勾选【针对新设备】（选择适用设备大类，隐藏具体设备选择）；未勾选则在【选择设备】中多选物联/监控/门锁/GPS设备（在线与离线均可选）；
> - **设备移除**：在【选择设备】中多选物联/监控/门锁/GPS设备（在线与离线均可选，无新设备选项）。

## 五、展示与引用规则

- 列表字段展示顺序：序号、事务通知规则名称、事务类型、关联设备摘要、状态、创建人、创建时间、更新人、更新时间、操作。
- 当前已确认的筛选字段：事务通知规则名称（模糊匹配）、事务类型（多选精确匹配）、事务规则状态（多选精确匹配）。
- `事务类型`是动态表单与设备选择范围的核心控制字段：
  - 选择“开锁通知/关锁通知”：仅展示【智能挂锁、人脸门禁】设备候选列表，且候选设备状态必须为“在线”；
  - 选择“设备上线”：先选择设备类型（物联、监控、门锁、GPS），可勾选【针对新设备】（勾选后隐藏设备选择；未勾选时从该类型在线/离线设备中多选）；
  - 选择“设备移除”：先选择设备类型（物联、监控、门锁、GPS），直接选择具体设备（多选，在线/离线设备均可；无针对新设备选项）。
- `针对新设备`继承逻辑：**仅适用于“设备上线”事务类型**；启用该选项后，系统在后续录入/绑定同类型新设备时，自动将新设备 ID 挂载至本条规则的生效设备集合中，无需人工再次编辑配置。
- 涉及事务通知配置、关联设备、通知对象和规则状态变更的写入操作，应采用服务端版本校验、防并发锁机制，并记录操作前后数据版本。
