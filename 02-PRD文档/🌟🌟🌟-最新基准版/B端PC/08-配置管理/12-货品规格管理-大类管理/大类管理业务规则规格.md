## 一、模块与单据定位

| 项目 | 内容 |
| :--- | :--- |

## 二、状态定义与计算

| 状态名称 | 字段与枚举 (`status`) | 是否可直接修改 | 含义说明 | 影响范围 |
| :--- | :--- | :---: | :--- | :--- |
| **启用** | `ENABLED` | 是 | 大类当前处于正常可用状态 | 允许下级新增品类、货品，下级计算有效状态时满足父级启用条件 |
| **停用** | `DISABLED` | 是 | 大类当前处于停用管控状态 | 级联停用所有下属品类和货品；下游新增业务单据禁止选择该大类及下属货品；历史数据保留 |
| **已删除** | `is_deleted = 1` | 否 | 逻辑删除标记，前台不可见 | 仅停用且整棵子树无入库单时允许触发；不可物理恢复 |

## 三、状态流转表（核心规则矩阵）

| 当前状态 | 触发动作 | 前置校验条件 | 结果状态 | 二次确认弹窗 | 后置级联影响 | 失败阻断提示 (Toast/Modal) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 未创建 | 新建保存 | ① 大类名称必填（≤20字）<br/>② 租户内大类名称唯一 | 启用 | 无 | 自动留痕创建人、创建时间，生成大类记录 | Toast: 「大类名称已存在，请重新输入」 |
| 启用/停用 | 编辑保存 | ① 大类名称必填且租户内唯一<br/>② **入库数据强校验**：整棵子树无入库单数据 | 保持原状态 | 无 | 更新大类名称、更新时间戳 | 弹窗阻断: 「该大类已有业务数据产生，不可编辑！」 |
| 启用 | 停用 | 具备配置维护/管理员权限 | 停用 | 弹窗: 「停用后后续新增品类无法选择，但历史已产生数据不受影响」 | ① 当前大类置为停用<br/>② **保存下级当前状态快照**<br/>③ 事务内级联停用该大类下所有品类和货品<br/>④ 更新更新时间 | Toast: 「停用失败，请稍后重试」 |
| 停用 | 启用 | 具备配置维护/管理员权限 | 启用 | 无（或标准确认） | ① 当前大类置为启用<br/>② **按快照恢复下级状态**：仅恢复停用前处于“启用”的品类与货品，不得强制激活原本处于“停用”的下级<br/>③ 更新更新时间 | Toast: 「启用失败，请稍后重试」 |
| 启用 | 删除 | 无 | 阻断 | 弹窗提示 | 不允许操作，大类保持启用 | 弹窗阻断: 「启用状态下的【大类/品类/货品】不可删除，请先停用。」 |
| 停用 | 删除 | **子树无入库单强校验**：扫描大类及全部下属品类、货品，均不存在入库单数据 | 已删除 (`is_deleted=1`) | 弹窗: 「删除后将一并删除下属品类和货品，且不可恢复！」 | 事务内将该大类及整棵子树的品类、货品全部执行逻辑删除，前台列表与选择器不再可见 | 弹窗阻断: 「该大类或其下级已有入库业务数据，不可删除！」 |

## 四、核心业务规则（R01 ~ R06）

### R-CAT-01：租户隔离与名称唯一性
- 大类名称长度限制在 1~20 个字符，去除首尾空格；
- 同一租户下大类名称严格唯一（不区分大小写比较）；不同租户间互不干扰。
- 数据库底层必须建立 `(tenant_id, category_name, is_deleted)` 唯一索引兜底。

### R-CAT-02：父级停用级联下发规则
- 当大类执行停用操作时，系统后台必须在开启事务的同时，生成该大类下属品类和货品的**当前自身状态快照**；
- 级联将该大类及其下所有品类、货品的状态批量更新为 `DISABLED`；
- 必须保证事务一致性，若其中任一子节点更新失败，整体事务回滚，禁止出现“父级停用而部分子级仍为启用”的不一致状态。

### R-CAT-03：父级启用快照恢复规则
- 当停用的大类被重新启用时，系统不得盲目将所有子级置为启用；
- 系统必须读取停用时保存的状态快照，仅将原本处于启用状态的品类和货品恢复为启用；原本主动停用的品类或货品继续保持停用状态。

### R-CAT-04：编辑操作入库单拦截规则
- 编辑大类名称时，服务端必须实时执行入库单数据扫描：
  - 查询条件：`SELECT COUNT(1) FROM wms_inbound_order_detail WHERE category_id = :categoryId AND is_deleted = 0`；
  - 若计数 $> 0$，立即阻断保存并返回特定业务拦截码，前端唤起统一阻断弹窗；
  - 严禁仅依赖前端缓存状态进行判断。

### R-CAT-05：删除两阶段强校验与级联逻辑删除
- **阶段一（状态校验）**：大类状态为 `ENABLED` 时直接拦截，必须先停用；
- **阶段二（入库单扫描）**：大类状态为 `DISABLED` 时，系统扫描整棵子树（大类、品类、货品）是否被任何已提交或草稿状态的入库单引用：
  - 若存在任何入库数据，强阻断删除；
  - 若完全无入库数据，经用户二次确认后，在同一事务内对该大类、下属所有品类、下属所有货品执行逻辑删除更新（`is_deleted = 1`）。
- 系统当前不支持逻辑删除恢复，需在提示中向用户明确说明。

### R-CAT-06：并发控制与幂等性
- 大类的新建、编辑、启停、删除均需采用乐观锁机制（基于 `version` 字段或更新时间戳 `updated_at`）；
- 若两人同时操作导致版本冲突，后提交者请求被拒绝并提示「数据已被他人修改，请刷新后重试」；
- 重复提交的相同请求通过幂等校验机制保障不重复写日志和状态。

## 五、权限与风控约束

| 角色 | 查看大类列表 | 新建/编辑大类 | 启用/停用大类 | 删除大类 | 数据范围 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **系统管理员** | ✅ | ✅ | ✅ | ✅ | 当前租户全量 |
| **配置维护人员** | ✅ | ✅ | ✅ | ✅ | 当前租户全量 |
| **风控管理人员** | ✅ | ❌ | ❌ | ❌ | 当前租户全量（只读） |
| **业务人员/只读用户** | ✅ | ❌ | ❌ | ❌ | 当前租户全量（只读） |

- **接口安全**：所有服务端接口必须强校验租户上下文，禁止任何跨租户越权查询与修改。

## 六、核心业务流程图

```mermaid
flowchart TD
    Start([用户操作大类管理]) --> OpType{操作类型}

    %% 1. 新建大类分支
    OpType -- 新建大类 --> InputCat[输入大类名称]
    InputCat --> CheckName{租户内名称唯一?}
    CheckName -- 重名 --> ToastErr1[Toast: 大类名称已存在，请重新输入] --> InputCat
    CheckName -- 唯一 --> SaveCat[保存大类主档<br/>状态默认：启用] --> End([完成])

    %% 2. 编辑大类分支
    OpType -- 编辑大类 --> CheckInboundEdit{后台扫描子树<br/>是否存在入库单?}
    CheckInboundEdit -- 存在入库单 --> ModalBlockEdit[弹出阻断弹窗<br/>该大类已有业务数据产生，不可编辑！] --> End
    CheckInboundEdit -- 无入库单 --> EditCatName[输入新名称并校验唯一性]
    EditCatName --> SaveEdit[更新大类信息并留痕] --> End

    %% 3. 启停用大类分支
    OpType -- 启用/停用大类 --> StatusJudge{当前大类状态}
    StatusJudge -- 当前为启用 --> ConfirmDisable[弹出停用确认提示]
    ConfirmDisable --> DoDisable[保存下级状态快照<br/>事务内级联停用大类及全部品类/货品] --> End
    StatusJudge -- 当前为停用 --> ConfirmEnable[确认启用大类]
    ConfirmEnable --> DoEnable[大类置为启用<br/>按快照级联恢复原启用下级节点] --> End

    %% 4. 删除大类分支
    OpType -- 删除大类 --> Phase1{阶段一: 自身状态校验}
    Phase1 -- 状态为启用 --> BlockEnableDel[弹出提示弹窗<br/>启用状态下的【大类/品类/货品】不可删除，请先停用。] --> End
    Phase1 -- 状态为停用 --> Phase2{阶段二: 后台扫描整棵子树<br/>是否存在入库单?}
    Phase2 -- 存在入库单 --> BlockInboundDel[弹出拦截弹窗<br/>该大类或其下级已有入库业务数据，不可删除！] --> End
    Phase2 -- 无入库单 --> ConfirmDelModal[弹出二次确认删除弹窗<br/>删除后将一并删除下属品类和货品，且不可恢复！]
    ConfirmDelModal -- 点击取消 --> End
    ConfirmDelModal -- 点击确定 --> CascadeDel[事务内执行逻辑删除 is_deleted=1<br/>大类及下属品类货品全部移除] --> End
```

## 七、操作时序图

### 1. 大类状态级联启停时序

```mermaid
sequenceDiagram
    autonumber
    actor U as 维护人员
    participant F as 前端界面
    participant B as 货品大类服务
    participant DB as 数据库

    U->>F: 点击【停用】或【启用】
    F->>B: 提交大类ID、目标状态与版本号
    B->>DB: 校验租户上下文、权限与大类当前状态
    alt 停用大类
        B->>DB: 保存下属品类及货品当前状态快照
        B->>DB: 事务内批量更新大类及下属所有品类/货品 status = DISABLED
    else 启用大类
        B->>DB: 查询下属品类及货品停用前快照
        B->>DB: 事务内更新大类 status = ENABLED，恢复快照为启用状态的下级节点
    end
    B->>DB: 记录审计日志与更新时间戳
    DB-->>B: 提交事务成功
    B-->>F: 返回操作结果
    F-->>U: Toast提示成功并刷新大类列表
```

### 2. 大类两阶段删除时序

```mermaid
sequenceDiagram
    autonumber
    actor U as 维护人员
    participant F as 前端界面
    participant B as 货品大类服务
    participant W as WMS入库服务
    participant DB as 数据库

    U->>F: 点击行操作【删除】
    F->>B: 提交大类ID
    B->>DB: 检查大类自身状态
    alt 状态为 ENABLED（启用）
        B-->>F: 返回状态错误（启用不可删）
        F-->>U: 弹窗提示「启用状态下的【大类/品类/货品】不可删除，请先停用。」
    else 状态为 DISABLED（停用）
        B->>W: 扫描大类ID及整棵子树下属品类/货品入库单引用计数
        W-->>B: 返回入库单引用计数
        alt 引用计数 > 0
            B-->>F: 返回存在业务数据阻断
            F-->>U: 弹窗提示「该大类或其下级已有入库业务数据，不可删除！」
        else 引用计数 == 0
            B-->>F: 返回允许删除校验通过
            F-->>U: 弹出二次确认弹窗「删除后将一并删除下属品类和货品，且不可恢复！」
            U->>F: 点击【确定】
            F->>B: 提交执行删除请求
            B->>DB: 开启事务，执行大类、下属品类及货品 is_deleted = 1 逻辑删除
            B->>DB: 写入删除操作审计日志
            DB-->>B: 事务提交成功
            B-->>F: 返回删除成功
            F-->>U: Toast「删除成功」并刷新大类列表
        end
    end
```
