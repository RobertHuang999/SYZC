# 人脸配置字段清单

> **文档定位**：人脸配置所有字段的唯一定义来源。下游需求文档、原型和关联功能只引用字段名称，不重复定义字段规则。
>
> **引用规则**：下游需要引用人脸配置字段时，标注“继承自人脸配置”；需要保留账号、人脸及门禁配置历史信息时，标注“快照字段”。
>
> **修改原则**：字段定义变化只修改本文件，并同步更新版本和修订记录。
>
> **版本**：V1.5 | 更新时间：2026-08-14
>
> **页面范围**：当前版本涉及人脸配置筛选区、列表页、人脸照片和开锁密码编辑页、菜单全局按钮、分配门禁页、进度记录列表及详情、门禁数据列表和移除确认弹窗；新增页暂不纳入本字段清单。

## 0. 对象层级说明

本文件是独立的“人脸配置与门禁授权”字段清单，不是门禁设备主数据的字段子表。门禁设备的“人脸配置”按钮只提供当前设备上下文；人脸照片、开锁密码、人员授权、批量分配和下发进度等字段由本文件统一维护。

## 三、展示与引用规则

- 列表业务字段展示顺序：序号、人脸照片、账号名称、账号、角色、归属机构、账号状态、人脸状态、开锁密码、门禁数据。
- 筛选字段：账号名称（输入框模糊匹配）、人脸状态（下拉精确匹配）、开锁密码（下拉精确匹配）。查询接口使用字段原始值或枚举值，不使用格式化后的展示文本作为查询条件。
- 列表仅返回账号状态为“启用”的账号；账号停用、账号删除或当前用户无权访问时，应从列表结果中排除，并同步阻断对应配置操作。
- **账号状态变更联动（后置影响规则）**：当人员账号在系统【账号/组织管理】模块被停用或删除时，系统自动触发后台异步任务，向该账号所有已绑定的门禁设备下发出库/删除凭证（人脸及开锁密码）指令，实现线下门禁鉴权与系统账号状态的物理联动闭环（此前系统设计遗漏，本版本补充闭环）。
- “操作”属于列表交互列，不作为业务数据字段。当前行操作包括：上传人脸、分配门禁、移除门禁；操作展示条件和顺序见下方“行操作规则”。
- 人脸照片保存成功后才可展示“已录入”；开锁密码保存成功后才可展示“已录入”；门禁数据按当前有效分配关系汇总，不由前端手工维护，点击数量可查看已分配的门禁列表。
- 账号、角色、归属机构和账号状态引用账号、权限及组织模块数据。本页不提供这些字段的新增或编辑能力，源数据变化后以重新查询结果为准。
- 当前资料未确认真实字段编码、人脸状态枚举编码及门禁数量统计接口；门禁设备“状态”字段及“设备状态”筛选项均引用门禁设备字段清单中的同一实时字段。确认前下游文档以中文字段名称引用，不自行固化英文属性名。照片格式、大小限制和开锁密码规则以本文件“人脸配置操作规则”为准。
- **门禁权限有效期说明（可优化项）**：当前版本人脸与开锁密码凭证分配为长期有效，三方底层接口支持授权有效期；在后期 PRD 迭代中记为可优化项，后续版本根据业务需要扩展凭证生效与失效时间控制。
- 人脸照片查看、照片上传/替换和开锁密码配置均需执行租户、机构、菜单及数据权限校验，并采用服务端状态校验、版本校验、锁或等效并发控制，避免账号状态变化或并发提交导致错误覆盖。

## 四、行操作规则

| 操作名称 | 触发入口 | 展示条件 | 当前规则状态 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| 上传人脸 | 列表“操作”列 | 账号状态为“启用”时展示；用于上传或维护人员人脸及开锁密码 | 已确认展示顺序 | 点击后进入“上传人脸”页面；页面展示账号名称、账号、角色、归属机构等基础信息，并提供人脸照片和开锁密码配置；具体权限和异常处理见下方规则 |
| 分配门禁 | 列表“操作”列 | 人脸状态为“已录入”或开锁密码为“已录入”时展示 | 已确认展示条件 | 必须先完成人脸照片或开锁密码任一凭证配置，才允许进入门禁分配；具体页面和提交规则见下方“分配门禁操作规则” |
| 移除门禁 | “门禁数据”列表操作列 | 仅当账号下已分配门禁，门禁数据数量大于0时展示 | 已确认页面规则 | 点击“移除”后弹出系统确认提示；确认后在当前页面同步处理，仅解除当前账号与门禁设备的关联，不影响设备主数据；在线、离线设备均允许移除；按钮不置灰，重复点击或并发冲突时限制请求并提示“请稍后再试”；成功提示“移除成功”，刷新门禁数据数量并立即隐藏该设备的“移除”按钮；移除失败回滚原关联关系 |

> 行操作展示顺序固定为：上传人脸、分配门禁、移除门禁。业务前置关系为：先完成人脸照片或开锁密码任一凭证配置，才展示分配门禁；账号存在已分配门禁后，才展示移除门禁。

| 页面区域 | 展示或交互规则 | 校验与结果 |

### 2. 提交与更新规则

| 场景 | 规则 |
| :--- | :--- |
| 首次配置成功 | 配置成功后返回人脸配置列表；列表刷新账号的人脸状态、开锁密码状态和门禁数据 |
| 已存在配置再次进入 | 页面回显已上传的人脸照片和已设置的开锁密码；人脸照片支持更换，开锁密码支持修改；若人员不再需要门禁权限，可在【账号管理】模块停用对应账号 |
| 密码重复 | 设置或修改密码时校验同一租户内密码唯一性（便于开锁日志精准识别具体开锁人员）；与其他用户密码重复时阻止提交并提示：“密码已存在，请重新设置” |
| 修改密码或照片 | 先向已绑定设备异步下发新凭证；所有目标设备下发成功后才保存新凭证并创建异步更新记录；任一目标设备失败则新凭证不保存，设备侧继续保留旧凭证，并在全局“查看进度”中记录失败原因 |
| 查看更新进度 | 提示“信息已更新，开锁信息更新中”后返回人脸配置列表；用户在列表页点击菜单全局“查看进度”按钮，查看开锁信息下发进度 |
| 部分更新 | 编辑提交采用增量更新模式；对于未修改的凭证项（如已有人脸图片未作更换、开锁密码未作修改），服务端保存时必须继承原镜像，严禁被空值覆盖 |

> 图片资料中已确认人脸图片和开锁密码字段均为非必填，但提交时至少一项完成；密码唯一性、异步下发和更新进度属于人脸配置操作规则，不改变字段表中的单字段“选填”属性。
