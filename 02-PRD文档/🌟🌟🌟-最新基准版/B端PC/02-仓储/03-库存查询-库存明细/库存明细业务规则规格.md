## 一、单据与能力定位

| 项目 | 内容 |
| :--- | :--- |
| **单据层级** | **【第2层-台账与执行明细层】**（仓储业务微观货位与批次管理底座 —— 物理存货明细台账） |
| **核心职责** | 最细粒度实现账面库存明细的精准查询与变动追溯。穿透到“仓库-库房-分区-具体垛位”，以存货条码为唯一锚点，实时区分“可用数量（未在流程中的数量）”与“冻结数量（处于审批流中的数量）”，并完整关联入库事实、现场照片与 IoT 抓拍凭证。 |
| **数据来源** | **入库堆放确权与流转动态更新**：<br/>1. **入库单生效归档**：入库单在多库位分配堆放成功并审核通过后，原子写入本台账，记录期初堆放数量与初始可用数量；<br/>2. **业务流程审批中**：发起出库、移库、质押、抵押、仓单、转让、异动、加工申请时，锁定对应货位的存货数量，将其从可用数量划拨至冻结数量；<br/>3. **业务执行终态**：出库核销出场扣减实物，移库调拨更新库位，质押生效更新货权状态。 |
| **上游依赖** | **存货管理 (P-CKG-001)**：接收宏观看板发起的【库存分布】穿透请求，根据触发视图执行仓库/货物/货主严格参数锁定；<br/>**入库管理 (P-CKG-009)**：继承入库单号、入库时间、制单人、入库类型、现场照片、补充材料及 IoT 设备抓拍图；<br/>**货品与仓库档案**：继承规格主档、计量单位及空间拓扑（仓库/库房/分区）。 |
| **下游影响** | **入库记录详情 (P-CKG-009-DETAIL)**：详情页入库单号提供【查看】直接穿透至原入库单据；<br/>**盘点与风控审计**：为现场 PDA 扫码盘点、动碰复核及金融监管现场稽核提供账实唯一的条码货位凭据。 |
| **权限隔离边界** | **【RBAC 仓库级与机构级双重隔离】**：基于当前登录用户的组织架构和分配的仓库权限，实时查询管辖范围内的数据，严禁越权查看未授权实体仓库的库存。 |

## 二、数量与堆放核算口径隔离表

| 口径名称 | 存在位置 | 业务含义与计算公式 | 约束与边界条件 |
| :--- | :--- | :--- | :--- |
| **期初堆放数量** | 列表列 / 详情页表格列 | 该批次货品在入库验收分配时，存放于该库房-分区-具体位置的初始实物数量 $Q_{\text{init}}$ | 数值 $> 0$，4 位小数；继承货品主档计量单位；入库归档后**不可篡改**；列表支持升降序排序 `▲▼` |
| **可用数量** | 列表列 / 详情页表格列 | 当前未处于任何审批流程中、可自由支配发起出库、质押、移库调拨的实际在库净额：<br/>$$Q_{\text{avail}} = Q_{\text{init}} - Q_{\text{out\_completed}} - Q_{\text{frozen}}$$ | 数值 $\ge 0$，4 位小数；业务口径：**未在流程中的数量**；带单位；列表支持升降序排序 `▲▼` |
| **冻结数量** | 列表列 / 详情页表格列 | 因正处于质押、抵押、出库、移库、仓单、转让、异动或加工审批流中被锁定的存货数量：<br/>$$Q_{\text{frozen}} = \sum Q_{\text{applying}}$$ | 数值 $\ge 0$，4 位小数；业务口径：**在流程申请中的数量**；带单位；列表支持升降序排序 `▲▼` |
| **存货条码** | 列表列 / 详情页表格列 | 该具体货位存货在入库审核通过时系统生成的全局唯一二维码/条形码资产凭据 | 点击二维码图标呼出居中弹窗，展示条码编号与二维码图形，支持现场扫码核验 |

## 三、存货状态机与冻结映射矩阵

> 本页面货品状态严格继承《存货管理》最新 18 项状态机，废弃原过期的“出库待核销”状态：

| 状态编码 | 状态名称 | 类别 | 可用数量归属 | 冻结数量归属 | 业务流转与出库控制 |
| :--- | :--- | :--- | :---: | :---: | :--- |
| `IN_STOCK` | **存货中** | 基准在库态 | ✅ 是 | ⚠️ 锁定转冻结 | 合并历史未分配/已分配二维码；允许发起出库、质押、移库、加工申请 |
| `PLEDGE_APPLY` | **质押申请中** | 审批流转态 | ❌ 0 | ✅ **100% 冻结** | 资方质押审核中，整批/申报量完全锁定，禁止出库或移库 |
| `PLEDGING` | **质押中** | 质押生效态 | ✅ 在押可用 | ⚠️ 质押出库转冻结 | 质押合同生效；若申请质押出库，被申报部分切入冻结池 |
| `MORT_APPLY` | **抵押申请中** | 审批流转态 | ❌ 0 | ✅ **100% 冻结** | 抵押审核中，申报量锁定，禁止其他操作 |
| `MORTGAGING` | **抵押中** | 抵押生效态 | ✅ 在押可用 | ⚠️ 抵押出库转冻结 | 抵押合同生效；若申请抵押出库，被申报部分切入冻结池 |
| `SUPERV_APPLY` | **监管申请中** | 审批流转态 | ❌ 0 | ✅ **100% 冻结** | 第三方监管报备流转中，全额锁定 |
| `SUPERVISING` | **监管中** | 监管生效态 | ✅ 在管可用 | ⚠️ 锁定转冻结 | 监管中存货，流转出库审批时产生冻结 |
| `TRANSFER_APPLY` | **移库申请中** | 审批流转态 | ❌ 0 | ✅ **100% 冻结** | 移出方调拨审批中，源库位存货锁定，禁止提货 |
| `OUT_APPLY` | **出库申请中** | 审批流转态 | ❌ 0 | ✅ **100% 冻结** | 出库单审核中，待提货存货全额冻结 |
| `RECEIPT_APPLY` | **仓单申请中** | 审批流转态 | ❌ 0 | ✅ **100% 冻结** | 电子仓单签发审批中，标的存货全额冻结 |
| `RECEIPT_ACTIVE` | **仓单中** | 仓单生效态 | ✅ 仓单可用 | ⚠️ 仓单出库转冻结 | 电子仓单生效存续中；发起仓单解押/提货审批时产生冻结 |
| `LIQ_APPLY` | **平仓申请中** | 风控清收态 | ❌ 0 | ✅ **100% 冻结** | 触及平仓线风控处置流转中，全额冻结 |
| `LIQUIDATING` | **平仓中** | 风控清收态 | ✅ 清收可用 | ⚠️ 锁定转冻结 | 司法或协议平仓执行处置中 |
| `ASSIGN_APPLY` | **转让申请中** | 审批流转态 | ❌ 0 | ✅ **100% 冻结** | 货权转让协议审核中，标的物锁定 |
| `ANOMALY_APPLY` | **异动申请中** | 异常调整态 | ❌ 0 | ✅ **100% 冻结** | 损溢、破损、短少报备审核中，异动量锁定 |
| `PROCESS_APPLY` | **加工申请中** | 生产加工态 | ❌ 0 | ✅ **100% 冻结** | 深加工单据申请中，待领料存货全额锁定 |
| `PROCESSING` | **加工中** | 生产加工态 | ✅ 在制可用 | ⚠️ 产出结算转冻结 | 加工车间作业中 |
| `OUT_COMPLETED` | **已出库** | 历史终态 | ❌ 0 | ❌ 0 | 物理出库完成核销离场；默认在勾选【仅查看有库存的】时被过滤隐藏 |

## 五、业务规则明细 (Rule 01 ~ 18)

### 4.1 存货管理穿透联动与参数锁定规则 (R01 ~ R03)
* **R01【仓库视图穿透锁定】**：当用户从《存货管理》（`P-CKG-001`）仓库 Tab 点击某行【库存分布】进入本页时：
  1. 系统自动在 URL 注入参数 `?warehouse_id=xxx`；
  2. 页面顶部筛选区【仓库名称】级联选择器中，**第一级“仓库”被强制锁定为当前仓库且置灰只读（不可切换）**；
  3. 用户**仅允许进一步展开并选择该仓库下属的“库房”与“分区”**；
  4. 点击【重置】按钮时，**不得重置被锁定的仓库参数**。
* **R02【货物视图穿透锁定】**：当用户从《存货管理》货物 Tab 点击【库存分布】进入本页时：
  1. 系统自动注入 `?goods_id=xxx`；
  2. 筛选区【货品名称】被强制填充当前货品规格并**置灰只读**，聚焦展示该货品在全仓各垛位的微观明细。
* **R03【货主视图穿透锁定】**：当用户从《存货管理》货主 Tab 点击【库存分布】进入本页时：
  1. 系统自动注入 `?owner_id=xxx`；
  2. 筛选区【货主名称/标识】被强制带入当前货主名称并**置灰只读**，精准展示该货主专属在库资产分布。

### 4.2 筛选与排序交互规则 (R04 ~ R07)
* **R04【默认排序与自定义排序】**：
  * **默认排序列**：列表初始加载时，严格按照 **【入库时间】倒序** 排列；
  * **多列升降序排序**：对 **【期初堆放数量】**、**【可用数量】**、**【冻结数量】** 三列增加表头排序触发器（`▲▼`），支持用户点击按单列升序/降序灵活切换浏览。
* **R05【“仅查看有库存的”快速过滤】**：
  * 筛选区右侧提供【仅查看有库存的】复选框，默认处于 **勾选状态**；
  * 勾选生效时，接口强制追加过滤条件 `(available_qty > 0 OR frozen_qty > 0)`，自动剔除已出库或数量为 0 的历史存货记录；取消勾选后展示全量历史货位。
* **R06【仓库级联三级结构】**：筛选区【仓库名称】为 `仓库 - 库房 - 分区` 三级联动选择器，支持用户精确下钻至特定物理空间。
* **R07【货品目录层级多选】**：筛选区【货品名称】基于货品中心“大类-品类-规格”目录树形展示，支持多选。

### 4.3 列表呈现与微观交互规则 (R08 ~ R11)
* **R08【货主与货物三段式展示】**：
  * 货主列展示：企业货主统一展示为 `企业全称 (统一社会信用代码)`；个人货主展示为 `真实姓名 (脱敏手机号)`；
  * 货物名称展示：统一采用 `大类-品类-规格型号`（中划线连接），超长文本以省略号截断并支持 Hover 展示全部规格。
* **R09【存货条码弹窗交互】**：
  * 点击列表中的二维码图标，居中弹出【存货条码】小弹窗；
  * 弹窗内展示存货全局唯一字符串条码（支持一键复制），下方渲染高清二维码图形；
  * 弹窗底部提供【关闭】按钮，支持现场扫码设备快速识读。
* **R10【具体位置空值占位】**：若入库录单时未填写分区下的微观具体垛位，列表与详情页统一展示占位符【`--`】。
* **R11【库房审核标签展示】**：库房列必须明确带出该库房在基础档案中维护的属性标签，如 `海霸王冷库 (不需要审核)` 或 `水果库房 (需要审核)`。

### 4.4 详情页跳转与全息追溯规则 (R12 ~ R15)
* **R12【行操作【详情】新标签页打开】**：
  * 点击列表操作列的【详情】文字链接（采用系统主题色），**强制在浏览器打开新标签页**访问 `P-CKG-003-DETAIL`；
  * 确保原列表页的分页、筛选条件及滚动条位置完整保留。
* **R13【入库单号【查看】穿透联动】**：
  * 在库存明细详情页的基础信息区，入库单号右侧高亮提供主题色 **【查看】** 链接；
  * 点击【查看】时，在新标签页跳转至该单据对应的 **`入库记录详情页`（`P-CKG-009-DETAIL`）**，实现从微观货位向源头业务单据的无缝回溯。
* **R14【影像证据链三要素呈现】**：
  * 详情页【附件信息】区分为三大并列区块：
    1. **现场照片**：展示现场工人码放与货品实物照片，缩略图可点击弹窗查看超高清原图；
    2. **补充资料**：展示随单质检单、送货磅单（支持在线预览 PDF 或图片）；
    3. **设备抓拍图**：展示 IoT 摄像头在入库作业时的自动抓拍凭证，无抓拍时显示 `无设备抓拍图`。
* **R15【详情页存货信息表格一致性】**：详情页底部的【存货信息】表格，展示该条明细对应的库房、分区、具体位置、期初堆放、可用、冻结及状态，数据必须与当前明细行保持 100% 强一致镜像。

### 4.5 权限隔离与安全规范 (R16 ~ R18)
* **R16【RBAC 权限码矩阵】**：
  * `P-CKG-003:VIEW`：库存明细列表与详情查看权限；
  * `P-CKG-003:BARCODE`：存货条码与二维码查看权限；
  * `P-CKG-003:EXPORT`：库存明细导出权限（预留）；
  * `P-CKG-009:DETAIL_VIEW`：跨模块查看入库单详情权限。
* **R17【数据范围仓库权限强隔离】**：操作员发起查询时，服务端根据其拥有的仓库授权列表注入 SQL 过滤条件 `warehouse_id IN (...)`，严禁越权返回未经授权仓库的存货明细。
* **R18【操作防抖与幂等】**：【查询】与【重置】按钮具有 1 秒防抖控制，避免连续点击引发的接口拥堵。

## 六、异常与边界处理 (C01 ~ C05)
