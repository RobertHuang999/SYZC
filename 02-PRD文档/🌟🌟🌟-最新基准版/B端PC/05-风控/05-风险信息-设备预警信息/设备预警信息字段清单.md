# 设备预警信息字段清单

> **文档定位**：设备预警信息列表、详情及预警处理页面的字段定义来源。设备预警的规则名称、预警大类、子类型、阈值和关联设备引用[设备预警配置字段清单](../../08-配置管理/20-风险管理-设备预警配置/设备预警配置字段清单.md)；设备名称、设备编码及仓库位置引用设备管理模块，并在预警触发时保存历史快照。
>
> **版本**：V1.2 | 更新时间：2026-08-18
>
> **页面范围**：当前版本覆盖设备预警信息列表、详情和解除预警处理；不包含新增页。预警信息由系统根据设备预警配置和三方设备事件自动生成。

## 0. 字段层级说明

1. **基础识别字段**：用于识别预警来源、触发内容、时间和当前处理状态。
2. **解除预警字段**：仅在支持人工解除的预警详情或处理弹窗中填写；系统自动解除的预警不展示人工解除表单。
3. **系统字段**：用于幂等、历史追溯、有效性控制和审计，不作为普通列表字段展示。

“处理时间”“处理人”和“预警状态”由系统维护，用户不能直接修改。人工解除是一个受权限控制的处理动作，不是新增或编辑预警记录。

## 四、页面展示与处理规则

### 1. 列表与筛选

- 列表展示顺序：预警规则名称、预警类型、预警内容、预警抓拍图、预警时间、处理时间、处理人、预警状态、操作。默认列表返回当前用户有权限查看的全部有效和无效记录；无效记录以“未处理（无效）”展示，计入列表总数和分页。
- 筛选字段：预警类型、预警状态。预警类型按预警大类下拉精确筛选；预警状态是查看有效或无效记录的唯一筛选入口，支持“未处理（有效）”“未处理（无效）”“已处理（有效）”精确筛选。预警时间、处理时间和处理人仅用于列表及详情展示，不提供筛选条件。
- “操作”属于列表交互列，不作为业务字段。状态为“未处理（有效）”且属于图像识别、智能挂锁、人脸门禁的非离线行为类或物联设备离线等人工解除类型的预警，在用户具备预警处理权限时展示“解除预警”；温度、湿度、烟感、二氧化碳、氧气、GPS及其他自动解除类型不展示人工解除入口；“未处理（无效）”和“已处理（有效）”也不展示人工解除入口。
- 列表和详情均按租户、菜单权限及设备绑定位置对应的仓库权限过滤；设备未绑定具体仓库、库房或分区位置时，对所有已登录且具备本模块菜单查看权限的账号可见，但不得绕过租户和菜单权限。该信息查看例外不扩展到设备预警配置的设备选择权限。
- 抓拍图列表列默认展示默认图，页面初始化不加载真实图片；用户点击放大后，前端通过后端接口换取真实图片并进行权限校验。无图片、抓拍失败或真实图片换取失败时展示对应状态，不使用破损图片占位。

### 5. 抓拍范围与位置层级

预警抓拍图和解除预警抓拍图统一按“仓库 > 库房 > 分区”的位置层级计算抓拍范围，库房是分区的上级单元。设备绑定位置的抓拍范围如下：

| 设备绑定位置 | 抓拍范围 |
| :--- | :--- |
| 仅绑定仓库 | 该仓库本身、仓库下属全部库房及各库房下属全部分区 |
| 绑定库房，未绑定该库房下属具体分区 | 该库房本身及该库房下属全部分区 |
| 绑定库房的具体分区 | 仅该“仓库-库房-分区”具体单元 |

设备同时绑定多个库房或分区时，按各绑定位置范围取并集；绑定库房 A（未绑定分区）时抓拍库房 A及其分区1、分区2，另绑定库房 B-分区2时仅增加库房 B-分区2；设备仅绑定仓库 A时覆盖仓库 A、全部下属库房及全部分区。无匹配监控设备时展示 `无抓拍图`，不扩大抓拍范围到其他仓库或无关位置。

### 2. 自动解除与人工解除

| 预警类型/子类型 | 解除方式 | 处理人展示 | 解除表单 |
| :--- | :--- | :--- | :--- |
| 温度异常、湿度异常、二氧化碳异常、氧气异常 | 设备有效采集值恢复到配置范围内自动解除；等于最低值或最高值时不属于越界 | 系统自动处理 | 不展示人工解除表单 |
| 烟感异常 | 收到设备恢复正常的有效采集值或三方恢复事件后自动解除 | 系统自动处理 | 不展示人工解除表单 |
| 全部 GPS 预警子类型 | 收到三方平台推送的对应恢复/正常状态事件后自动解除 | 系统自动处理 | 不展示人工解除表单 |
| 非物联设备离线预警 | 收到对应三方设备重新上线结果后自动解除 | 系统自动处理 | 不展示人工解除表单 |
| 图像识别、智能挂锁、人脸门禁的非离线行为类预警 | 由具备权限的用户人工解除；具体事件再次触发时按设备和分类键去重 | 人工处理人及所属机构 | 展示情况说明、现场照片；提交时联动解除预警抓拍图 |
| 物联设备离线 | 按离线轮次处理；同一轮次内重复离线事件仅更新当前未处理记录，人工解除后设备未上线期间忽略重复离线事件；收到有效上线事件后结束当前轮次，下一次离线才开启新轮次 | 人工处理人及所属机构或系统自动处理 | 展示情况说明、现场照片；提交时联动解除预警抓拍图 |

人工解除提交时必须使用预警信息唯一标识和记录版本进行服务端校验，并通过幂等键或分布式锁防止重复提交、并发覆盖和重复扣减。提交成功后原子更新预警状态、处理时间、处理人、解除材料和审计日志；失败时保持原预警状态和原材料不变。

### 3. 预警状态与有效性

- “预警状态”由处理状态和记录有效性组合组成，列表与详情统一展示为“未处理（有效）”“未处理（无效）”或“已处理（有效）”；“记录有效性”仍作为系统内部字段保存，不单独占用展示列。
- 未处理预警按预警大类和子类型执行分类去重；同一设备同一分类键仅保留一条有效未处理记录，新事件到达时将旧有效记录置为“未处理（无效）”并生成最新有效记录，不同分类键分别展示。已处理预警不参与未处理去重，用户可见的已处理记录全部保留。
- 无效记录进入默认列表并计入总数和分页，但不再发送普通提醒和升级通知，不参与未处理去重，也不展示人工解除入口；详情按只读方式展示。
- 设备规则关联解除、设备解绑、逻辑删除或数据权限撤销导致的无效记录同样进入默认列表并计入总数和分页，详情只读展示。
- 已处理记录的后续事件应按新预警轮次生成新记录，不能回写已处理记录的预警时间、触发值或处理材料。

### 4. 审计与图片安全

- 预警触发、状态变更、自动解除、人工解除、通知发送、通知失败、抓拍失败、图片查看和越权拦截均需记录审计日志。
- 图片应保存图片地址、来源设备、抓拍时间、抓拍结果和关联预警信息唯一标识；访问地址使用时效签名，并校验租户、菜单和仓库数据权限。
- 设备、位置、触发值、阈值和规则版本以预警触发时快照为准，满足历史追溯、异常复核和升级通知要求。
