## 二、CSV 字段说明

### 2.1 页面与权限列

| 原型页列 | CSV 列名 | 说明 |
| :--- | :--- | :--- |
| **页面路径** | `端` + `所属模块` + `一级菜单` + `二级菜单` + `Tab` | 拼装菜单路径；合并单元格写法允许留空，读取时沿用上一行 |
| **页面功能按钮** | `页面功能按钮` | 页面按钮并集，顿号分隔 |
| **数据可见范围** | `数据可见范围` | 数据过滤规则 |
| **变更记录** | `创建时间` + `修定时间` + `变更说明` | 日期格式 `YYYY年M月D日` |
| **旧系统对照** | `旧系统路径` | 老系统菜单路径，便于迁移核对 |

### 2.2 四类角色列（2026-11-11 新增）

| 列名 | 说明 |
| :--- | :--- |
| `平台运营方按钮` | 平台运营方在该页可操作/可查看的按钮；`—` 表示无权限 |
| `仓储服务方按钮` | 仓储服务方视角 |
| `监管服务方按钮` | 监管服务方视角 |
| `资金服务方按钮` | 资金服务方视角 |

> C 端页面的「平台运营方」一列在 TSV 中表示 **门户管理员**，不是 B 端平台运营方；SAAS 四页四类角色均为「无」，因为走 SAAS 专属账号体系。

### 2.3 菜单索引列（文档维护用，原型页不展示）

| 列名 | 说明 |
| :--- | :--- |
| `菜单模块编码` | 如 `01-工作中心`、`12-C端PC`、`14-SAAS` |
| `顶栏/底栏模块名` | 菜单地图显示名 |
| `基准模块目录` | 如 `B端PC/01-工作中心`、`C端PC/01-首页/` |
| `记录状态` | `active` / `planned` / `cancelled` / `6.2-target` / `6.3-target` |

## 三、维护工作流

```mermaid
flowchart LR
  A[角色按钮矩阵 TSV 有变更] --> B[合并到 权限清单 CSV 四列角色按钮]
  C[页面/菜单有变更] --> D[编辑 权限清单 CSV]
  D --> E{模块结构变了?}
  E -->|是| F[同步 00-菜单模块映射.md]
  E -->|否| G[在 B端PC 运行 generate:reference]
  D --> H{新增页面 PRD?}
  H -->|是| I[补 页面-基准文档映射.csv]
```

1. **日常改权限**：直接编辑 [功能与数据权限清单.csv](./功能与数据权限清单.csv)；
2. **角色按钮有更新**：先改 TSV，再合并到 CSV 四列角色按钮，保持「TSV 为角色级来源、CSV 为落地主表」；
3. **同步原型参考页**：
   ```bash
   cd 03-前端原型demo/B端PC
   npm run generate:reference
   ```
4. **新增菜单页**：在 [页面-基准文档映射.csv](./页面-基准文档映射.csv) 追加一行，指向对应基准目录；
5. **CSV 结构异常**：运行 `node scripts/normalize-csv.mjs` 规范化（先备份）。
