## 一、文件约定

每个迭代版本目录下维护一份 **`00-菜单迭代记录.md`**：

```text
B-迭代需求/
├── README.md                          # 版本入口导航（含迭代 PRD 链接）
├── 00-菜单迭代记录/                    # 本索引
├── 6.2版本（2026.08）/
│   ├── README.md
│   └── 00-菜单迭代记录.md              # ← 6.2 菜单调整明细
└── 6.1版本（2026.07）/
    └── 00-菜单迭代记录.md              # ← 6.1 菜单调整明细（可为空表）
```

## 二、Markdown 模板

文件头部使用 YAML frontmatter 描述版本；正文用表格列出菜单级变更：

```markdown
---
version: "6.2"
name: "6.2版本（2026.08）"
period: "2026.08"
summary: "物联网 IOT、运行时预警、预警配置三主干 + 门禁开锁审批"
docPath: "B-迭代需求/6.2版本（2026.08）/README.md"
---

# 6.2 · 菜单迭代记录

## 菜单调整明细

| 端 | 变更类型 | 标题 | 调整前 | 调整后 | 优先级 | 交付标注 | 说明 | 日期 | 来源文档 |
| :--- | :---: | :--- | :--- | :--- | :---: | :--- | :--- | :--- | :--- |
| PC | 更名 | 示例 | 旧名 | 新名 | P0 | 必交付 | 备注 | 2026-08 | B端PC/00-菜单地图.md |
```

可选增加 **`## 交付范围标注`** 节（摘要表：交付标注 / 含义 / 涉及菜单），选中该版本时在原型「迭代记录」页顶部展示。

**交付标注枚举（6.3 示例）**：`必交付` · `暂定` · `暂定开发` · `不涉及` · `—`

**变更类型枚举**：`新增` · `更名` · `迁移` · `取消` · `结构`

**端枚举**：`PC` · `移动` · `双端`

## 三、同步原型

```bash
cd 03-前端原型demo/B端PC
npm run generate:iterations
```
