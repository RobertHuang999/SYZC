## 2. 页头操作栏

| 按钮 | 规格 |
| :--- | :--- |
| 返回 / 取消 | 次操作；存在未保存策略卡片修改时弹出离开确认 |
| ~~保存并生效~~ | **已移除**——不提供整页统一保存 |

## 3. 新增态 vs 编辑态差异

| 对比项 | 新增 | 编辑 |
| :--- | :--- | :--- |
| 规则名称 | 空，可填 | Readonly（R06） |
| 关联订单 | 可选（过滤已有规则订单） | Readonly（R06） |
| 订单类型/货主/货物 | 选订单后自动带出（R02） | 只读 |
| 各策略 Switch | 默认 OFF | 读当前启用状态 |
| Version | 不展示（首次策略保存后生成） | 只读，**每次策略保存**携带（R07） |
| 保存粒度 | **逐条策略保存**；首次保存创建主表 | **逐条策略保存**；保持生效中 |
| 关闭已启用子项 | 保存 OFF 后生效 | 该子项未处理流水置无效（C01a） |

## 4. 基础识别卡片

| 字段 | 控件类型 | 必填 | 规格 |
| :--- | :--- | :---: | :--- |
| 规则名称 | `Input` | 是 | ≤50 字，租户唯一（R01）；编辑 Readonly |
| 关联订单 | `SelectWithSearch` | 是 | R03/R04；编辑 Readonly |
| 订单类型 | `ReadonlyText` | 自动 | 抵/质押 / 监管 |
| 货主 | `ReadonlyText` | 自动 | 脱敏手机号 |
| 货物 | `ReadonlyText` | 自动 | 大类/品类/规格/单位 |
| Version | `ReadonlyText` | 编辑 | 乐观锁；每次策略保存成功后刷新 |

> **首次保存时机**：新增页在用户点击任一策略卡片「保存该策略」时，一并校验并提交基础识别字段（R01/R04），创建综合规则主表。

## 5. 预警策略配置区（6 大卡片）

卡片标题：**预警策略配置（逐条独立保存 · 至少启用 1 项 · R07a）**。

每张策略卡片结构：

```text
[Switch ON/OFF]  策略 N：{名称}  （监管订单不可用提示）  [ 收起/展开 ▼▲ ]
  └─ 策略专属参数字段
  └─ 预警等级（SelectWithSearch，提交 severity_level_id）
  └─ 通知渠道（CheckboxGroup，选填；系统小角标自动更新）
  └─ 预警对象（多选，R19）
  └─ 升级预警（Checkbox + 天数 + 对象，R20）
  └─ [ 保存该策略 ]  ● 未保存 / ✓ 已保存
```

### 5.1 六策略卡片清单

| # | 策略名称 | 监管订单 | 核心参数字段 |
| :---: | :--- | :---: | :--- |
| 1 | 解抵/质押/监管超时 | ✅ | 超时配置动态表格（R14） |
| 2 | 抵/质押率双控 | ❌ 置灰 R12 | 补仓线 LTV + 等级 / 平仓线 LTV + 等级 / 解除方式（R12a） |
| 3 | 仓储巡检超期 | ✅ | 巡检人 + 周期动态表格（R17） |
| 4 | 解抵/质押/监管超时监控 | ✅ | （同策略1或合并展示，以字段清单为准） |
| 5 | 盘点账实差异 | ✅ | 启用即监听（R16） |
| 6 | 贷中风控模型 | ❌ 置灰 R12 | 模型参数（R18） |

> 实际 6 卡片命名与 ASCII 线框一致：价格下跌、抵质押率双控、仓储巡检、解抵质押监管超时、盘点差异、贷中风控。

### 5.2 监管订单差异化

策略 2（抵质押率）、策略 6（贷中）Switch **disabled** + 辅助文案「监管订单不可用」。

### 5.3 LTV 双等级

抵质押率子项分别绑定：
- `margin_call_severity_level_id`（补仓线）
- `close_out_severity_level_id`（平仓线）
- R11：平仓线 LTV ≥ 补仓线

## 6. 卡片交互规则

### 6.1 编辑与展开

- Switch OFF：折叠面板收起，内部字段不校验
- Switch ON：展开面板，**保存时**校验该子项全部必填
- 新增页默认全部 OFF；编辑页读真实状态
- 下拉等级读 03/01 启用档；展示编码+名称+色块

### 6.2 逐条保存（核心交互）

| 行为 | 规格 |
| :--- | :--- |
| **保存该策略** | 每张卡片底部独立主按钮；API 仅提交当前 `strategy_type` + 基础识别（新增首次）+ Version |
| **脏数据状态** | 卡片内字段变更后显示「● 未保存」；保存成功后显示「✓ 已保存」并刷新 Version |
| **保存成功** | Toast「{策略名称}保存成功」；**不跳转列表**，停留当前页继续配置其他策略 |
| **Switch OFF 保存** | 提交 `is_enabled=0`；若为最后 1 项已启用策略则 R07a 阻断 |
| **并发** | 携带 Version；冲突时 Toast「数据已被他人修改，请刷新重试」 |
| **离开拦截** | 任一卡片处于「未保存」状态点击返回/取消 → 确认弹窗 |

### 6.3 新增首次保存

1. 校验基础识别 R01/R04
2. 创建 `order_rule_config`（Version=1，状态=生效中）
3. Upsert 当前策略子项
4. 若启用贷中风控子项 → 触发 C04 台账同步

## 7. 保存校验（单策略粒度）

| 规则 | 反馈 |
| :--- | :--- |
| R01 名称重复（首次保存） | 阻断 |
| R04 订单已有规则（首次保存） | 阻断 |
| R07a 关闭最后 1 项已启用策略 | 「请至少启用一项预警策略」 |
| R08~R09 LTV 区间（保存 LTV 子项） | 「平仓线必须高于补仓线」 |
| R10 未选等级（保存该开启子项） | 「请选择{子项}的预警等级」 |
| R19 未选对象（保存该开启子项） | 「请配置{子项}的预警对象」 |
| R20 升级不完整（保存该开启子项） | 「请完善升级天数与对象」 |
| R12 监管提交禁用策略 | 服务端拒绝 |
| R07 Version 冲突 | 「数据已被他人修改，请刷新重试」 |
