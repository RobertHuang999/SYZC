## 一、模块定位


| 项目            | 内容                                                                                       |
| ------------- | ---------------------------------------------------------------------------------------- |
| **业务性质**      | 在现有「获取门锁密码」直接操作基础上，新增按**指定设备**控制的开锁审批链路；未配置的设备走原有免审直发流程                                  |
| **配置入口**      | 配置管理 → 业务流程管理 → 开锁审批                                                                     |
| **涉及系统模块**    | 开锁审批配置 / 工作中心·审批中心·其他审批·开锁审批（PC）/ 业务办理·其他审批·开锁审批（H5） → 仓库与库房主数据 → 门禁设备 → 密码服务与短信平台 → 门禁事务记录 / 审计 / 我的申请记录                                |
| **涉及业务对象**    | 审批配置、门禁开锁申请、审批任务、临时开锁凭证、门禁实际开锁事务                                                         |
| **职责边界**      | **其他审批—开锁审批**负责审批列表与通过/驳回；**我的申请记录**负责申请人查询；门禁模块负责设备校验、密码入口、凭证与事务；**不进** 07 待处理 |
| **与门禁设备模块关系** | 门禁设备模块本身不生成独立业务单据、不建立独立审批流程；本模块为审批扩展链路，设备主档、在线/离线状态和已有密码获取规则仍由原模块负责                      |


### 1.1 业务对象职责分层


| 业务对象        | 回答的问题            | 状态独立性            |
| ----------- | ---------------- | ---------------- |
| 审批配置        | 哪些位置需要审批、谁来审批    | 独立版本化配置          |
| 开锁申请        | 谁因为什么事申请打开哪一台设备  | 独立审批主状态          |
| 审批任务 / 审批记录 | 审批人作出了什么决定       | 独立任务状态           |
| 临时凭证        | 密码是否生成、是否发送、是否有效 | 独立凭证状态，不与申请主状态混写 |
| 门禁事务        | 设备实际上有没有开锁       | 独立事实记录，非申请下游状态   |


> 设计原则：`审批通过 ≠ 密码生成成功 ≠ 短信发送成功 ≠ 实际开锁成功`，四者须分别留痕。

## 五、流程编排与联动

### 5.1 正向链路（摘要）

**审批配置 → 设备位置匹配 → 用户发起开锁申请 → 其他审批（开锁审批）→ 审批通过/驳回 → 临时密码生成与短信下发 → 实际开锁 → 门禁事务与审计追溯**

### 5.2 业务对象联动

| 上游动作 | 触发条件 | 下游对象 | 后置影响 |
| :--- | :--- | :--- | :--- |
| 启用审批配置 | 范围、审批人、权限和冲突校验通过 | 有效配置版本 | 新申请按该版本匹配 |
| 设备发起获取密码 | 类型、权限、绑定状态、手机号和防重校验通过 | 开锁申请或原有直发密码流程 | 需审批时不得调用密码服务 |
| 创建开锁申请 | 命中需要审批且无有效重复申请 | 审批任务（平台） | 申请=待审批，凭证=未生成 |
| 审批通过 | 申请仍为待审批且未终态 | 凭证处理 | 申请=已通过；进入凭证处理 |
| 审批驳回 | 驳回原因填写完整且任务未处理 | 开锁申请 | 申请=已驳回；不生成密码 |
| 密码生成与短信下发 | 申请已通过且设备复核仍有效 | 临时凭证 | 新凭证生效时同设备旧凭证=已失效（被覆盖） |
| 实际开锁上报 | 事件唯一标识未入库 | 门禁事务记录 | 生成事实记录；不反向改变审批结论 |
| 配置停用或修改 | 管理员执行配置变更 | 新申请匹配 | 只影响新申请；在途申请继续使用快照 |

## 设计自检清单

- [x] 是否存在永远到不了的状态？—— 各对象状态均有对应进入路径
- [x] 是否存在进去就出不来的死状态？—— 非终态均有离开路径
- [x] 是否存在两个名字不同但含义相同的状态？—— 申请/凭证/事务分层，无混写
- [x] 每个动作是否在所有状态下都定义了允许/不允许行为？—— 动作能力矩阵已覆盖
- [x] 终态是否还有可执行操作？—— 终态仅查看
- [x] 状态变更是否都通过动作按钮触发？—— 符合规范 2.4
- [x] 物理删除和作废的路径是否区分清楚？—— 配置不提供物理删除；**仅已停用**可逻辑删除（C08）；废弃配置可先停用；申请终态保留记录
- [x] 规则代码是否唯一编号？—— R/C/P/W/A 系列已分配
