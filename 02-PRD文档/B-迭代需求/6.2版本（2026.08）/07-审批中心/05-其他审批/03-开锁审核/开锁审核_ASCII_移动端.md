## 0. 移动端与 PC 差异摘要

| 维度 | PC 端 | 移动端（本文件） |
| :--- | :--- | :--- |
| 一级入口 | 工作中心 → 审批中心 → 其他审批 → **开锁审核** 卡片 | 业务办理 → 其他审批 → **开锁审批** |
| 列表 | 表格 + 筛选栏 + Tab | 全卡片 + 搜索框 + 状态下拉胶囊 |
| 详情 | 多分区只读大表单 + 底部操作区 | 页头摘要橙框 + SectionCard + 页内审批区 |
| 审批处理 | 详情页「审批操作」分区；驳回可弹窗 | 详情页内嵌「审批处理」SectionCard；驳回 inline 校验 |
| 导出 / 批量 | ❌ 本期不做 | ❌ 本期不做 |
| 底栏 | PC 列表无固定底栏 | 🚫 **无固定悬浮操作栏**（审批按钮随 SectionCard 滚动） |

**移动端能力范围**：列表浏览与筛选、详情只读查看、待审批时通过/驳回；**无**发起申请、凭证明文查看、审批配置编辑。

### 0.1 PC 与移动端字段排版差异（⚠️ 生成必遵）

| 端 | 详情只读区 | 审批可填区 |
| :--- | :--- | :--- |
| **PC** | `DetailField`：**上 label 下 value**，多列 Grid | Label 在上、Textarea 在下，独立「审批操作」分区 |
| **移动 H5** | `KeyValue`：**左 label（w-20）右 value** 横排 | SectionCard 内 Label 在上、Textarea / 双按钮在下 |

> 移动端**不要**套用 PC 宽表栅格；列表卡片**不展示申请单号**（字段清单 §一），申请单号仅在详情页头与搜索框可检索。

### 1.2 状态下拉选项

```text
+----------------------------------+
| 选择状态                    [x] |
+----------------------------------+
| (•) 待审批                        |
| ( ) 已处理                        |
| ( ) 全部                          |
+----------------------------------+
```

**已处理** = 申请状态 ∈ {已通过、已驳回、已撤回、已失效、已作废} 且当前用户 eligible 或曾处理。

### 1.3 布局说明

**NavBar**：左侧 `<` 返回 `/m/tasks`（业务办理 · 其他审批区块）；标题「开锁审批」。

**搜索区**：实时过滤申请单号、设备名称/编码、申请人、事由（L01、L02）。

**卡片字段投影**（字段清单 §一，列表展示=是）：

| 卡片区域 | 字段 | 说明 |
| :--- | :--- | :--- |
| 头部 | 设备名称、申请状态 | 状态 Tag；待审批 warning 色 |
| 灰框 | 绑定仓库、申请人、事由 | 核心事实摘要 |
| 元信息 | 提交时间 | 格式 `YYYY-MM-DD HH:mm` |
| 底链 | 去审批 / 详情 | 待审批 →「去审批 ▸」；终态 →「详情 ▸」 |

**行操作对照**（与 PC 列表一致）：

| 申请状态 | 卡片底链 | 点击卡片 |
| :--- | :--- | :--- |
| 待审批 + eligible | 去审批 ▸ | 进入详情 + 展示审批处理区 |
| 待审批 + 非 eligible | 详情 ▸ | 只读详情，无操作区（D05） |
| 已通过 / 已驳回 / 已撤回 / 已失效 / 已作废 | 详情 ▸ | 只读详情 + 审批记录 |

## 3. 审批处理（详情页内嵌）

> H5 **无独立审批页**；处理动作在详情页「审批处理」SectionCard 内完成，规则同 [02审批处理字段清单](./操作字段清单/02审批处理字段清单.md)。

### 3.1 通过流程

```text
1. 审批人可选填「审批意见」（≤200 字）
2. 点击 [ 通过 ]
3. Toast「已通过，凭证生成中」或「审批通过」
4. ~1.2s 后自动返回列表 /m/approval/unlock-applies
```

| 规则 | 说明 |
| :--- | :--- |
| R10–R12 | 引用平台通用审批通过规则 |
| R11 / P06 | 不可审批自己发起的申请 |
| R18 | 状态条件更新；并发冲突见 §3.4 |
| A01 | Toast + 返回列表 |

### 3.2 驳回流程

```text
1. 审批人填写「审批意见」（H5 复用同一 Textarea 作为驳回原因）
2. 点击 [ 驳回 ]
3. 若意见为空 → Toast「驳回须填写审批意见」（U03 提交时校验）
4. 校验通过 → Toast「已驳回」→ 返回列表
```

| 规则 | 说明 |
| :--- | :--- |
| R13 | 驳回时意见/原因必填，≤200 字 |
| U03 | H5 提交时校验（PC 可另用弹窗，见 PC 详情 ASCII） |
| A02 | Toast + 返回列表 |

### 3.3 PC 驳回弹窗对照（H5 不单独实现）

> PC 可选独立「驳回原因」弹窗，见 [开锁审核_ASCII_详情页](./开锁审核_ASCII_详情页.md)。H5 以 SectionCard 内 Textarea 合并承载「审批意见 / 驳回原因」，**不**另开全屏驳回页。

### 3.4 异常与阻断

| 场景 | 规则 | 移动端表现 |
| :--- | :--- | :--- |
| 申请状态已变更 | R18 / A03 | Toast「审批失败：申请状态已变更」→ 刷新详情 |
| 非 eligible | D05 | 隐藏「审批处理」区 |
| 自审 | R11 / P06 | 隐藏操作区或提交拦截 |
| 意见超 200 字 | 字段清单 §五 | 前端截断或 Toast 提示 |
| 申请不存在 | — | 全页「申请单不存在或已不可见」 |
