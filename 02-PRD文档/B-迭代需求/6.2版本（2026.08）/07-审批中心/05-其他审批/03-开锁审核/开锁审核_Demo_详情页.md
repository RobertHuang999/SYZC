| 项目 | 内容 |

## 6. 审批处理 SectionCard（条件展示）

### 6.1 展示条件（D01–D07）

同时满足：

- 申请状态 = `待审批`
- 当前用户 = eligible 处理人
- 对应审批任务 = `待处理`

否则**整区隐藏**；非 eligible 时可展示提示「您不是当前审批人，仅可查看。」（D05）。

### 6.2 表单控件

| 字段 | 控件 | 规格 |
| :--- | :--- | :--- |
| 审批意见 | `textarea` | placeholder：`通过可选填；驳回必填`；`min-h-[88px]`；最多 200 字；显示 `0/200` |
| 驳回 | 按钮 outline | 左列，`rounded-xl border` |
| 通过 | 按钮 primary | 右列，`bg-orange-600`；双按钮 `grid grid-cols-2 gap-2` |

SectionCard 标题「审批处理」；`indicatorColor="#f57c00"`（与原型一致）。

### 6.3 通过流程

1. 审批意见选填
2. 点击「通过」
3. Toast「审批通过」（A01）
4. `setTimeout` ~1200ms → `navigate('/m/approval/unlock-applies')`

### 6.4 驳回流程

1. 填写审批意见（H5 复用为驳回原因）
2. 点击「驳回」
3. 意见为空 → Toast「驳回须填写审批意见」（U03、R13）
4. 校验通过 → Toast「已驳回」（A02）→ 返回列表

> H5 **不**单独实现 PC 驳回弹窗；见 [ASCII §3.3](./开锁审核_ASCII_移动端.md#33-pc-驳回弹窗对照h5-不单独实现)。

### 6.5 异常反馈

| 场景 | 表现 |
| :--- | :--- |
| 申请不存在 | 全页「申请单不存在或已不可见」 |
| 状态已变更 | Toast「审批失败：申请状态已变更」→ 刷新详情（A03） |
| 自审 | 隐藏操作区或提交拦截（R11、P06） |
| 意见超 200 字 | 前端截断或 Toast |

## 7. 详情页态差异（与 ASCII §2.4～§2.7 对齐）

| 状态 | 审批处理区 | 审批记录 | 终态摘要 |
| :--- | :---: | :--- | :--- |
| 待审批 + eligible | ✅ | 空或待处理节点 | — |
| 待审批 + 非 eligible | ❌ + 提示 | 只读 | — |
| 已通过 | ❌ | 完整节点 | 通过 + 凭证状态 |
| 已驳回 | ❌ | 驳回节点 | 驳回 |
| 已撤回 | ❌ | 空 | 撤回 |
| 已失效 | ❌ | 空或历史 | 超时失效 |
| 已作废 | ❌ | 空或历史 | 作废 |
