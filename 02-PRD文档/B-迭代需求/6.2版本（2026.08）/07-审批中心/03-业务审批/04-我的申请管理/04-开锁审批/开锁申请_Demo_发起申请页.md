## 2. 入口路由（列表行操作）

列表页点击「获取门锁密码」/「获取门禁密码」后，**先调用审批配置匹配**，再决定打开哪个 Dialog：

| 匹配结果 | 挂锁 | 人脸 |
| :--- | :--- | :--- |
| **免审** | `GetLockPasswordDialog` | `GetAccessPasswordDialog` |
| **需审批** | `UnlockApplySubmitDialog`（本文档） | `UnlockApplySubmitDialog`（本文档） |

```typescript
// 伪代码 · 行操作 handler
async function onGetPassword(row: AccessDevice) {
  const needApproval = await matchUnlockApprovalConfig(row)
  if (needApproval) {
    openUnlockApplySubmitDialog({
      deviceType: row.deviceType,
      deviceName: row.displayName,
      deviceCode: row.deviceCode,
      warehouseName: row.warehouseName,
      locationDetail: row.locationDetail,
    })
  } else if (row.deviceType === '挂锁门禁') {
    openGetLockPasswordDialog(row)
  } else {
    openGetAccessPasswordDialog(row)
  }
}
```

> UI **不展示**「需审批/免审」标签；用户感知为同一「获取密码」入口，弹窗内容因匹配结果不同而变化。

## 7. 校验与阻断

| 规则 | 场景 | 反馈 |
| :--- | :--- | :--- |
| R05 | 无获取密码权限 / 仓库数据权限不足 | Toast |
| R05 | **挂锁**未绑定手机号 | Toast「请先绑定手机号」 |
| R06 | 未命中需审批 | 不应打开本 Dialog |
| R07 | 同设备在途申请 | Toast「设备已有在途申请 {单号}」 |
| R08 | 60 秒内重复提交 | 返回原申请单号及状态 |
| — | 预计时段开始 > 结束 | 字段红字 |
| — | 人脸次数 / 有效期越界 | 同获取门禁密码免审校验 |
