### A.2 T0 — 保存综合规则

1. `POST /order-warning/rules` 传入一个 `rule_id` 语义的主对象和两个策略子项；等级字段只传 `SL-002`、`SL-003`，不传 `L3/L4` 字符串。
2. 服务端校验 `tenant_id + order_id` 唯一、监管限制、LTV 平仓 `sort_order(3) >= 补仓 sort_order(2)`、通知对象和 Version。
3. 写入主表、两个子项、审计日志；响应 `rule_id=OR-202608-001`、`version=1`。
4. 预期：规则列表只出现 1 行，已启用预警项为“抵/质押率异常、价格下跌”。

### A.3 T1 — 命中补仓线并生成商业预警

| 步骤 | 输入/结果 |
| :--- | :--- |
| 货值变化 | 当前货值 920 万，LTV = 700 / 920 = 76.09%，严格大于 75% |
| 幂等事件 | `event_id=VAL-202608-001`；幂等键=`TEN_SENYUN_001 + ORD-202608-001 + LTV + VAL-202608-001` |
| 生成流水 | `warn_id=COL-202608-001`；`strategy_type=LTV`；命中线 `MARGIN_CALL`；`severity_level_id=SL-002`；快照 `sort_order=2`；来源 `ORDER_CONFIG` |
| 状态/通知 | `PENDING_VALID`；站内信发送给张三；`fuse_status=NONE` |

重复投递相同 `event_id` 只返回原 `warn_id`，不新增流水。

### A.4 T2 — 命中平仓线并升级同一记录

| 步骤 | 输入/结果 |
| :--- | :--- |
| 货值变化 | 当前货值 800 万，LTV = 87.50%，严格大于 85% |

| 订单动作 | `OUT-202608-001` 出库请求通过；6.2 不阻断出库 |

### A.5 T3 — L4 物联事件穿透并按设备事件 ID 跳转

| 步骤 | 输入/结果 |
| :--- | :--- |
| 设备事件 | `device_event_id=DEV-E-501`；`IOT-R-101` 命中“剪杆破坏”；等级 `SL-004`；02/01 写入 `PENDING_VALID` |
| 03/01 穿透判断 | `SL-004.sync_to_order_warn=true`；空间匹配 `WH-A01/RM-01/ZN-A`；订单状态 `PLEDGING` |
| 押品流水 | `warn_id=COL-P-001`；`warn_type=IOT_PENETRATION`；`related_device_event_id=DEV-E-501`；等级快照 `SL-004/CRITICAL/sort_order=4`；`fuse_status=NONE` |
| 页面跳转 | 02/02 点击“查看设备事件”携带 `device_event_id`、`warn_id`、`return_route`；02/01 按 `device_event_id` 定位，不按设备编号或列表序号定位 |
| 权限失败 | 若用户缺少 IoT 查看或仓库权限，返回 `403_CROSS_DOMAIN_SCOPE`，不跳转且不改变押品流水 |

### A.6 T4 — 设备核销联动解除

1. 王五在 02/01 提交 `DEV-E-501` 解除，填写处理说明并通过 IoT 处理权限校验；设备流水置 `PROCESSED`。
2. 发布 `DeviceEventReleased(tenant_id, event_id=DEV-E-501, order_id, processed_by, processed_time)`。
3. 02/02 消费事件以 `event_id` 幂等匹配 `COL-P-001`，置 `PROCESSED`，处理人=`SYSTEM`，记录关联事件 ID；重复消费不重复处理。
4. `COL-202608-001` 是商业类 LTV 预警，保持未处理，不能被设备核销误解除。

### A.7 T5 — 补仓后商业预警解除

货值恢复为 970 万，LTV=72.16%，业务订单处理页提交补仓完成并返回 `warn_id=COL-202608-001`。订单服务完成幂等校验后将该流水置 `PROCESSED`；返回 02/02 时按 `warn_id` 重新查询，列表显示已处理。若用户只有预警查看权限而无项目单据权限，点击“去处理”应固定提示且不跳转。

### A.8 边界用例

| 编号 | 场景 | 预期 |
| :--- | :--- | :--- |
| EC-01 | `SL-003` 的 `sync_to_order_warn=false` | 仅 02/01 有设备流水，不生成 02/02 穿透流水 |
| EC-02 | 同一 `DeviceEventReleased` 重复投递 | 02/02 仍只有 1 条 `COL-P-001`，处理接口幂等 |
| EC-03 | API 直接解除 `COL-P-001` | 返回“不支持人工解除物联穿透告警”，状态不变；统一走设备事件联动解除契约 |
| EC-04 | 订单已办结后设备事件到达 | 02/01 可保留设备事实；空间穿透不生成 02/02 押品流水，并记录拒绝原因 |
| EC-05 | 03/03 编辑普通阈值/等级 | 仅影响后续触发；`COL-202608-001` 的历史快照不变 |
| EC-06 | 关闭 `PRICE_DROP` 子项 | 主规则仍 `ACTIVE`；仅价格下跌未处理流水无效，LTV 流水不变 |
| EC-07 | 同订单尝试新增第二条综合规则 | R04 阻断并引导编辑 `OR-202608-001` |
| EC-08 | 抵/质押率平仓等级 `sort_order` 低于补仓等级 | 保存阻断；不比较 `severity_code` 字符串 |

## Part B — OPT-FUSE-01 未来预览（不纳入 6.2 验收）

只有业务中台锁定/解锁接口、幂等键、审计和独立版本上线后，才允许增加以下断言：

| 时点 | 未来行为 |
| :--- | :--- |
| T2 | 按最高 `sort_order` 和业务策略写入 `OUTBOUND_BLOCK` 或 `FULL_BLOCK` |
| T3 | 设备核销只触发风险重算，不直接解锁；由业务中台幂等解锁 |
| T5 | 商业预警解除后重新计算订单锁定范围 |

Part B 不得回写 Part A 的通过结果；6.2 页面和接口仍只展示/返回 `fuse_status=NONE`。

## 验收结论模板

| 检查项 | 通过条件 |
| :--- | :--- |
| 03/03 数据模型 | 一订单一综合规则；策略子项唯一；等级均为租户内 `severity_level_id` |
| 动态等级 | 用例可使用 `INFO/NOTICE/RISK/CRITICAL` 等非 L 编码；比较只按 `sort_order` |
| 商业闭环 | 补仓→平仓同记录升级→补仓解除，幂等且快照可追溯 |
| 物联闭环 | 05 事件→空间穿透→06 流水→按事件 ID 跳转→05 核销→06 联动解除 |
| 权限/路由 | 无权限不跳转；返回按 ID 重新查询；路由参数齐全 |
| 熔断 | Part A 全部 `fuse_status=NONE`，无用户筛选、按钮或阻断断言 |
