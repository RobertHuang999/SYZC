## 三、版本标识方案（推荐）

### 3.1 一句话方案

**一个顶栏总开关管住「框 + 点」，6.3 用琥珀、历史用灰，页面顶部给一行「变更计数」，不做花活。**

### 3.2 具体长什么样

**① 顶栏放一个三档开关（替代现在散落在页面里的开关）**

位置：现有「迭代记录」按钮旁边。文案：

| 档位 | 界面表现 |
| :--- | :--- |
| **只看 6.3 变更**（默认） | 6.3 改动区块显示琥珀虚线框 + 角标；历史红点全部收起，只留抽屉里的计数 |
| **全部原型** | 琥珀框照旧；历史红点变成**浅灰小圆点**（比现在的玫红弱一档），一眼能分出主次 |
| **还原线上** | 框和点全关，等于现在关掉高亮的效果 |

**② 6.3 改动区块的框**：沿用现有 `IterationHighlight` 的琥珀虚线框 + 左上角标签「6.3 新增 / 6.3 优化 / 6.3 联动」，一句话说明改了什么（现在没有这一句，建议补）。

**③ 历史模块不装饰，只加一条说明**：14-01、14-03 这类「6.2 已交付、6.3 无变更」的页面，页头放一行很轻的灰字：`6.2 已交付 · 本次无变更`。不画框、不加色块。

**④ 页面版本条**：每页顶部右角一行小字 `本页 6.3 变更 3 处 · 历史沿用 12 处`，点击展开清单，可直接跳到对应位置。研发走查时一眼知道这页动了多少。

**⑤ H5 端用轻量版**：H5 不适合虚线框（屏幕小、易花），改成区块左上角一枚小标签「6.3 新增」，配极淡琥珀底，不描边。

### 3.3 需要改的代码（成本很小）

1. 给标注类型加两个可选字段：`version`（如 `"6.3"`）与 `changeType`（新增/优化/联动），现有标注不填默认按「历史」处理。改 `B端PC/src/shared/annotations/PrototypeAnnotationLayer.tsx` 的类型即可，其余模块不用动。
2. 标注抽屉已有按类型筛选的入口，在同一处加「版本」筛选即可；历史点默认折叠成一行「历史沿用 12 处」。
3. `PartnerChangeFieldMark` 接入现有的「6.3 迭代高亮」上下文，让表单琥珀框能被总开关关掉。
4. 总开关从页面级挪到顶栏 `Header.tsx`，页面里的旧开关去掉，避免一页一个开关。
5. H5 新增一个轻量标签组件（大约 20 行），PC 与 H5 共用同一份标注数据。

### 3.4 不建议的做法

- **不建议把所有红点一律隐藏**：评审时要能翻到「这块为什么这么设计」的说明，全隐藏等于把依据也藏了。
- **不建议给历史区块加灰色底或删除线**：页面会变花，且历史就是线上现状，不该被画成「有问题」。
- **不建议在页面正文里写「6.3」字样**（现在设备预警处置弹窗就是这种）：那是评审信息，不是用户该看的，必须走规格对照层或标注层。

- [07 业务规则规格](./07-货品规格管理-入库收集项配置/入库收集项配置业务规则规格.md) 的【下游货品执行与入库单只读规则】(R06) 由「只配置三件事」改为「配置四件事」，新增第四件「下拉单选框适用候选项」：只存该货品实际适用的选项子集，选项池仍只读引用 07，默认全选、至少 1 项、不允许在货品端新建选项。
- 同文件与 [07 字段清单](./07-货品规格管理-入库收集项配置/入库收集项配置字段清单.md) 补齐版本修订记录（字段清单补 V2.8 / V2.9 缺档，版本升至 V3.0）。
- 字段清单「下游引用」口径由「品类总数」改为「引用的货品数量（不含已删除货品）」，与规则一致。

### 8.2 出入库「资料管理」金融类型隔离

- 共享组件增加 `allowSupplement` 开关：入库仅「普通入库」可事后补资料，出库仅「普通出库」可补。
- 质押、抵押、仓单、监管服务等金融货权单据进入【资料管理】时，不显示【补充本阶段资料】按钮，改为一条说明：按【出入库事后资料补充与审批穿透】(R33) /【出库流程后补充资料与审批穿透】(O18) 不允许后补，确需调整走抵质押资料管理追加流程。

### 8.3 待审单据不再进「已通过」台账

- 入库提交后只写入「入库申请」，不再向入库记录 Mock 插入 `checkStatus: 2` 的记录；提示语改为「已提交审核……审批通过后才会进入『入库记录』台账」，提交后跳转入库申请列表。

### 8.4 出库提货经办人绑定校验

- 个人提货未绑定「提货人信息」档案时直接阻断提交，提示「个人提货要先选好提货经办人（或点【快速添加提货经办人】建档），只手工填姓名和证号不能提交」，对应【提货经办人引用与快捷建档】(O06a)「禁止无引用仅手输提交」。

### 8.5 详情页基础信息改 DetailSection

- 入库、出库详情页的「基础信息」由原生 `table` 左右「标签-值」改为 `DetailSection` + `DetailField`（上标签下取值、4 列栅格，窄屏自动降为 3 列），备注信息整行铺满。
- 字段名对齐字段清单：出库改为「仓库名称 / 关联单号 / 备注信息」；入库补「货主类型」。

### 8.6 顺带修掉的两个问题（做 P1 时暴露）

- **资料管理还有两处上传入口没受控**：除各阶段的【补充本阶段资料】外，页头的【上传补充资料】按钮与「补充资料节点」的空态上传区也能绕过隔离，现已一并按单据类型收口。
- **入库详情切换单据会串数据**：详情页的数据只在首次进页面时取一次，从 A 单跳到 B 单仍显示 A 单。已改为跟随路由 id 重置（顺带重置标签页与展开状态）。

### 8.7 验证

- `B端PC` 类型检查通过；浏览器实测：入库详情（抵押入库）资料管理无任何上传入口并显示隔离说明，普通入库正常显示上传；出库质押单同样隔离、普通出库正常；两处详情基础信息均为上标签下取值；单据之间来回切换不再串数据。
