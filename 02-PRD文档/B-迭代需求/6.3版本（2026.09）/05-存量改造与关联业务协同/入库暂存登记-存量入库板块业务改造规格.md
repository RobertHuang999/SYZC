## 一、为什么要做调整及调整原则

### 1. 调整背景
现有的正式入库单要求非常严格：货主必须明确、如果是新货主必须通过短信验证码核实、货物必须分配到具体垛位不能有剩余、现场照片必须拍照上传。  
但在大宗商品仓库现场卸货时，经常遇到货主还没最终敲定、或者现场忙着卸车来不及分配垛位的情况，导致现场人员没法提交正式单。  
为了解决这个痛点，本次增加了独立的【入库暂存登记】功能。为了让大家用起来顺手，需要在现有的入库页面上增加快速切换和互相带入的通道。

### 2. 三大核心原则
1. **正式入库台账保持纯净**：正式的入库记录列表依然只展示审批通过的正式单据。任何未完成转正、还在暂存中的登记单，**绝对不混入**正式入库记录里。
2. **支持快速切换与带入**：在正式入库页面如果填不下去了，可以一键切换到暂存登记，并把刚才填好的信息带过去，不用重复录入；在暂存单里准备就绪后，也可以一键打开正式页面并把数据带过来。
3. **正式提交仍然严格要求**：虽然暂存登记放宽了要求，但后续要把暂存转为正式单时，必须依然补齐所有信息（确定货主、核对验证码、定好库位、上传照片），风控要求不降低。

## 二、电脑端 · 入库记录页面调整

### 1. 新增入库页面增加【入库暂存登记】通道
- **按钮位置**：在新增入库页面右上角操作栏，放在【取消】与【提交审核】按钮的左侧。
- **按钮样式**：次要操作按钮，文案为【入库暂存登记】。
- **点击交互**：
  - 点击后不直接跳转，而是弹出一个说明窗口，告诉用户暂存登记的作用和注意事项。

### 2. 切换说明弹窗内容
- **弹窗标题**：入库暂存登记说明
- **提示内容**：
  1. 适合现场货主暂时没定、来不及分配库位或拍照等紧急到货备忘情况；
  2. 暂存登记**不会**发起审批、**不会**生成正式入库单、**不会**增加实际库存、**不会**给货主发短信；
  3. 切换到暂存通道将**无损原样带入**已选的入库类型、关联单号（若已填）、SKU、库位与照片。
- **弹窗按钮**：
  - 【取消】：关闭弹窗，留在当前正式入库页继续填；
  - 【去空白登记页】：打开一张全新的空白暂存登记表；
  - 【带入内容并前往】：把当前已经填写的类型、单号、仓库、货品、数量、库位与照片无损复制过去，直接打开暂存登记页，避免重复输入。

### 3. 数据带入规则
| 正式页已有内容 | 带入暂存登记页后的处理 | 业务说明 |
| :--- | :--- | :--- |
| **入库日期** | 原样复制 | 继承已选日期 |
| **入库仓库** | 原样复制 | 继承已选仓库 |
| **入库类型** | **原样无损带入** | 支持普通/质押/抵押/监管服务/仓单，不再强制降级 |
| **关联单号** | **原样无损带入** | 若已填则带入（支持手填文本）；转正时执行系统单据匹配校验 |
| **货主信息** | 如果选了就带入，没选就留空 | 选了档案货主直接带入；没选货主时，暂存页支持直接手填临时说明 |
| **货品明细** | 原样复制 | SKU、计量、**收集项**、备注、**现场照片**、**补充资料**均可带入并在登记页继续编辑 |
| **存放库位** | 如果分了就带入，没分就留空 | 含库房/分区/**具体位置（文本20字）**/堆放数量；暂存页默认折叠且允许未分完 |
| **现场照片** | 原样复制 | 已经上传的照片带过去，暂存时不强制要求传照片 |

### 4. 追溯方式（正式单不展示来源暂存单号）
1. **正式入库单主表/详情/入库记录台账**：**不增加**【来源暂存单号】字段；与直接新建的正式单展示一致。
2. **暂存侧互链**：登记单【已转正式】后在本菜单展示【关联正式入库单号】，可跳转正式流程/详情。
3. **审批中心**：可通过流程扩展信息或按正式单号反查暂存登记详情（司机交接、过磅备忘）；不要求在正式单头展示 REG 单号。
4. **正式单驳回/撤回**：登记单自动回退【待补全】（P10），可再次发起转正。

## 三、手机端（小程序）· 入库板块调整

### 1. 业务发起 · 入库发起页面调整
1. **表单顶部增加切换提示条**：
   - 在手机端填写入库单的顶部，增加显眼的黄色提示条：*“货主未在场或未分垛？点击切换为【入库暂存登记】”*；
   - 点击后同样弹出说明弹窗，支持“带入内容并前往”或“去空白登记页”。
2. **发起列表新增独立入口**：
   - 在手机端「业务办理 → 业务发起」页面中，除了已有的【入库发起】外，增加独立的【入库暂存登记】入口卡片；
   - 现场人员点击后，可直接打开极简的暂存登记页面快速录入。

### 2. 工作台 · 仓储管理板块调整
1. **工作台增设独立菜单**：
   - 在「工作台 → 仓储」模块中：
     - 保留原有的【入库管理】（专门用来查看和管理正式入库单）；
     - **新增独立的【入库暂存登记】菜单**，方便专门查看和处理现场的暂存单。
2. **手机端暂存列表与详情功能**：
   - **列表页面**：卡片式展示单号、时间、货主（或“待确认”标签）、仓库、数量和状态；顶部提供状态切换栏（全部 / 待补全 / 已转正式 / 已作废）；
   - **详情页面**：支持现场直接调用手机拍照补充照片；
   - **转正式按钮**：在【待补全】的单据底部，提供【转为正式入库】主操作按钮；确认后打开 **入库发起** `/m/inbound/initiate?sourceRegId={REG}`（步骤 ② 货品页同参预填，H5 **P10**）；**仓单**暂存从 PC 转正 likewise 须走该 H5 链路（P06/R04f）。

## 四、对其他业务的影响说明

### 1. 仓库实物盘点协同
- **现场实物比账面多的情况**：
  - 货物已经卸在仓库，但目前还处于暂存登记状态（还没转正），这时仓库系统账面上是没有这笔库存的。如果此时进行盘点，会出现“实物比系统账面多”的情况；
- **处理方式**：
  - 盘点人员发现库里有多出来的货物时，先去查一下【入库暂存登记】列表，看是不是有对应的【待补全】暂存单；
  - 如果核对一致，在盘点记录里备注写明即可（例如：*“经核对为暂存单 REG-20261013-0001，待货主确认后转正入库”*）；
  - **严禁直接自动平账**：不允许直接把盘多出来的货物通过盘盈功能调整进系统账，必须由业务人员把暂存单正规转为正式入库单并审批通过。

### 2. 各业务板块协同说明表

| 业务板块 | 关联影响与配合机制 | 页面改动要求 |
| :--- | :--- | :--- |
| **仓储 · 入库记录** | 新增页【入库暂存登记】与 `sourceRegId` 预填；详情无来源暂存字段 | O01 弹窗；仓单转正提示手机操作 |
| **仓储 · 盘点管理** | 卸货但未转正时盘点会出现账面货物偏少 | **P11**：查暂存台账备注，禁止盘盈自动平账（已写入暂存三件套） |
| **风控 · 合作企业档案** | 暂存时允许暂不确定货主；转正式时必须选定正式合作企业并做验证码核实 | 暂存阶段不创建假货主；转正式时严格执行企业核验 |
| **审批中心 · 入库审核** | 正式单提交后进入审批 | 可选扩展字段或反查暂存 REG，正式单头不展示来源暂存 |
| **库存与条码中心** | 暂存阶段不增加库存、不生成条码；正式审批通过后才增加库存和发码 | 保持既有库存入账逻辑不变，不影响条码系统 |
