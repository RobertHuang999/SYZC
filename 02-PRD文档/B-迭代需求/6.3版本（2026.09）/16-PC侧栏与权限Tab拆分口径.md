## 一、为什么要单独写（与三件套的关系）

| 做法 | 6.3 是否采用 | 说明 |
| :--- | :---: | :--- |
| 在 CSV 里删掉 Tab 行，只留侧栏菜单 | **否** | Tab 行承担 **RBAC 按钮/子能力**、权限页路径 `顶栏模块 / 一级 / 二级 / Tab`，不能为修侧栏而削弱权限粒度 |
| 把 Tab 全部画进侧栏子菜单 | **否** | 与线上一致体验及 6.2 已定 **监管管理三 Tab** 等产品口径冲突 |
| **本文写「侧栏 vs Tab」映射 + 回写基准清单** | **是** | 研发、原型生成脚本、测试验收 **侧栏树** 时以本文为准；权限对照页仍可按 CSV 全路径展示 |

**变更顺序（合并进最新基准版时）**：先更新本文与 `00-菜单模块映射.md` → 再按需回写各菜单主 PRD「页面功能说明」中的 **导航结构** 段落 → 最后同步 ASCII / 原型标注（**不**反向改 CSV 权限行，除非产品主动合并权限粒度）。

## 二、核心原则（说人话）

1. **侧栏**回答：用户从哪个 **菜单入口** 进模块（与工作台卡片、顶栏模块一致）。
2. **CSV 的 Tab** 回答：在这一入口下，还有哪些 **可单独授权** 的页面视图或子能力；**多数情况下是页内 Tab 或看板内功能**，不是第二级侧栏项。
3. **原型路由**可保留 Tab 级 path（书签、占位页、深链）；**`generatedMenuPaths`** 含全路径，**`generatedSidebarGroupsByModule`** 仅含侧栏项。
4. **6.2 已写清三 Tab 的菜单**（监管管理）：以基准三件套 + [04-融资监管-菜单更名与监管管理口径.md](../6.2版本（2026.08）/04-融资监管-菜单更名与监管管理口径.md) 为准，CSV Tab 行只作权限拆分。

### 2.1 侧栏形态分类（PC）

| 类型 | 含义 | 侧栏展示 | CSV 典型结构 | 6.3 示例 |
| :--- | :--- | :--- | :--- | :--- |
| **A · 单页单入口** | 一级即页面，无二级侧栏项 | 分组下 **1 项**，名与一级相同 | 一级=菜单名，二级=-，Tab=- 或 Tab=页内 | 客户管理、监管档案（见下表） |
| **B · 二级 hub + 页内 Tab** | 二级菜单是一个页面，Tab 在页顶切换 | 分组下 **1 项**（二级名） | 一级=业务域，二级=页面，Tab=订单类型等 | 监管管理 + 抵押/质押/监管服务 |
| **C · 多二级并列** | 多个独立页面同属一级分组 | 分组下 **多项**（各二级各一项） | 各二级 Tab=- | 监管办理 + 监管管理（两项并列） |
| **D · 权限 Tab、非侧栏** | Tab 只登记权限，UI 挂在父页内 | **不出现** 在侧栏 | Tab=子能力名 | 链接分享记录 |

## 四、原型与菜单生成脚本（已实现，供验收对照）

| 规则 | 脚本常量 / 逻辑 | 作用 |
| :--- | :--- | :--- |
| 一级 hub + Tab | `SIDEBAR_HUB_ONLY_LEVEL1` = `监管档案` | 侧栏仅 `/用户中心/监管档案` |
| 二级 hub + Tab | `SIDEBAR_HUB_ONLY_LEVEL2` = `监管管理` | 侧栏仅 `…/监管管理`，Tab 路由仍进 `generatedMenuPaths` |
| 权限 Tab、非侧栏 | `SIDEBAR_EXCLUDED_TABS` = `链接分享记录` | 不进侧栏 catalog，路由保留 |
| 监管办理 | `navigation.ts` · `financeSidebarGroupsWithSupervisionMgmt` | 监管业务分组固定 **办理 → 管理** 顺序 |

**验收自检（PC 原型）**：

1. 用户中心展开「监管档案」：子菜单 **只有 1 项**「监管档案」。
2. 融资/监管 → 监管业务：**监管办理、监管管理** 两项；**无** 抵押/质押/监管服务订单子链。
3. 风控 → 风控中心：**无**「链接分享记录」侧栏项；看板路由仍可直达占位页。
