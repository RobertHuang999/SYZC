# 设备操作的历史逻辑和规则

> **文档定位**：记录监控设备菜单已确认的历史操作逻辑、弹窗规则及跨模块联动规则，作为后续监控设备主 PRD、功能清单和关联模块 PRD 的整理依据。
>
> **适用范围**：重命名、仓库绑定、查看直播、查看回放、图像锚点、移除设备。
>
> **规则边界**：监控设备菜单当前以弹窗操作和配置操作为主，不建立监控设备业务状态机；“预警已失效”等预警状态由“风险-设备预警信息”模块负责。
>
> **版本**：V1.0 | 更新时间：2026-08-06
>
> **说明**：本文件为历史规则汇总，不替代后续正式主 PRD、功能清单、字段清单或风险模块规则；最终落地时应按文末归属建议拆分引用。

## 设备分类

| 规则项 | 历史规则 |
| :--- | :--- |
| 字段名称 | 设备分类 |
| 分类数量 | 2 种 |
| 分类一 | 视频监控；属于历史数据 |
| 分类二 | 人脸门禁；属于新增设备分类，具备摄像头功能，是摄像头的一种类型 |
| 菜单展示 | 同一设备 ID按设备能力归属并展示到不同菜单；人脸门禁因具备摄像头能力，可同时存在于“监控设备”和“人脸门禁”菜单中 |
| 操作能力 | 人脸门禁设备在“监控设备”菜单中可使用与视频监控一致的摄像头操作，包括“查看直播”“查看回放”“图像锚点”等 |

> 人脸门禁虽然可在“人脸门禁”菜单中独立管理，但因其具备摄像头功能，也属于监控设备范围；两个菜单中的设备记录是否共用同一设备主数据和操作权限，需在正式主 PRD及权限规则中保持一致。

## 设备名称来源优化

| 规则项 | 历史规则 |
| :--- | :--- |
| 设备原名称 | 三方平台同时返回设备名称和通道名称时，优先展示设备名称与通道名称的拼接名称 |
| 名称兜底 | 三方平台未返回通道名称或通道名称为空时，使用设备名称 |
| 系统内名称默认值 | 系统内名称首次默认取设备原名称的展示值 |
| 人工重命名 | 用户重命名后，以保存的系统内名称为准；后续三方名称变化不得覆盖人工维护值 |

> 具体拼接分隔符及三方通道名称为空字符串、空格字符串的判定规则，待接口和前端展示规范确认。

## 一、重命名

| 规则项 | 历史规则 |
| :--- | :--- |
| 操作入口 | 从列表“操作”列进入重命名弹窗 |
| 数据可见范围 | 已绑定仓库的设备：登录用户拥有对应仓库数据权限时可见；未绑定仓库的设备：所有登录用户均可见 |
| 名称限制 | 系统内名称最多 50 个字；是否允许空值、特殊字符及是否需要同租户唯一，历史规则未明确 |
| 操作结果 | 更新设备的系统内名称，并更新设备的修改人员和更新时间 |
| 无权限处理 | 无对应仓库数据权限的设备不返回数据，也不展示重命名入口 |

> “所有登录用户”仍需服从租户隔离和账号有效性校验。该规则只解决数据可见范围，不等同于角色操作权限；最终主 PRD需补充重命名操作权限矩阵。

## 二、仓库绑定

### 2.1 选择与展示规则

| 规则项 | 历史规则 |
| :--- | :--- |
| 选择层级 | 仓库、库房、分区三级联动选择 |
| 仓库数量 | 一个设备最多绑定一个仓库 |
| 库房数量 | 同一仓库下可勾选多个库房 |
| 分区数量 | 同一仓库下可勾选多个分区 |
| 层级约束 | 已选库房和分区必须全部归属于同一个已选仓库；分区必须归属于对应库房 |
| 权限范围 | 按登录账号的数据权限展示和选择仓库；无权限仓库不可见、不可选 |
| 仓库必填性 | 仓库非必选 |
| 已选信息 | 选中后，在弹窗下方展示当前已勾选的仓库、库房和分区信息 |
| 具体位置 | 非必填；用户可根据实际情况补充；最多 50 个字 |

### 2.2 按钮和保存规则

| 操作 | 历史规则 |
| :--- | :--- |
| 取消 | 关闭弹窗，不保存本次仓库、库房、分区和具体位置变更 |
| 确认 | 保存或更新仓库绑定信息；保存前由后端校验设备当前订单绑定情况 |
| 有效订单校验 | 如果设备已绑定申请中，或处于抵/质押中、监管中的抵/质押订单或监管订单，则不允许更新仓库绑定规则 |
| 阻断提示 | “该设备已绑定有效订单，请先解绑后再修改。” |
| 解绑前置 | 需先解除设备与有效订单的绑定，再重新进入仓库绑定弹窗修改信息；仓库绑定弹窗不负责解除有效订单绑定 |

> 订单绑定校验必须由后端在保存前再次执行，不能只依赖前端展示结果；并发创建订单或并发修改绑定时，需要使用数据版本、锁或等效机制防止绕过校验。

## 五、图像锚点

### 5.1 配置入口与分组规则

| 规则项 | 历史规则 |
| :--- | :--- |
| 操作入口 | 从列表点击“图像锚点”，进入该监控设备的图像锚点页面 |
| 配置对象 | 针对当前监控设备进行锚点配置 |
| 配置组数量 | 可配置多组；最多创建的组数量与后端返回的监控类型数量一致；当前已确认监控类型为 3 种，最多 3 组 |
| 监控类型唯一性 | 每组单选一个监控类型，不同组之间的监控类型不允许重复 |
| 每组保存 | 每组配置单独保存，不要求所有组一次性提交 |

### 5.2 单组配置规则

| 配置项 | 历史规则 |
| :--- | :--- |
| 锚点区域 | 背景为打开时捕捉到的监控画面中的一帧静态图片，不使用动态视频作为绘制背景 |
| 锚点绘制 | 鼠标可操作锚点，绘制闭合形态；至少 3 个点位 |
| 坐标保存 | 按原始监控画面分辨率保存锚点坐标；前端展示时根据当前画面尺寸进行比例换算 |
| 时间模板 | 由后端返回可选项，例如“全天模板”；每组单选一个时间模板 |
| 监控类型 | 行人入侵检测、车辆入侵检测、物品形态监控；每组单选一个监控类型 |
| 重置锚点 | 点击后仅清空当前前端画布中的锚点，不删除已保存配置；其他画布按钮以实际前端实现为准 |

### 5.3 保存、离开和删除规则

| 操作 | 历史规则 |
| :--- | :--- |
| 未保存离开 | 单组配置完成但未点击保存，离开页面时弹窗：“当前配置尚未保存，是否确认离开？” |
| 未保存离开-确定 | 关闭弹窗并离开当前页面，不保存当前未保存配置 |
| 未保存离开-取消 | 关闭弹窗，停留当前页面 |
| 删除确认 | 点击删除时弹窗：“您正在删除${页签名称}的锚点，删除后预警不可用？” |
| 删除确认-确定 | 完成删除并关闭弹窗；调用赛达删除云端算法任务接口 |
| 删除确认-取消 | 关闭弹窗，不删除锚点 |
| 删除单组 | 仅关闭该监控类型的图像预警 |
| 删除接口失败 | 三方删除接口失败时保留本地锚点配置，不得将本地配置误标记为已删除；失败提示和重试方式待主 PRD补充 |
| 删除全部 | 锚点信息全部删除后，同步关闭该监控设备的图像预警配置，后续不再触发图像预警 |

> 锚点类型唯一性、组数量上限、闭合区域和至少 3 个点位必须由后端再次校验；前端校验通过不能替代服务端校验。

## 六、移除设备及跨模块联动

### 6.1 移除设备定义

| 规则项 | 历史规则 |
| :--- | :--- |
| 动作名称 | 平台端“删除设备”和当前操作“移除设备”是同一个动作，统一称为“移除设备” |
| 设备端结果 | 移除成功后，设备从监控设备管理页面移除 |
| 订单关联校验 | 移除设备前需校验设备与抵质押订单、监管订单及设备预警配置的关联情况 |

### 6.2 抵质押订单历史详情

| 规则项 | 历史规则 |
| :--- | :--- |
| 快照保留 | 设备移除后，抵质押订单历史详情仍保留对应设备快照信息 |
| 手动删除 | 用户需在订单历史详情中手动删除该设备展示信息 |
| 删除边界 | 用户手动删除时，仅删除订单历史详情中的设备展示关系；历史审计记录和设备快照继续保留，不删除业务追溯数据 |

### 6.3 风险预警联动

| 规则项 | 历史规则 |
| :--- | :--- |
| 未解除预警 | 设备移除时，如果该设备已经产生预警且预警尚未解除，后端将预警状态更新为“已失效” |
| 处理归属 | 预警状态更新和后续预警处理由“风险-设备预警信息”模块负责 |
| 监控设备展示 | 监控设备端只负责查看关联预警，不负责处理或解除预警 |

### 6.4 移除设备确认与执行流程

#### 6.4.1 确认弹窗

| 规则项 | 历史规则 |
| :--- | :--- |
| 弹窗标题 | “提示” |
| 提示内容 | “您正在操作${设备类型}:${系统内设备名称}的移除，请确认是否继续该操作！移除设备后该设备产生的所有未处理风险状态会失效，所绑定的订单会解绑，所涉及的预警规则、通知规则会解除该设备绑定。如需继续请点击确认！” |
| 说明字段 | 弹窗包含“说明”文本域，截图中标记为必填；用于记录本次移除说明 |
| 取消 | 取消本次移除操作，不执行后续解绑和失效处理 |
| 确认 | 提交移除设备操作，进入后端移除处理 |

#### 6.4.2 确认后的系统处理

| 执行动作 | 历史规则 |
| :--- | :--- |
| 订单维度风险状态 | 将该设备未处理的订单维度风险状态置为“已失效”，失效原因为“设备移除” |
| 设备维度风险状态 | 将该设备未处理的设备维度风险状态置为“已失效”，失效原因为“设备移除” |
| 订单绑定 | 解绑该设备绑定的订单 |
| 订单风控规则 | 解除该设备与涉及订单风控规则的绑定 |
| 设备预警规则 | 解除该设备与涉及设备预警规则的绑定 |
| 通知规则 | 解除该设备与涉及通知规则的绑定 |
| 仓库绑定 | 解绑该设备绑定的仓库 |

#### 6.4.3 执行结果

| 结果 | 历史规则 |
| :--- | :--- |
| 成功判断 | 系统判断移除设备相关处理是否成功 |
| 成功提示 | Toast：“移除设备成功” |
| 成功审计 | 后端落库记录操作人、操作时间、操作事项和移除说明 |
| 失败提示 | Toast：“移除设备失败，请联系管理员” |
| 失败处理 | 任一子操作失败时，全部撤回本次移除操作产生的变更 |

### 6.5 移除后设备重新加入

| 规则项 | 历史规则 |
| :--- | :--- |
| 有效列表 | 移除成功后设备不展示在监控设备有效列表中 |
| 三方同步 | 系统每 5 分钟轮询三方设备接口 |
| 重新加入 | 轮询发现被移除设备仍存在时，按原设备 ID重新加入设备数据和有效列表 |

## 九、历史功能优化规则（2025-07-23）

### 9.1 设备绑定规则升级

| 优化项 | 历史规则 |
| :--- | :--- |
| 绑定维度扩展 | 用户设备绑定范围从单一分区级别扩展为支持仓库、库房、分区三级中的任意一级绑定 |
| 仓库级绑定 | 仓库级别绑定仅支持单选，不允许同时绑定多个仓库 |
| 库房级绑定 | 库房级别绑定支持多选，可同时绑定多个库房 |
| 分区级绑定 | 分区级别绑定支持多选，可同时绑定多个分区 |

> 该历史规则与本文件前文“一个设备绑定一个仓库，并在仓库下选择多个库房和分区”的规则存在口径差异。后续主 PRD需确认：绑定是“三级任意一级择一绑定”，还是“选择一个仓库后继续选择其下库房和分区”。

### 9.2 门锁预警抓拍范围优化

| 优化项 | 历史规则 |
| :--- | :--- |
| 抓拍范围 | 门锁预警，包括订单预警和设备预警，抓拍范围调整为触发区域本级及下一级关联监控设备 |
| 不抓拍范围 | 不抓拍触发区域的上级区域、同级其他区域及更深层级区域监控设备 |
| 仓库层级示例 | 仓库A下设库房1、库房2；库房1下设分区X；库房2下设分区B |
| 触发示例 | 库房1触发门禁预警时，抓拍库房1本级监控设备和库房1下一级分区X监控设备 |
| 排除示例 | 仓库A、库房2及库房2下属分区B的监控设备不触发本次抓拍 |

#### 9.2.1 设备绑定与抓拍范围展开规则

##### 核心层级关系

- 抓拍范围以仓库、库房、分区为层级维度。
- 仓库下设库房，库房包含下属分区；库房是分区的上级单元。
- 设备绑定到不同层级时，按绑定层级向下展开抓拍范围。

##### 绑定层级规则

| 设备绑定范围 | 抓拍范围 |
| :--- | :--- |
| 仅绑定某仓库 | 抓拍该仓库、该仓库下属全部库房，以及所有库房下属的全部分区 |
| 绑定某库房，未绑定该库房下属的具体分区 | 抓拍该库房，以及该库房下属的全部分区 |
| 绑定某库房的具体分区 | 仅抓拍该“仓库-库房-分区”具体单元 |

##### 多选示例

| 示例 | 设备绑定 | 抓拍范围 |
| :--- | :--- | :--- |
| eg1 | 同时绑定库房A（未绑定具体分区）和库房B-分区2 | 抓拍库房A、库房A-分区1、库房A-分区2，以及库房B-分区2 |
| eg2 | 绑定仓库A | 抓拍仓库A、仓库A下属全部库房，以及全部库房下属的所有分区 |
| eg3 | 绑定库房B-分区2 | 仅抓拍库房B-分区2 |

> 多个绑定项同时存在时，抓拍范围按各绑定项展开后的结果取并集，并对重复监控设备去重。具体绑定项之间的父子覆盖关系、同一库房同时选择库房级和分区级时的优先级，待主 PRD和接口规则进一步确认。

#### 9.2.2 多区域绑定设备的位置展示

| 问题 | 历史规则 |
| :--- | :--- |
| 抓拍时摄像头绑定多个区域如何展示位置 | 展示该摄像头绑定的全部位置信息 |
| 展示范围 | 展示摄像头全部绑定的仓库、库房、分区路径，不仅展示本次触发抓拍的命中区域 |

### 9.3 订单绑定设备展示规则

| 新逻辑 | 展示货物所在仓库匹配的监控设备，展示范围扩大到仓库级匹配结果 |

### 9.4 出入库及移库抓拍范围

| 业务动作 | 历史规则 |
| :--- | :--- |

| 移库 | 抓拍仓库、仓库下属库房及所有库房下属分区的监控设备 |

## 十、仓库绑定字段与编辑规则历史优化

### 10.1 2025-07-23：仓库字段拆分

| 优化项 | 历史规则 |
| :--- | :--- |
| 字段拆分 | 原“仓库”字段拆分为“仓库”和“库房分区”两个下拉字段 |
| 展示联动 | 选择仓库后，才展示“库房分区”下拉字段 |
| 仓库 | 下拉单选框，非必选 |
| 库房分区 | 下拉多选框，非必选；支持跨选多个库房，也支持跨选多个分区 |
| 具体位置 | 沿用原有规则，非必填，用户可根据实际情况补充，最多 50 个字 |
| 已选位置 | 用户选择仓库或库房分区后，展示对应的已选位置信息 |
| 名称调整 | 原“已选仓库”区域改名为“已选位置” |

### 10.2 2025-08-06：绑定信息可编辑为空

| 优化项 | 历史规则 |
| :--- | :--- |
| 编辑为空 | 设备已经绑定位置时，允许编辑为绑定为空 |
| 保存前校验 | 编辑保存前由后端校验设备是否绑定抵质押监管订单 |
| 有效订单阻断 | 如果设备已绑定抵质押监管订单，则不允许编辑为空或更新绑定信息 |
| 阻断提示 | Toast 沿用原“设备绑定抵质押监管订单”编辑校验提示，具体提示文本以历史页面实现为准 |
| 无有效订单 | 未绑定抵质押监管订单时，允许保存为空 |

> 本规则细化了仓库绑定更新逻辑：绑定为空不代表可以绕过有效订单校验；存在有效抵质押监管订单时，仍必须先解除订单绑定后再更新设备绑定信息。
