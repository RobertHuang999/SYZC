## 一、单据与能力定位

| 项目 | 内容 |
| :--- | :--- |
| **单据层级** | **【第2层-订单/执行控制层】**（库存业务层——加工管理控制单据） |
| **核心职责** | 规范存货在仓储监管期间因切割、拆分、熔炼、组装等产生的加工业务，锁定投入库存，记录实际消耗与余量释放，入库产出存货并生成存货条码，实现抵/质押货权的无缝继承与全路径追溯。 |
| **单据来源** | 业务操作人员或仓库监管人员在 PC 端或移动端（App/PDA）手动发起。 |
| **上游依赖** | **货主档案**：提供货主主体 ID、名称和数据权限；<br/>**可用库存明细**：提供库存批次/条码、仓库/库房/分区、可用数量和货权状态；<br/>**抵押单、质押单**：提供有效单据 ID、货权状态和物料清单，业务规则由下游融资单据维护；<br/>**货品基础信息**：读取大类、品类、规格、计量单位和单价（继承自 [货品管理字段清单](../货品规格管理/03货品管理/货品管理字段清单.md)）。 |
| **下游影响** | **库存锁定与扣减**：提交时锁定投入库存流水，完成时原子扣减实际消耗库存；<br/>**余量释放**：完成时释放未消耗余量，单据终止（驳回/撤回/作废）时全额释放计划投入库存；<br/>**产出入库与条码**：生成产出库存并由系统生成全局唯一存货条码；<br/>**货权继承**：更新原抵质押单物料清单（旧条码置为已出库，新条码追加入单）；<br/>**全链路审计**：写入全生命周期操作与库存审计流水。 |
| **审核流** | **【有审核流】**（创建提交 ➔ 锁库 ➔ 审批中 ➔ 审批通过 ➔ 待完成 ➔ 登记完成 ➔ 已完成）。 |

## 二、数量与金额口径隔离表

| 口径名称 | 存在位置 | 业务含义与计算公式 | 约束与边界条件 |
| :--- | :--- | :--- | :--- |
| **一级计划投入量** | 投入明细（头部汇总） | 同一规格（大类+品类+规格）下全部二级计划投入量之和 | 必须等于同规格二级计划投入量之和；公式：$\text{一级计划量} = \sum \text{二级计划量}$ |
| **二级计划投入量** | 投入明细（行级） | 针对特定库存批次/条码填写的计划投入数量 | $0 < \text{二级计划投入量} \le \text{提交时实时可用库存}$ |
| **实际消耗数量** | 投入明细（行级） | 完成加工时填写的实际物理消耗数量 | $0 < \text{实际消耗数量} \le \text{二级计划投入量}$（严禁为 0） |
| **释放数量** | 投入明细（行级） | 完成加工：$\text{计划投入量} - \text{实际消耗量}$；终止态（撤回/驳回/作废）：$\text{全额计划投入量}$ | 必须由系统自动计算与流水回写，禁止手工修改 |
| **预计产出数量** | 产出明细（行级） | 申请时填写的预计产出数量 | $\text{预计产出数量} > 0$；提交后产出 SKU 结构强行冻结 |
| **实际产出数量** | 产出明细（行级） | 完成加工时填写的实际产出入库物理数量 | $\text{实际产出数量} > 0$；允许大于或小于预计产出数量 |
| **预计产出总金额** | 统计汇总区域 | $\sum (\text{预计产出数量} \times \text{行业参考单价})$ | 仅汇总有价行；缺价提示「存在未定价货物」，不阻断提交 |
| **实际产出总金额** | 统计汇总区域 | $\sum (\text{实际产出数量} \times \text{行业参考单价})$ | 仅汇总有价行；缺价提示「存在未定价货物」，不阻断完成 |
| **加工损耗比例** | 单据主表/汇总 | 手动录入的实际物理损耗百分比；范围 $0\% \sim 100\%$ | 仅做整单记录留痕，严禁参与库存扣减与货值/安全线计算 |

## 三、状态定义

| 状态名称 | 枚举值 (`Enum`) | 业务含义 | 是否终态 | 进入条件 | 离开条件 |
| :--- | :--- | :--- | :---: | :--- | :--- |
| **审批中** | `PENDING_APPROVAL` | 单据已提交，计划投入库存已成功锁定，正在等待审批流裁决 | 否 | 校验通过且计划投入库存锁定成功 | 审批通过 / 审批驳回 / 申请人撤回 |
| **待完成** | `PENDING_COMPLETION` | 审批流已通过，计划投入库存保持锁定，等待现场仓库监管员登记实际加工结果 | 否 | 审批流“审批通过”节点执行成功 | 完成加工成功 / 授权人员执行作废 |
| **已完成** | `COMPLETED` | 实际消耗扣减、余量释放、产出入库、条码生成及货权继承事务执行成功，单据锁定 | **是** | 完成加工原子事务整体执行成功 | — （终态不可逆，不支持业务冲正或作废） |
| **已驳回** | `REJECTED` | 审批流拒绝该申请，已被驳回，计划投入库存全额解锁释放 | **是** | 审批节点执行“驳回”动作 | — （终态留痕） |
| **已撤回** | `WITHDRAWN` | 申请人在审批完成前主动撤回，计划投入库存全额解锁释放 | **是** | 申请人在审批中执行“撤回”动作 | — （终态留痕） |
| **已作废** | `VOIDED` | 待完成状态下授权人员执行作废，计划投入库存全额解锁释放 | **是** | 有作废权限人员执行“作废”动作 | — （终态留痕） |

## 六、核心业务规则（R01 ~ R35）

### 1. 申请与前置校验规则

#### R01：业务时间合规性
- 加工日期只能选择不晚于当前系统时间的日期时间，默认当前时间，精确到秒；禁止录入未来时间。

#### R02：货主主体与明细联动
- 支持企业货主与个人货主；货主变更时，前端清空已选的投入货物与关联单号，防止出现跨主体数据污染。

#### R03：加工类型与库存状态匹配
- **普通存货**：仅允许选择状态为 `存货中` 且无任何锁定的在库可用库存；
- **抵押货 / 质押货**：必须关联对应的有效抵押单或质押单，且仅能选择该单据名下的抵质押在库货物。

#### R04：抵质押关联与仓单货物强过滤
- 抵押或质押加工仅允许关联处于正常在押状态的单据；
- **仓单强过滤**：若抵质押单中的货物已开具数字仓单，系统强行过滤并禁止选择，阻断提示「仓单货物不可发起加工，请先解单」。

#### R05：投入货物“三同”校验
- 单张加工单内所有的投入明细，必须同时满足：**同一货主**、**同一实体仓库**、**同一加工类型**。
- 用户选择第一条投入货物后，系统自动锁定单据的货主、仓库与加工类型。

#### R06：计划投入量与即时锁库
- 每条二级计划投入量必须满足 $0 < \text{计划量} \le \text{提交时实时可用量}$；
- 提交成功后，系统即时锁定对应库存数量，扣减可用量，打上“加工锁定”标记，防止其他业务并发争抢。

#### R07：产出有效性与结构冻结
- 每条产出货物的预计产出数量必须 $> 0$；
- **无效操作拦截**：若整张加工单的投入与产出 SKU 完全相同且数量完全相等，系统判定为无效操作并阻断提交；
- 提交成功后，产出货物的 SKU 结构强行冻结，后续完成加工时不允许新增、删除或替换产出 SKU。

### 2. 审批与作废控制规则

#### R11：审批通过流转规则
- 审批流所有节点通过后，单据状态变更为 `PENDING_COMPLETION`（待完成）；计划投入库存继续保持锁定状态。

#### R12：审批驳回与库存释放规则
- 审批流中任一节点执行驳回，单据状态变更为 `REJECTED`（已驳回）；系统在同一事务内全额解锁并释放该单据锁定的全部计划投入库存。

#### R13：申请人撤回与库存释放规则
- 仅单据申请人在单据处于 `PENDING_APPROVAL`（审批中）状态时可执行撤回；
- 撤回后单据变更为 `WITHDRAWN`（已撤回），终止审批流并全额释放锁定库存。

#### R14：待完成单据作废规则
- 单据处于 `PENDING_COMPLETION`（待完成）状态时，具备作废权限的人员可执行作废；
- 必须填写作废原因；作废成功后单据变更为 `VOIDED`（已作废），全额释放锁定库存并记录审计日志。

### 3. 完成加工与产出入库原子事务

#### R21：实际产出数量合规性
- 完成加工登记时，每条产出货物的实际产出数量必须 $> 0$；允许大于或小于预计产出数量，但不得为 0 或负数。

#### R22：产出入库位置与同仓强约束
- 产出货物的入库仓库必须与单据主表仓库**强一致**（严禁跨仓产出）；允许在同仓下选择不同的库房、分区及具体位置；
- 产出具体位置为必填项，缺失强行阻断完成登记。

#### R23：实际消耗数量超额强拦截
- 现场填写的每条二级实际消耗数量必须满足 $0 < \text{实际消耗} \le \text{二级计划投入锁定量}$；
- 若录入的实际消耗大于锁定量，强行阻断提交并提示「实际消耗数量不得大于计划投入锁定量」；
- 若某条投入货物完全未使用，不允许填 0，应作废当前加工单后重新发起申请。

#### R24：计划余量自动释放机制
- 完成加工登记提交后，系统自动计算每条投入明细的余量：$\text{释放数量} = \text{计划投入量} - \text{实际消耗量}$；
- 系统在完成加工事务内自动生成库存解锁流水，将余量无缝释放回可用库存。

#### R25：加工损耗留痕规则
- 完成加工必须录入加工损耗比例（$0\% \sim 100\%$）及损耗说明；无损耗录入 `0%`；
- 损耗数据仅作为单据技术指标留痕，严禁参与库存数量扣减、产出货值核算或抵质押安全线计算。

#### R26：存货条码生成与货权无缝继承
- 产出货物入库成功后，系统自动为每条产出货物生成全局唯一的**存货条码**；
- **抵质押货权继承**：若本次加工为抵押货或质押货：
  1. 系统将原抵押单/质押单物料清单中被消耗的原存货条码状态置为 `已出库(加工)`；
  2. 将新生成的产出存货条码、规格、数量追加写入原抵押单/质押单物料清单中，实现货权链路不中断。

### 4. 价格计算、影像抓拍与并发审计

#### R31：缺价统一提示口径
- 产出货物单价统一继承自货品管理中的行业参考单价；
- 若货品未设置单价，单价列展示 `--`，汇总区域提示「存在未定价货物」，系统不阻断加工申请提交或完成登记。

#### R32：产出金额试算公式
- $\text{预计产出总金额} = \sum (\text{预计产出数量} \times \text{行业参考单价})$（仅汇总有价行）；
- $\text{实际产出总金额} = \sum (\text{实际产出数量} \times \text{行业参考单价})$（仅汇总有价行）。

#### R33：IoT 现场抓拍与降级容错
- 提交申请时系统自动调用投入仓库摄像头与联网设备抓拍现场图像；
- 若现场无监控设备或调用超时/失败，系统记录异常状态（“无监控设备”或“抓图失败”），不阻断加工申请的正常提交。

#### R34：并发乐观锁与排他控制
- 单据操作基于 `version` 乐观锁；多用户并发操作同一单据或同一库存批次时，后提交者直接提示「数据已被修改，请刷新后重试」；
- 完成加工接口采用严格的分布式幂等防重锁，防止网络重发导致重复入库。

#### R35：全生命周期操作审计
- 提交、审批、撤回、作废、完成及异常失败操作，全量记录操作人、角色、IP、时间戳、请求标识及前后数据快照。

### 1. 加工申请提交与库存锁定时序

```mermaid
sequenceDiagram
    autonumber
    actor U as 业务人员/监管员
    participant F as 前端界面
    participant B as 加工管理服务
    participant W as WMS库存服务
    participant IoT as 物联网监控
    participant DB as 数据库

    U->>F: 选择货主、类型、在库货物及预计产出，点击【提交申请】
    F->>B: 提交加工申请报文（投入明细、预计产出）
    B->>DB: 校验货主、三同规则及抵质押单有效性
    B->>W: 校验可用库存并请求锁定计划投入量
    W-->>B: 库存锁定成功流水
    par 异步抓取监控
        B->>IoT: 触发投入仓库摄像头现场抓拍

    B-->>F: 返回提交成功，展示单号
    F-->>U: Toast「提交成功」并跳转列表
```

### 2. 完成加工原子事务与货权继承时序

```mermaid
sequenceDiagram
    autonumber
    actor U as 现场监管员
    participant F as 前端界面
    participant B as 加工管理服务
    participant W as WMS库存服务
    participant P as 抵质押货权服务
    participant DB as 数据库

    U->>F: 录入实际消耗量、实际产出量、入库位置及损耗，点击【确认完成】
    F->>B: 提交完成加工登记报文
    B->>DB: 校验单据状态为 PENDING_COMPLETION 与 Version 乐观锁
    B->>DB: 校验实际消耗 <= 计划投入锁定量，产出仓库强一致
    B->>DB: 开启全局数据库原子事务
    B->>W: 扣减实际消耗库存，释放未消耗余量
    B->>W: 执行产出货物正式入库上架
    B->>W: 生成产出存货条码
    opt 若为抵押货或质押货
        B->>P: 更新原抵质押单物料清单：原条码置已出库，新条码追加入单

    B->>DB: 更新加工单状态 = COMPLETED，记录完成人与时间
    B->>DB: 写入操作审计流水
    DB-->>B: 事务整体提交成功
    B-->>F: 返回完成加工成功
    F-->>U: Toast「加工已完成」并刷新单据为只读详情
```
